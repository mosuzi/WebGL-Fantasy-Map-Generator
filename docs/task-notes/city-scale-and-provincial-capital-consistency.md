# 城市规模与省会选择一致性

本文档是权威任务第 217～218 项的调查依据与施工边界。当前批准状态、编号、顺序和最小验收统一以 [`../current-plan.md`](../current-plan.md#权威任务清单) 为准；本文不得另行扩展活动待办。

## 现场问题

2026-07-29 在 `127.0.0.1:5410/?debug=1` 的真实地图中确认：

- 城市 `#150`“上虞”人口为 `1.179` 个内部人口单位，即 `1,179` 人；它带有省会身份，并因高地文化使用寨堡剪影。
- 城市 `#284`“澜晖”人口为 `3.997` 个内部人口单位，即 `3,997` 人；它属于上虞省，却被城市图标层标为“村落”并使用小屋剪影。
- 两枚图标实测外框都是约 `40.12 × 30.68px`，视觉上的“大 / 小”主要来自剪影复杂度，而不是人口驱动的几何尺寸。

这里包含两个独立问题：

1. 城市生成、`city.group / burg.group`、图标、提示文字和手工视觉使用了不同的规模判断，行政身份与人口等级又混在同一剪影字段中。
2. 省份中心先从尚未形成最终人口的城市锚点中选出，随后强制生成省会并继续生成普通城市；最终人口形成后没有重新评估省会，因此较小的早期锚点可能长期压过本省明显更大的城市。

## 当前根因

### 城市规模

- `cityIconKind()` 对普通非港口城市使用 `population < 8` 即“村落”、`population >= 64` 才是“城市”的独立阈值。内部人口单位为千人，因此该口径会把全部不足八千人的普通城市显示为村落。
- 城市生成与 `city.group / burg.group` 使用另一套口径；source 默认组别以 `0.1`、`2`、`5` 和全体人口百分位区分 hamlet、village、town、city。
- `defaultCitySilhouette()` 又允许首都、省会、港口和文化类型直接覆盖人口剪影。省会的寨堡或塔楼因而容易被理解为“大城市”，但其实际表达的是行政或文化身份。

### 省会选择

- `buildPackProvinces()` 在城市最终重建前，从当时已有 burg 中按带随机扰动的人口顺序选择省份中心。
- `buildPackSettlements()` 随后在固定省份中心强制创建省会，再生成普通城市并计算最终人口。
- 路线、标签和其它派生系统消费的是这个已经固定的省会身份；当前缺少“最终城市就绪后重新评估省会”的确定性阶段。

## 第 217 项方案：人口规模与行政身份解耦

### 单一规模契约

新增唯一的城市规模派生入口，供生成器、运行时人口编辑、DOM 图标、提示文字、对象面板和 PNG overlay 共用。内部人口仍以千人为单位，不新增另一套显示阈值。

自动分级对齐 source 默认语义：

| 规模 | 自动人口口径 | 中文显示 |
|---|---:|---|
| `hamlet` | `population <= 0.1` | 村落 |
| `village` | `0.1 < population <= 2` | 村庄 |
| `town` | 其它未进入 city 的城市 | 城镇 |
| `city` | `population >= 5` 且进入当前城市人口前 10% | 城市 |

`fort / monastery / caravanserai / trading_post` 等功能或文化标签不再自行充当人口等级；它们可以影响装饰、材质或文化变体，但必须映射到上述基础规模。城市人口被手工编辑、区域人口事务改变、重新生成或旧数据回填时，只有自动分级对象跟随重算。

### 视觉语义

- 基础剪影和基础尺寸由人口规模决定；补齐 `village` 的独立基础剪影。
- `capital / provincial / port` 是行政或功能角色，以徽记、旗帜、角标、轮廓强调等附加层表达，不再把基础人口剪影直接替换成更大的整座城堡。
- 文化类型只改变同一规模内的建筑语言、材质和配色，不得把低人口城市自动升级为高规模。
- 行政角色继续提高标签和图标可见优先级，但不再强制人口尺寸达到上限。
- 提示文字同时显示角色和规模，例如“省会·村庄”“普通·城镇”，人口字段继续单独显示。
- `visual.manual === true` 的旧手工剪影、调色和文化样式保持不变；行政角色附加层仍可显示，避免手工视觉导致省会身份不可辨认。

### 兼容边界

- 不向旧地图增加必填字段；缺失或陈旧的自动规模在读取时可派生，只有正常保存或相关编辑才写入当前规范。
- 旧 `visual.silhouette` 枚举继续可读；新增 `village` 只扩展可选值，不删除旧值。
- 浏览器缓存地图、完整地图 JSON、gzip / base64 信封、旧导出文件和手工视觉都必须验证。
- 不改变人口单位、人口统计、标签上限、selection、picking、城市身份 ID 或手工设置入口。

## 第 218 项方案：最终人口形成后重评省会

### 选择时序

新图和允许重算相应领域的重生成链统一采用：

1. 形成省份边界与候选城市。
2. 完成城市人口、规模、港口、资源和基础区位字段。
3. 对每个未锁省份确定最终省会。
4. 同步省份、city、burg、pack / politics 镜像和中心字段。
5. 再生成依赖省会身份的道路、标签、经济和其它派生内容。

最终选择不得继续使用比较器内的随机采样；相同 seed、锁定集合和输入地图必须得到相同省会。

### 候选规则

- 候选必须是本省有效陆地城市，国家、省份、city、burg 与 pack cell 归属一致。
- 锁定省份或锁定省会城市保持原省会，不参与自动替换；锁定数据冲突必须显式拒绝并原子回滚。
- 国家首都所在省默认由国家首都兼任省会，避免同一国家最高行政中心被省级自动选择降级。
- 其它省份先取人口不低于本省最大城市 `75%` 的前列候选，排除人口明显落后的早期锚点；再以人口为主，结合到省份 pole 的中心性、cell 适居度、资源、港口 / 河流可达性形成有界确定性评分，最后以 burg ID、city ID 稳定破同分。
- `#150 / #284` 类固定夹具中，`1.179` 人口单位的旧锚点不进入 `3.997` 最大人口的 `75%` 候选带，最终应选择 `#284`；人口接近时才允许更居中或交通条件更好的城市胜出。

### 更新与显式操作

- 选中结果必须原子同步唯一 `city.provincial`、`province.burg / center / gridCenter`、city / burg 归属及 politics / pack 镜像；旧省会只移除行政角色，不改名称、人口、手工视觉或城市 ID。
- 省份名称默认保持不变；自动重评省会不是省份重命名。
- 新图生成自动执行；城市或省份重生成只处理对应未锁范围。
- 旧地图加载、导入和单次城市人口编辑不得静默迁都。省份管理与公开 API 提供“只读预览 → 明确确认”的单省 / 全部未锁省份重评入口，以单条 `EditHistory` 事务更新当前地图，并支持撤销、重做和失败回滚。
- 省会变更后只刷新受影响的路线优先级、标签、对象面板、政治统计及相应 stale 标记；不重画省界，不自动重命名省份。

## 执行顺序

1. 第 217 项先建立单一人口规模语义，消除图标、提示、面板和 PNG 的重复判断。
2. 第 218 项复用第 217 项的最终人口与规模结果，建立省会重评、显式事务和生成阶段顺序。
3. 两项均不得在第 216 项统一复审与 Chrome 验收完成前开始实施；不得顺带修改 `source/` 或扩展其它政治制度。

## 统一验收矩阵

- 固定 `#150 / #284` 反例、人口阈值边界、前 10% 百分位、人口接近但区位不同、国家首都兼任、锁定省会、无候选和稀疏旧图。
- 人口编辑跨级、区域人口事务、城市 / 省份 / 世界重生成、手工视觉、PNG 导出、浏览器缓存与完整地图往返。
- 每省恰好一个省会，`province.burg / center / gridCenter` 与 city / burg / pack / politics 双镜像一致，路线与标签消费最终省会。
- 相同 seed 结果稳定；拒绝、取消和 no-op 不改地图与历史；成功重评恰好一条历史，撤销 / 重做恢复完整指纹。
- `10k / 50k / 100k` 三档生成不出现省会缺失、重复或锁定泄漏。
- 真实 Chrome 至少验证低人口省会 + 高人口普通城市、人口接近但区位胜出、手工剪影、省会重评预览 / 确认 / 撤销，以及实时 DOM 与 PNG 一致；application console、page error、WebGL error 均为 `0`。
