# 第 330 项：优雅 Loading 与编辑面板文案治理

本文记录第 330 项的初步静态盘点、文案原则、分层范围和验收方法。当前只是登记与冻结，不在本轮直接改产品文字。

## 初步盘点

当前正式 UI 共有 `28` 个 `*Panel.vue` 面板和 `30` 个 `*panel.js` 适配文件。启动、共享操作、地图生成 / 替换、导入导出、云端操作、面板懒加载和面板内状态中，初步检出至少 `56` 处显式“正在……”或 loading 占位。问题不是所有句子都错误，而是近年来新增能力绕过了已经建立的用户语言层。

### Loading 主要问题

| 当前示例 | 问题 | 建议方向 |
|---|---|---|
| 正在写入受控网格结构 | 暴露内部控制模型 | 正在更新地图网格 |
| 正在重算气候下游内容 | “下游”是实现依赖术语 | 正在更新受气候影响的地图内容 |
| 正在接入地图运行时 | 用户无法理解运行时 | 正在打开新地图 |
| 正在准备地图显示 | 含糊且频繁重复 | 正在整理地图画面 |
| 正在应用市场归属并重算经济链 | 句子长且偏工程化 | 正在更新市场与贸易 |
| 正在调整兵种比例并重建军事部署 | 两个内部步骤挤在一句 | 正在调整兵种并更新部署 |
| 正在重新扩张文化 | “扩张文化”语义生硬 | 正在重新划分文化分布 |
| 正在规划路线改线 | 动宾重复 | 正在规划新的路线走向 |

既有 `delayed-operation-feedback` 已经提供 `420ms` 延迟、token ownership、取消、失败、重叠和迟到完成保护，不能为了换文案另造第二套 Loading 生命周期。第 330 项只统一用户可见 copy 和局部面板占位的显示时机。

### 面板主要问题

- 生物群系普通提示直接显示 `grid cells / pack cells`，并使用“水域人口承载恒为 0”这类模型说明；普通用户更需要“地图区域”和“水域不会承载常住人口”。
- 城市移动写成“连续拖动城市到目标 cell”“同步归属到所在 cell”；普通模式应说“目标位置”“按所在区域更新归属”，底层 ID 留在开发诊断。
- 文化 / 宗教编辑把“中心 pack cell”“同事务联动宗教”“只读预检”直接当表单语言；可改为“影响中心”“同时更新宗教分布”“查看影响范围”。
- 湖泊预览显示 `pack cells / grid cells / 目标 feature #`；普通模式应显示受影响区域数量和目标水体名称，无法解析名称时再用中性的编号兜底。
- 经济面板的“重算经济链”“应用并重算”没有说明用户会看到什么；可统一为“更新市场与贸易”“应用并更新”。
- 高度、城市、国家、省份、文化、宗教、路线等面板已经区分普通 / 调试模式，但仍有部分技术词穿过普通分支。调试模式中的 GPU、cell ID、checksum、revision 等诊断必须保留，不纳入普通文案禁词替换。
- 气候面板已经使用“更新受气候影响的内容”“查看更新范围”“相关内容会按安全顺序一并处理”等结果导向表达，可作为其它复杂面板的参考基线。

## 文案原则

1. **先说用户结果**：使用“更新地图网格、整理地图画面、重新划分文化分布”，不描述 Worker、buffer、镜像、补丁、缓存、运行时或安装步骤。
2. **只展示有意义的阶段**：阶段变化必须能帮助用户理解进度；纯内部切片、包传输和重复 prepare / commit 不刷新可见文案。
3. **快速操作不闪**：共享操作沿用 `420ms` 延迟。面板首次挂载另使用短延迟占位，快速打开直接显示内容，慢打开才显示稳定的一句等待提示。
4. **一句只表达一件事**：Loading 不堆叠“应用、重算、重建、刷新”多个动词；复杂影响放在操作前的预览或操作后的结果摘要。
5. **按钮说明结果**：普通按钮采用“动作 + 对象 / 结果”；“预检”优先改为“查看影响范围”，“提交”按语境改为“应用 / 保存 / 完成”。开发工具可保留严格术语。
6. **状态可恢复**：失败文字说明地图是否保持原样及用户下一步；禁用状态说明缺少的条件，不能只显示灰色按钮。
7. **中文排版统一**：普通用户文本使用中文标点与省略号，不混用 `... / … / ……`；ID、单位、代码和导出字段按既有契约保留。

## 实施边界

### A. 文案矩阵

建立机器可读或可审计的矩阵，至少包含：文件、界面、状态、当前文案、建议文案、普通 / 调试可见性、危险级别和验收入口。矩阵覆盖：

- 启动画卷和首次地图恢复；
- 新图、随机种子、地图模板、十一类重生成、网格写入 / 细分；
- 导入、导出、浏览器存档和云端存储；
- runtime operation 与兼容降级；
- `28 / 28` Vue 面板及其懒加载、空态、预览、危险动作、失败和禁用原因。

### B. 共用实现

- 生成与重生成继续由现有 `loadingMessage` 和 `regeneration-user-copy` 提供用户 copy；避免在 `app.js`、Worker task 和面板里重复硬编码同一阶段。
- lazy panel 仍保持按需加载和现有 chunk 故障恢复，只增加防闪延迟与统一句式，不把低频面板重新塞进主 bundle。
- 普通用户 copy 和结构化错误 / API code 分层：界面可以自然，开发日志和 API `details` 仍保留准确技术信息。

### C. 验收

- 静态专项锁定普通用户界面禁词、中文标点、重复 Loading 句式和矩阵覆盖率；不能只用全局替换制造假绿。
- 真实浏览器覆盖短于阈值不显示、超过阈值稳定显示、阶段更新、成功、失败、取消、重叠、迟到完成，以及 panel chunk 获取 / 挂载故障恢复。
- 普通模式依次打开全部 28 个面板，检查可见文案；开发模式抽检技术诊断仍在。桌面固定视口全量检查，窄视口选择高复杂度面板抽检长文案换行、按钮可达和无横向溢出。
- 文案修改不得改变操作 code、history、地图数据、确认、撤销 / 重做、面板加载方式或用户偏好；console、page、非性能 health、WebGL 和 Loading 残留为零。
