## 第 305 项调查：河流自由控制点与共享曲线

### 五个现象的统一根因

1. `runtime/river-control-point-drag.js` 的新控制器只在命中已有控制点，或正式 `pick.river` 恰好命中当前河流时接管。
2. 其它点击仍进入 `runtime/app.js` 的通用对象创建链，被转成 pack cell 后调用旧 `river-waypoint-session.stage`。
3. 旧 `stage` 只产生单个 legacy draft；只有新 `stageAction` 会更新 `working.controlPoints`。同一个模式因点击位置不同而进入两套互不兼容的状态。
4. 双击删除只查询 working 集合，因此对 legacy 候选无效；只依赖浏览器原生 `dblclick`，第一次 click 还可能先恢复 / 清理草稿。
5. 新增和移动只向 `river.points` 插入或替换折点。预览直接画折线，正式 renderer 再单独做 Chaikin 细分；这不是二次 / 三次曲线模型，预览、正式画面、picking、长度和导出也不是同一几何。

### 性能风险

已提交基线中，拖动每次 pointermove 都会对相邻河段做密集穿水采样，每个样本又线性扫描 pack cells；100k 下可达到千万级距离计算，并同步重画。当前工作树中的未提交差异删除了部分采样和距离门，但仍保留双输入链、cell 依赖和逐事件同步绘制，还一并放宽了端点保护，不能直接接纳。

### 整改方案

#### 305-A：统一输入和草稿状态

- 从通用对象创建链完全排除 `RIVER_EDIT_WAYPOINT`；活动模式只允许河流控制点控制器调用 `stageAction`。
- legacy 单点 API 只保留旧调用兼容，不得再进入当前画布模式、预览或“应用”分支。
- 点击正式河线、点击已改变的预览河线和自由点击地图都进入同一 working 集合；Apply 始终只消费该集合。

#### 305-B：世界坐标优先，cell 只作派生索引

- 使用指针的精确世界坐标新增 / 移动，不吸附到 `pack.cells.p[cell]`。
- `packCell` 可以在提交时从坐标派生，用于定位和兼容；不得参与控制点身份、唯一性、排序、命中或“同 cell 只允许一个”的门禁。
- 硬门只保留有限坐标、地图边界、河流存在、稳定 ID、合法控制点顺序和受保护河源 / 河口端点。
- 陆水和水文检查必须基于连续曲线，而不是 cell 是否相同；用户主动编辑造成的可疑穿水、过近点或剧烈回折先给出结构化警告，不得因同 cell 或缺少唯一 cell 而拒绝。

#### 305-C：可靠手势和错误恢复

- pointerdown 只建立候选手势；超过 `3 CSS px` 才进入拖动。
- pointermove 通过 `requestAnimationFrame` 合并，每帧最多更新一次；pointerup 强制刷新最终坐标；pointercancel、Escape、换图、关闭面板均恢复进入模式前的 working state。
- 双击按控制点稳定 ID、时间窗和屏幕距离识别，并与原生 `dblclick` 共用一个删除动作；两次 click 不得先新增、换选或清空其它草稿。
- 所有 pointer 回调使用统一错误边界和 `finally` 清理 pointer capture、drag state 与编辑锁。

#### 305-D：唯一的三次曲线几何

- 推荐用向心参数化 Catmull–Rom 经过用户锚点，再确定性转换为分段三次 Bézier。它能经过控制点、保持连接处切线连续，并比 uniform spline 更少过冲。
- 预览、正式 renderer、河流长度、picking、PNG、GeoJSON 和 JSON 导出必须消费同一个共享曲线构建器和同一组与相机无关的确定性采样点。
- 正式 renderer 不得对已经采样的曲线再次 Chaikin 平滑。
- 旧 `pointIndex` 仅作为兼容派生值；正式控制点顺序使用稳定 ID 与 segment / order 语义，避免重采样后索引漂移。
- 本项只改视觉控制几何，不改 `cells / gridCells / parent / basin / source / mouth / flux / discharge` 等水文身份。
- 没有 `controlPoints` 的旧河流必须继续使用既有视觉、Chaikin、picking、长度和导出路径并保持指纹；只有进入新版控制点编辑并提交曲线版本的河流切换共享 cubic 几何，不能用取消 double-smoothing 为由改写全部旧图。
- 共享曲线快照除 `x / y` 外还要定义 flux、width、alpha 及河口宽度等沿程属性的确定性插值；预览、正式 draw、命中、长度和导出必须消费同一属性采样，不能只保证中心线相同。

第 305 项只拥有控制点身份、手势和用户编辑后的视觉路径；第 304 项只拥有实验室中的汇流锚点、水文关系和生成候选。两者最多共享无状态的 cubic Bézier 求值 / 采样 / 长度 / 命中原语：305 用 Catmull–Rom 计算用户锚点间的 Bézier 控制柄，304 可用端点与水文切线构造 Hermite / Bézier 汇流段。304 不读取 `controlPoints`，305 不依赖实验 DAG / 汇流候选，任一任务的验收都不能替代另一个。

### 第 305 项最小验收

- 在用户流程中进入模式，自由点击和点击新预览河段均能新增；坐标与指针误差不超过 `1 CSS px`。
- 同一 pack cell 内新增两个可见控制点，稳定 ID 独立，可分别拖动和双击删除。
- 拖动至少 `30 CSS px` 并跨 cell；连续 60 次 pointermove 后最终坐标准确，100k 交互无 `>=50ms` 长任务，预览延迟 P95 小于 `33ms`。
- 带轻微抖动的双击只删除目标点，不新增、不换选、不清空其它草稿；补测 mouse / pen / touch。
- 固定非共线夹具证明结果是切线连续的三次曲线，不是折线；预览与提交后几何指纹一致。
- 取消、Escape、异常、换图和关闭面板均保持正式 points、控制点、checksum、revision 和历史不变；确认只增加一条历史，撤销 / 重做精确恢复。
- 旧无 `controlPoints` 存档、picking、PNG、GeoJSON、JSON / gzip 和四类错误门禁通过。

## 第 306 项调查：城镇自由迁移与交互性能

### 卡顿调用链

当前 `bindCityRelocationDrag` 在 pointerdown 和每个 pointermove 都同步执行完整 `inspectCityMove`。一次预检会：

1. 扫描全部路线寻找关联路线；
2. 对每条关联路线执行 `planRouteRelocation`，陆路可能进入最多约 50k pack cells 的 A*；
3. 更新面板共享 preview/version，使城镇列表重新计算指标、筛选和排序；
4. pointerup 对同一目标再预检一次，随后 `command.isNoop` 和 `command.apply` 又各预检一次；
5. 提交阶段克隆路线 / 政治对象并触发标签、picking、point layer、路线 mesh 等宽泛刷新。

当前所谓预览只更新面板文字，没有给 WebGL 城镇实例写 ghost / 临时位置；即使预检最终返回，地图上的城镇图标也不会随指针移动，因此“拖动不好使”本身也是独立的可见缺口。

一次性只读 Node 探索在一张 100k 生成图上观察到：4 条关联陆路的远目标单次完整预检约 `153.6ms`；10 条路线的近目标重复预检中位约 `9.3ms`、最高约 `61.0ms`；即使没有关联路线，命令 execute / undo / redo 仍约为 `146 / 110 / 95ms`。该探索尚未固化独立脚本、seed、预热和样本数，不能作为可复现验收数字；306-A 实施前必须把同样场景写成正式 benchmark，最终预算以浏览器真实指针为准。

`CITY_MOVE` 当前又以全局交互锁运行。只要同步调用变慢、预检抛错或提交失败而清理没有进入，页面控件就会持续 disabled，形成“整页所有交互丢失响应”的现场表现。

### 现有回归为何误判通过

- Node 指针回归使用小型 stub 和少量 move，没有 Vue、真实 renderer、全局交互锁、`lostpointercapture`、blur 或异常注入。
- 浏览器回归只在隔离新图中挑普通城镇和容易通过的落点；没有用户旧图 / 细分图、跨国首都、跨省省会、同 cell 多城或缺失 `points / cells` 的兼容夹具。
- `mouse.move(...steps: 12)` 后只固定等待，没有 EventTiming、longtask、RAF 心跳或最大输入延迟断言，也没有断言城镇图标实际跟随指针。
- 原脚本收集 health errors 但没有把非空作为失败；第 302 项记录的约 `0.93s input-delay` 被列为观察项而没有阻断交互验收。

### 2026-08-08 用户明确确认的规则

下列四条直接来自用户，本报告不再沿用第 73 / 302 项的相反限制：

1. 省会可以移出原省份；移出后原省份自动重算一个省会。
2. 城镇移出国境后自动划归新所在地国家，原国家不再拥有该城镇。
3. 首都移出国境后，原国家自动重算首都。
4. 允许移入已有城镇的 cell；城镇均衡只约束自动生成，人工移动除水域外不受该类门禁。

有限坐标、地图边界和必要映射损坏仍属于结构安全错误，不能伪装成一个合法陆地目标。既有“省份 / 文化 / 宗教跟随目标 cell”的规则没有被本次否定，但必须和国家归属一起重新做镜像一致性验收。

“只要不移到水里都行”还意味着港口、市场或路线派生失败不能反向把合法陆地移动判为无效。既有规则已经确认：正常判定为不再具备港口条件时清除港口；但用户没有指定港口重算异常、关联海路、市场或陆路失败时应删除、标记 stale、异步修复还是采取其它降级，因此本报告只把“不阻断移动”列为硬边界，不把这些异常降级策略冒充为已确认规则。

### 实施前仍需确认的边缘策略

1. **迁出城镇在目标实体的角色**：推荐清除其旧首都 / 省会角色，保持目标国家 / 省份既有首府不变，避免双首府；如果目标实体本来没有首府，是否晋升迁入城镇仍需产品决定。
2. **原实体没有任何候选城镇**：国家现有不变量要求有效 `capital > 0` 且 center 对应有效陆地 / burg；省份即使允许 `burg = 0`，center 也必须是父国所属有效陆地。不能写 `center = 0` 规避。需要在“生成一个替代城镇”“正式支持无首都国家”或其它保持不变量的方案中明确选择。
3. **港口异常 / 关联海路 / 市场 / 陆路降级**：正常判定为不再具备港口条件时按既有规则清除港口；推荐港口重算异常时回退为非港口、市场镜像迁移并标 stale、无法重寻的路线在可撤销事务中删除。后三类处理只是当前技术建议，实施前应确认是否保留待修复对象或采用其它策略。
4. **同 cell 多市场中心**：`pack.cells.market` 仍是单值索引；如果同一 cell 的多个城镇都带市场中心，需决定代表、共享或多值市场语义，不能把城市多值索引直接套用。
5. **同坐标多城的选择表现**：候选列表、重复点击循环、聚合或屏幕扇出都能满足可操作性，具体视觉不是用户本次四条规则的一部分；第 306 项只冻结“所有对象可被选中和再次移动”，不先锁死表现方案。

### 同 cell 多城兼容设计

当前 `city.cell / city.packCell` 与 `burg.cell` 已能表达多城同 cell；真正的单值瓶颈是 `grid.cells.burg` 和 `pack.cells.burg`。

- 以 city / burg 对象自身的 cell 字段作为权威归属，运行时构建 `cityIdsByGridCell` 与 `burgIdsByPackCell` 多值索引。
- 旧 `grid.cells.burg` / `pack.cells.burg` 的兼容代表规则需要与全部消费者一起迁移；推荐固定取 bucket 中最小有效稳定 ID，不按人口、角色或操作先后选择，但不能在消费者审计前把它当作已完成的数据契约。
- 当前源码精确搜索至少有 `106` 处 `cells.burg` 文本消费、分布在 `17` 个文件。所有唯一性校验、picking、selection、标签、对象查询、导出和删除 / 移动清理必须改用多值语义；不得只改写两个单值槽位后覆盖原城镇。
- 多值索引由旧存档的 city / burg 对象重建，不增加必填 schema 字段；JSON / gzip / browser storage 往返后代表占位和对象集合保持确定性。
- 写入链必须覆盖加载 / ensure、自动生成、城市新增 / 删除 / 移动、撤销 / 重做、Grid 细分、地形 / 湖泊改变、重生成锁和旧缓存回填；省会重评不能再要求 singular 槽恰好指向候选自身。
- 消费链必须覆盖经济、军事、marker、地区 / 无人区、国家 / 省份命令、cell query / map analysis、hover / picking / selection、标签与 WebGL 城镇实例、完整导出及 API。`pack.cells.market` 是另一套单值市场索引，不能混成城镇唯一性依据。
- 公开 `cities.move / inspectMove` 需要接受精确 `{x,y}` world point 并派生 grid / pack cell，同时兼容旧 `{gridCell,packCell}`；不得继续让只传 cell 的 schema 把坐标吸附回 cell 中心。旧 singular API 字段保持兼容，同时新增 `cityIds / burgIds / cityCount / burgCount`，并同步 `info.describe`、input / output schema、reference space 与能力矩阵。
- 旧缓存、JSON / gzip / `.webfmg`、浏览器存档、旧完整导出和 Grid 细分旧图都要从 city / burg 对象重建多值索引并完成往返；缓存版本变化不能静默丢掉同 cell 的非代表对象。
- 同 cell 不等于同坐标。拖动保留精确世界坐标；完全重合时所有对象仍必须可被选中和再次移动，但候选循环、列表或视觉扇出方案按上节产品决定执行。

消费者迁移至少按下表分类，逐处审计后才能决定 singular 兼容值：

| 类别 | 必需语义 |
| --- | --- |
| 旧序列化字段、旧只读 API、只显示一个摘要的兼容入口 | 可以返回稳定代表，但必须同时提供完整集合 / count，且不能据此判断唯一占用 |
| 占用检查、创建 / 删除 / 移动、首府候选、锁、统计、经济 / 军事 / 地区、picking / cell detail | 必须消费完整 bucket；只读代表会漏对象或破坏镜像 |
| ensure / import / 聚落重建 / Grid 细分 / undo / redo | 必须重建 bucket，并在代表对象删除或迁出后确定性重选兼容代表 |
| 标签 / WebGL 实例 / selection / hover | 必须保留每个对象身份和精确坐标；视觉聚合不得改写真实位置 |
| `pack.cells.market` 等其它单值索引 | 保持独立语义，在产品决定前不得借城市代表规则自动迁移 |

### 性能与生命周期整改

#### 306-A：一帧内只做 O(1) 快速预览

- pointermove 只计算世界坐标、目标 land 状态、目标归属和轻量角色摘要；通过 RAF 合并，每帧最多一次。
- 城镇 marker 使用临时 transform / GPU 实例覆盖；preview 使用独立局部状态，不递增会使全部城镇 metrics、筛选和排序重算的共享版本。
- 预先建立 city → routes 邻接索引，不再为每个指针事件扫描全部路线。

#### 306-B：昂贵派生异步化并只算一次

- 停留约 `120～180ms` 后可以启动可取消的后台预检；最终 pointerup 以最后坐标启动一次完整预检。
- 路线 A* 在 worker 或可让出主线程的任务中运行，带 generation token；新指针坐标、取消、换图或 revision 变化立即废弃旧结果。
- `onCommit`、`isNoop` 和 `apply` 复用同一不可变 preflight；仅当地图 revision 已变化时重新预检，不能对同一目标重复三次。
- 路线、港口、政治角色和多值索引在一个事务中提交；只刷新受影响城市实例、标签、picking、路线和两个政治实体，避免全量 point layer / object index / labels 重建。

#### 306-C：非模态锁与异常兜底

- 城镇移动只互斥冲突的画布工具，不禁用取消、Escape、面板关闭和必要的全局恢复入口。
- pointerdown / move / up / cancel 和异步任务均包在统一错误边界；`finally` 必须释放 capture、drag、preview、pending token 和工具锁。
- 非法水域目标只显示无效预览，页面继续可交互；异常写入 health 和完整 stack，恢复正式位置与历史，并退出或回到可取消的待移动状态。

### 第 306 项最小验收

- 10k / 100k 真实指针连续移动 120 帧：输入到 marker 预览 P95 小于 `33ms`，pointermove 主线程工作 P95 不超过 `8ms`、最大不超过一帧 `16.7ms`，无 `>=50ms` 长任务。
- 覆盖 0、4、10 条关联路线；后台预检期间平移、取消和 Escape 保持响应，陈旧结果不能覆盖最后坐标。
- pointerup 到完整影响摘要期间不冻结 UI；同一目标完整预检最多一次，单事务提交，撤销 / 重做不执行重复 A*。
- 普通城镇、港城、市场中心、省会、首都分别覆盖同省、跨省、跨国、中立陆地、同 cell 已有城镇和水域反例。
- 跨境后 city / burg 归属一致，原国家 / 省份首府确定性重选；迁入角色和无候选场景按获批策略保持全部政治不变量，不得用非法 `center = 0` 假装成功。
- 单城国家、单城省份与锁定首府分别有反例；获批方案必须原子同步迁出 / 替代城镇的 city / burg 角色标志、state / province 反向引用、center、capitalName、自动视觉和标签。
- 同 cell 两城及三城的列表、标签、picking、删除、再次移动、导出 / 导入、旧存档、Grid 细分、锁和历史均不丢对象，不覆盖兼容代表。
- 故障注入覆盖预检、worker、路线、派生刷新和 renderer；每种异常后 `editing-locked=false`、无 pointer capture、工具栏可操作、地图 / revision / 历史无半写入。

## 第 304 项复查：河流网络实验室为何仍未通过

### 当前回归的实际语义

`pnpm run regress:river-network-lab` 当前退出码为 0、输出 `ok: true`，但它只检查：

- 八个夹具是否“包含”预先登记的 issue ID，不拒绝额外诊断；
- 10k / 50k / 100k 两轮结果是否可重复；
- 原始快照是否未被写入。

它没有断言真实 seed 的候选必须被接受。运行 `pnpm run regress:river-network-lab` 的公开固定 seed `304-river-network-lab-100000` 时，100k 汇流候选实际为拒绝：river `760` 到 parent `5` 的末端距离约 `16.568`，超过固定容差 `12`，产生 `confluence-anchor-rejected`。这些 ID 只属于公开实验 seed，不是用户地图对象。随后水文候选在汇流候选失败时回退原始河流，却仍可报告 `accepted=true`，违反“候选失败不得静默降级”的实验室约束。

### 304-E 旧证据需要纠正

- 正式摘要 checksum 的 payload 包含 `timing / buildMs` 等运行时遥测，两次运行当然可能不同。剔除遥测后，本轮 10k / 50k / 100k 的 semantic digest 与各自 `networkChecksum` 均一致；现有证据不能证明河网不确定。
- 100k 正式页长任务是在候选尚未接入时测得的正式生成基线，不能归因于实验室候选。候选性能必须在同一只读快照上做 baseline / candidate A/B。
- 旧边界拓扑实验室不是本问题：`regress:boundary-topology-lab` 的 20 个夹具、推荐算法 `14/14`，以及 pure shoreline 回归当前均通过。

### 304-F：修复验收证据

- 把“夹具覆盖”与“候选验收”拆成两个状态；每个夹具声明精确允许诊断、额外诊断策略和候选应接受 / 拒绝。
- 真实 10k / 50k / 100k seed 必须断言 DAG、汇流和水文候选状态以及拒绝原因。
- 阶段依赖显式化：C 失败时 D 只能是 `rejected` 或 `partial`，不得显示整体接受。
- 使用排除遥测字段的 semantic checksum，并继续保留 network checksum；正式 checksum 的兼容问题另行审计，不在实验室中直接改旧地图身份。
- 页面实际并排绘制固定夹具和三档真实快照的 baseline / candidate，显示锚点、拒绝段、宽度和碎线策略；不能只展示文字卡片。

### 304-G：修正汇流与曲线候选后重做决策门

- 固定 `12` 改为由局部 cell 尺度、河宽和段长共同决定的可解释容差；单条关系失败必须显式局部拒绝，不能整体静默回退。
- 汇流末段只复用第 305 项无状态 cubic Bézier 求值 / 采样原语，由第 304 项根据汇流端点和水文切线独立构造 Hermite / Bézier 控制柄；检查过冲、自交、反向折返、非法水陆穿越、非汇流交叉和河口漂移，不读取用户 `controlPoints`。
- 在同一只读快照上分别测算法、曲线采样、GPU 上传和 draw 增量；正式生成固有长任务单列为 baseline。
- 增加独立浏览器回归、固定截图、候选可见像素差和 console / page / health / WebGL 门禁。
- 304-F～G 全部通过后只形成新的正式接入决策；在此之前不得修改正式 `rivers.js`、地图、schema、存档或用户 5410 标签页。

## 推荐实施次序

1. **第 304-F 与第 305 项可并行**：304-F 只修实验室验收语义，不依赖曲线；305 统一用户侧河流输入和共享 cubic 几何。
2. **第 306-A～C 可先行，第 306-D～E 随后**：先完成城镇快速 ghost 预览、异步预检、单次 preflight、局部刷新和错误清理，解除整页失去响应风险；只把多城全消费者迁移、行政角色与派生落盘放到边缘产品策略确认后的 306-D，最后执行兼容与浏览器矩阵 306-E。
3. **第 304-G**：只在纯 cubic 原语稳定后修正实验室汇流曲线候选，重新执行正式接入决策门。

三个任务都必须先在隔离环境通过专项和 10k / 100k 浏览器矩阵；最后只在用户现有 5410 标签页做不刷新、不生成、不替换地图的真实交互确认。
