# 路线、河流与湖泊创建闭环

## 范围

本文记录权威任务第 40 项的最小闭环。路线绘制、河流新增和湖泊开挖分别使用独立的数据约束与编辑命令，共用第 36 项画布工具模式管理器、统一编辑执行器和公开 runtime action，不引入通用粗放创建器。

## 入口与公共路径

- 路线面板“绘制路线”进入 `route:draw`，依次选择起点和终点；公开入口为 `api.edit.routes.create({startPackCell, endPackCell, type})`。
- 河流面板“新增河流”进入 `river:add`，单击陆地河源；公开入口为 `api.edit.rivers.create({sourcePackCell})`。
- 湖泊面板“开挖湖泊”进入 `lake:excavate`，单击封闭陆地区域；公开入口为 `api.edit.lakes.create({packCell, radius, waterHeight})`。
- UI 手势仅负责把 pack cell 参数交给稳定 action。三类入口均由相同 action 创建命令、进入 `EditHistory`、执行派生刷新并更新选择；成功后结束当前画布模式，失败时保留模式供用户重试。

## 数据约束

### 路线

- `road / trail` 端点和路径只能位于陆地，`searoute` 只能位于水域。
- 起终点不能相同，也不能与现有同类路线重复。
- 使用 pack 邻接图和地形成本执行 A*；不存在连通路径时拒绝，不用直线跨越拓扑缺口。
- 创建后同步 `settlements.routes`、`pack.routes`、cell 路线链接、路线 metadata，以及经济、军事和外交待派生状态。

### 河流

- 河源必须是未被河流占用的陆地 cell。
- 河道每一步必须严格下降，直到进入水域或汇入既有河流；无下坡出口、路径过短或超过安全长度时拒绝。
- 汇流时记录 `parent / basin`，并重建 `pack.cells.r / fl / conf`；入湖时同步湖泊 inlet、主入流和流量引用。
- 新河流带有可供详情面板读取的近似汇水面积、汇水 cell 数和平均降水诊断，并明确标记为手工下坡估算。

### 湖泊

- 中心和所选区域必须是陆地，不能接触地图边界或连通现有水域；区域限制为 1～256 个 grid cells。
- 湖盆内不得包含城市、既有河道、路线或标记，且必须形成至少三个相邻陆地岸线 cell。
- 创建后同时更新 grid / pack 高度与 feature，重建 feature 摘要、水陆拓扑、岸线、haven / harbor 和对象 metadata。
- `radius` 限制为 `0～4`，水位限制为 `0～19`；默认水位为 `19`。

## 撤销、读取与导出

每类创建只产生一条历史记录。命令在第一次执行前保存本领域完整快照；撤销恢复对象列表、cell 索引、feature / 岸线、水文和待派生状态，重做重新得到同一对象。创建结果立即可被对象解析器、管理面板、画布拾取、定位和现有地图 / GEOJSON 导出路径读取。

## 回归门禁

`pnpm run regress:object-creation` 使用固定 3000 cells 地图覆盖：

- 路线连通、地形不匹配拒绝、拾取索引、要素导出和撤销 / 重做；
- 河流严格下坡、既有河流汇流、无下坡出口拒绝、拾取索引、要素导出和撤销 / 重做；
- 湖盆封闭、连通既有水域拒绝、feature / 岸线、画布拾取、完整地图导出和撤销 / 重做。

API 三方覆盖、方法元数据和稳定性门禁同步更新到 11 个命名空间、165 个公开方法、75 个编辑方法；稳定等级为 157 个 stable、7 个 experimental、1 个 deprecated。本项按快速迭代约定只执行代码回归和生产构建，不单独启动浏览器。
