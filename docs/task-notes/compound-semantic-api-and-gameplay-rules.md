# 复合语义 API 与玩法规则体系

> 状态：权威任务第 204 项规则分层说明。后续第 207～210 项已完成全部 inspector、原子规则事务、缺失游戏规则、十个 AI 配方与完整中文玩法说明；当前实现与验收以 `docs/current-plan.md`、机器矩阵和 `gameplay-rules-and-ai-planner-recipes.md` 为准。

## 一、为什么不能只按现有按钮设计 API

现有控制台 API 已经能操作大量按钮、字段和对象，但“按钮可调用”不等于“AI 能正确理解游戏规则”。例如“国家 A 占领 Cell B”同时涉及：

- Grid / Pack Cell 映射；
- 国家和省份归属；
- 城镇、首都与省会；
- 原国家是否失去最后领土；
- 外交、军事、市场、路线和纪事引用；
- 单条历史、revision 与失败回滚。

如果让 AI 自行串联多个原子方法，任何一步失败或地图中途变化，都可能留下半完成状态。因此需要在现有原子 API 之上建立规则语义层。

## 二、三层能力模型

### 2.1 事实与原子原语

这一层提供可组合但不承诺完整游戏规则的基础能力：

- `objects.*`、`cells.*`、`info.*` 等只读事实；
- 单字段名称、颜色、备注、视觉样式；
- selection、camera、layers、units 等编辑器服务；
- 数据导出和运行时诊断。

它们不应被包装成大量重复的“语义接口”。

### 2.2 规则事务

一个规则事务对应一个不可拆开的玩家意图。判定条件是至少满足一项：

- 同时修改多个对象或多个领域；
- 根据当前地图状态走不同业务分支；
- 需要只读预检、稳定业务 code 或用户确认；
- 任一阶段失败都必须完整回滚；
- 成功必须只形成一条历史和一次 revision 递增。

规范入口统一为：

```js
api.<domain>.inspect<Action>(input)
api.<domain>.<action>({
  ...input,
  inspectionToken,
  expectedRevision
})
```

业务不可执行使用 `ok: true + allowed: false + code`；参数、运行时或完整回滚失败使用 `ok: false + error.code`。

### 2.3 AI 规划器配方

殖民、战争、行政改革、人口迁徙和经济开发等战略目标由多个规则事务组成，不应变成一条覆盖半张地图的超级 API。

规划器必须：

1. 读取事实和规则目录；
2. 选择一个规则动作；
3. 调用 inspector；
4. 在需要时等待用户授权；
5. 提交一条事务；
6. 重新读取 revision 与结果；
7. 再决定下一步。

已经提交的步骤不能在后续失败时伪装成“整体从未发生”。需要撤回时，应明确调用历史或反向规则动作。

## 三、封闭审计分母

机器报告 `docs/audits/compound-semantic-action-matrix.json / .md` 同时消费：

- 第 200 项全量能力矩阵；
- 当前 `API_METHODS`；
- 第 195 项 Cell / 画布动作矩阵；
- runtime actions、command / inspector exports；
- 已冻结的城市移动、国家合并拆分、海岸 Feature、文化宗教、适居度、人口与危险删除产品规则。

只有以下项目全部归类，审计才为通过：

- 每个公开 API 方法；
- 每个注册画布模式；
- 每类非注册直接操控；
- 每个规则事务候选；
- 每个规划器配方引用的规则动作。

“所有可能”在这里表示覆盖当前游戏模型和已存在交互能够表达的**规则动作族**，而不是枚举无穷多句自然语言或参数组合。新领域进入 runtime、API 或交互分母时，source digest 与门禁必须要求重新审计。

## 四、优先级

### P0：现有多 API 碎片

优先把当前可以勉强串联、但不具备原子性的能力收敛为规则事务：

- 领土征服、割让、中立化与最后领土灭国；
- 确保省份并分配 Cell；
- 整省转移；
- 名称库绑定并批量重命名；
- 删除或替换名称库时迁移绑定。

### P1：已有写命令但缺 AI inspector

为国家、省份、城市创建和删除、河湖创建删除、路线、军队、区域等现有命令补稳定预检、business code、revision/token 和统一描述。

### P2：当前尚无完整游戏规则

以下不是简单 API 缺口，而是必须先写规则再实现：

- 省份合并与拆分；
- 宣战、议和与宗藩变更；
- 真实战斗结算；
- 由战争结果驱动的领土、人口和军事联动。

## 五、玩法文档路线

完整玩法文档按领域组织，不按控制面板抄按钮：

1. 世界创建、存档与重算；
2. 地形、水文与 Feature；
3. 气候、生态与人口承载；
4. 国家、省份与政治拓扑；
5. 城镇、人口与定居点；
6. 文化、宗教、命名与社会归属；
7. 路线、区域与资源设施；
8. 市场、资源与经济链；
9. 外交、战争与国家关系；
10. 军队、调动与战斗；
11. 编辑器事务、批量操作与发布；
12. AI 规划器玩法配方。

每个章节都必须包含：

- 玩家目标；
- 可用对象与输入空间；
- 合法前置；
- 规则分支与稳定 code；
- 成功后影响的系统；
- 失败、取消、确认和回滚；
- 旧图兼容；
- 可组合的上游和下游玩法配方。
