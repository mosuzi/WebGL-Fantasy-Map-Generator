# 河流干流关系与汇流完整性专题

## 目标

河流对象需要同时满足“水文网络正确”和“玩家、AI 可解释”两项要求。若一条河标记为支流，列表、详情、悬停与 API 都必须能回答它立即汇入哪条干流；生成器不得留下父河缺失、自指、循环或没有真实汇流点的孤立支流。

本专题对应权威任务第 206 项，临时前置于第 205 项代码实施，不并入重生成锁定体系。用户对“丹水—玉溪”继续追问后，本专题第二次纠错：河网完整性不能止于“根河进入某个湖泊”，还必须回答该湖泊能否长期消纳来水，以及不能消纳时出口河如何继续到海。

## 现场证据

用户 `http://127.0.0.1:5410/` 存档中的“丹水”显示为支流，流量 `15,338 m³/s`、长度 `381.8 km`，但河流管理和对象详情都没有显示其干流，地图上看起来在到海前截断。

固定五个 10k 种子复现出三类结构错误：

- 候选父河被最小河长或河源合法性过滤后，子河仍保留其 ID；
- 流量反转路径可能产生 `parent === self`；
- 湖泊入流被直接挂到湖泊出流，即使两段河道只经湖水连通、没有同一陆地汇流点。

因此这不是单纯线条裁剪，也不能只靠重新生成当前存档解决；现有生成过程本身需要增加河网归一化门禁。

## 数据契约

### `parent`

- `0`：主河、入湖河流、入海河流或出界河流；
- 正整数：立即接收本河的直接干流 ID；
- 有效支流的 `mouth / confluence` 必须是陆地 cell；
- 父河必须包含该汇流 cell，并在该 cell 后还有下游河段；
- 父河必须存在、不能是自身，父链不能形成循环。

### `basin`

- 有效支流解析到父链最顶层主河 ID；
- 主河与入湖、入海、出界河流使用自身 ID；
- 旧图孤立河段使用自身 ID，不伪造不存在的流域主河。
- 只有根干流拥有合法出口时，整个 `basin` 才是有效水系；“直接父河存在”不是充分条件。

### 出口与诊断

- `outletKind` 使用 `confluence / lake / ocean / border / inland`；
- `outletFeatureId` 只在可识别水体时填写；
- `networkStatus` 使用 `valid / lake-inlet / ocean-mouth / border-outlet / orphaned`；
- 旧图原始错误父河可保存在兼容诊断字段中，但不得继续作为有效 `parent`。

## 归一化顺序

1. 完成既有最小长度与河源合法性过滤，形成候选河流。
2. 只在支流末端为陆地、接收河流包含该 cell 且继续下游时建立父子关系。
3. 原父河无效时，可在同一汇流 cell 的有效下游候选中按流量、长度和 ID 确定性选择接收河流。
4. 清除缺失、自指、循环与跨湖伪父子关系，重新计算根 `basin`。
5. 新生成河段若终止在陆地又没有接收河流，整段拒绝；旧图迁移则保留河道并标记 `orphaned`。
6. 校验河道自身连续性与根干流出口：相邻河道 cell 必须拓扑相邻；入海 / 入湖必须由相邻陆水 cell 构成真实岸线过渡，海洋 Feature 必须连到地图边界；出界末端必须来自边界 cell。
7. 根干流没有合法出口时，新图删除整棵上游河树；旧图保留全部几何，但整棵水系统一标记为无有效出口。
8. 使用归一化后的河流重建 `pack.cells.r / conf`、湖泊 `inlets / outlet` 和对象 picking。

## 展示要求

- 河流管理表新增“干流”列：主河显示 `—`，支流显示 `#ID 名称`，孤立旧河段显示“缺失 / 孤立”。
- 河流管理详情与通用对象详情增加“汇入干流”“流域主河”“河网状态”“汇流 cell”。
- 悬停普通模式显示河名和类型；支流追加 `→ 干流名`，孤立旧河段追加异常提示。
- 对象查询字段增加 `parentName / basinId / basinName / confluence / outletKind / networkStatus / networkIssue`，不要求 AI 通过多个原子查询自行猜测关系。

## 旧存档兼容

旧浏览器缓存、JSON 与 gzip 统一走同一归一化函数。迁移只纠正关系字段，不删除旧河道、名称、宽度、水文、备注或点列：

- 入湖误挂解除 `parent`，标记为入湖河流；
- 缺失、自指、循环父河解除关系；
- 能从同一陆地汇流点确定有效干流时自动修复；
- 仍终止在陆地且无法接续的河段保留并标记 `orphaned`。

## 验收

- 合成旧图覆盖入湖误挂、缺失、自指和孤立河段，迁移前后河流数量与几何不变。
- 河流管理列表、详情、对象详情、悬停和对象查询使用同一关系解析结果。
- 生产构建通过；用户现有 `5410` 存档中“丹水”的干流或异常状态可见，不要求用户先重新生成整张地图。

## 作废的首轮证据

> 本节证据已因“玉溪仍是内陆河”的现场反例作废，不能继续作为第 206 项完成依据。后续证据必须覆盖丹水到根干流的完整出口链。

- 五个固定 10k 种子生成 `857` 条河流，其中支流 `219` 条；缺失父河、自指、循环、父子不相交和最终孤立河段均为 `0`，共拒绝 `9` 条无法接续的陆地河段。
- 合成旧图保留 `5 / 5` 条河流，正确得到真实支流、入湖河流、出界河流和孤立旧河段；完整 JSON 往返保留 `73 / 73` 条河流。
- 用户 `5410` 存档中“丹水”的直接干流是 `#48 玉溪`，汇流 cell 为 `#3488`；河流管理列表、详情与地图悬停均可见。原来同样显示成支流的“西丹水”被归一化为入湖河流。
- 专项回归、既有河流删除回归、API 旧数据兼容、生产构建和差异检查通过；浏览器无应用 error。

## 纠错后最终证据

- 河网门禁除父子关系外，新增相邻 cell 拓扑、边界出界、末端陆水邻接、共享岸线终点、外海 Feature 边界连通和根干流出口验证。
- 五个固定 10k 种子最终保留 `833` 条河流与 `200` 条有效支流，拒绝 `33` 条无有效出口河段；关系、路径和根出口断言全部通过。
- 合成旧图保留 `7 / 7` 条河道，能把伪水体出口根河及其上游支流统一标为无出口水系；旧图不因诊断而丢失几何。
- 当前 `5410` 存档的玉溪为“主河（无出口）/ 水体出口无效”，丹水为“支流（无出口）/ 下游根河无有效出口”，地图悬停显示“丹水 / 支流 → 玉溪 / 无有效出口”。旧存档的 `258` 条河流完整保留，未自动执行重生成。

> 上述“纠错后最终证据”现只算第二轮河网拓扑证据，不再是本专题最终结论。它证明玉溪没有合法出口，却仍把进入湖泊当作水文终点，正是本轮要修正的模型缺口。

## 第二次纠错：湖泊水量收支与河床下切

### 湖泊不是天然终点

湖泊必须同时通过水量与地形两层判定：

1. 计算长期净补给 `flux - evaporation`。净补给不为正时，蒸发能够长期消纳来水，湖泊可以保持闭流。
2. 净补给为正时，有限湖盆迟早蓄满。生成器以湖面至最低出海鞍点的高程差和湖泊面积计算规范化蓄水容量指数，并记录预计蓄满时间。
3. 从全部外海岸线与地图边界反向构造最低溢流障碍场，为每个深洼湖选择确定性的最低鞍点路径，避免只看紧邻湖岸的最低 cell。
4. 溢流路径超过湖面可被动上涨范围的部分视为河床下切需求；需求不得超过由净流量对数派生的有界预算。高净补给可切穿平均高度略高的 cell，小流量不能任意穿越高分水岭。
5. 成立的溢流路径只调整河床有效排水顺序，并逐 cell 激活强制下游边；`cells.h` 继续表示该 cell 的平均地形高度，不因一条窄河床而整体降低。

### 稳定诊断

新图湖泊持久保存 `overflow v1`：

- `status`：`natural-outlet / overflow-channel / balanced-terminal / incision-limited / no-escape`；
- `netFlux`、`storageCapacity`、`estimatedFillTime`；
- `spillElevation / spillRise / spillRiseMeters / spillCell / pathCells`；
- `requiredIncision / incisionBudget / method`。

其中 `storageCapacity` 是当前地图坐标与 FMG 高度量尺下的规范化容量指数，不伪装成真实立方米。旧图缺字段时只回填 `unknown-legacy` 或 `legacy-outlet`，不根据残缺数据倒推一个伪结论。

### 修订验收

- 固定合成夹具覆盖高净补给小湖经较高平均 cell 溢流到外海、蒸发平衡闭流和小流量受高分水岭限制。
- 多种子新图的每个湖泊都有 `overflow v1` 诊断，不出现 `unknown-legacy`。
- 河流生成统计记录真实的平均高度逆向下切段数量，并继续通过父子关系、逐 cell 邻接和根出口门禁。
- 完整地图导出 / 导入保留新诊断；旧图缺字段安全回填且不删除河流、湖泊或几何。

### 完成证据

- 合成纯规则夹具：湖面 `19.9`、最低鞍点 `26`、容量指数 `768`、预计蓄满时间 `0.051`、下切需求 `0.1`、预算 `15.886`；高净补给判为 `overflow-channel`，蒸发大于补给判为 `balanced-terminal`，高分水岭小流量判为 `incision-limited`。
- 合成生成主循环夹具使用跨三个水面 cell 的湖，迫使出口不能沿用邻接入湖河 ID；新出口河从陆地 cell #1 起算并沿 `[1,2,3,4]` 到外海，最终为 `ocean-mouth`，证明湖水 cell 河源过滤断点已修复。
- 三个 10k 种子共 `20` 个湖泊全部具有新诊断，河网记录 `137` 个平均高度逆向但在预算内的河段；五个既有 10k 河网种子为 `847` 条河流、`209` 条有效支流、拒绝 `24` 条候选，输出中所有关系 / 路径 / 根出口缺口为 `0`。
- 50k 样本含 `23,725` 个 pack cells、`298` 条有效河流与 `23` 个湖泊，其中 `21` 个自然外流、`2` 个蒸发平衡闭流、`276` 个下切段，最终 `orphaned=0`，本机整图约 `2.15s`。
- 旧图缺字段 roundtrip 回填 `unknown-legacy / legacy-outlet`；对象查询公开水量、容量、溢流高程和下切字段。隔离浏览器的旧湖泊详情显示“旧图待重新诊断”及 `—` 容量 / 高程 / 下切，不伪造结论。
- 真实 Chrome `5410` 保留原 `258` 条河流和“丹水”筛选：丹水仍为 `#69 / 15,338 m³/s / → #48 玉溪 / 无有效出口`，玉溪仍为 `#48 / 3,375 m³/s / 主河（无出口）`。本轮没有自动修改或重生成用户存档；应用新模型需要用户明确执行河流重新生成。
