# 下一批交互审计准权威任务候选池

本文依据已经通过独立审查的 [`interaction-usability-audit-plan.md`](./interaction-usability-audit-plan.md)，把全功能交互审计拆成可依次执行、可独立审查、最终统一浏览器验证的准权威候选。候选编号延续上一批 `Q-12～Q-17`，使用 `Q-18～Q-24`。

用户已于 2026-07-19 整体批准本池，`Q-18～Q-24` 已按顺序转为权威任务第 101～107 项。具体执行范围、顺序、状态和最小验收以 [`../current-plan.md`](../current-plan.md#权威任务清单) 为准；本文件保留候选来源与转正边界，不再作为活动状态源。

## 拆分原则

- 本批目标是审计现有交互，不改变已有功能逻辑，也不把历史第 28～52、54～100 项重新入队。
- 每项采用“调查 → 开发 → 审查测试”：调查冻结真实代码与契约，开发仅形成清单、脚本或证据账本，审查测试只运行静态和文档门禁。
- `Q-18～Q-23` 完成时不逐项启动浏览器；`Q-24` 复用同一浏览器状态，对前六项准备的全部路径进行统一验证并收口证据。
- 发现的问题只登记为 `INT-R / U / F / S / C / V / E / A / P`；涉及 callback、handler、command、history、selection、mode、持久化或数据结果变化时必须附加 `INT-B`。
- 审计发现不得在本批顺手修复。纯交互整改与功能变更提案由 `Q-24` 分池输出，等待用户另行批准。
- 新发现的阶段外能力或性能工作写入 `FOLLOWUPS.md`，不能扩展本批完成标准。

## 候选范围与最小验收

### Q-18：冻结交互表面分母、固定场景与证据基础设施

**任务目标**

从当前 checkout 生成唯一的交互表面分母，冻结后续审计所需的固定场景、状态复位契约和证据格式，消除“只数 Vue 面板”或依赖人工记忆造成的覆盖缺口。

**封闭范围**

- 枚举 Vue 主面板与详情、非 Vue 面板、常驻组件、固定浮层、共享组件、画布 / overlay 和全局事件。
- 每行记录 `surfaceId`、来源类型、入口、条件、事件 / 回调、结果、既有决定、证据状态、`INT-B`、`included / excluded` 和排除理由。
- 生成机器可读 JSON 与中文 Markdown；`excluded` 项的理由必须非空，并汇总 included / excluded 数量。
- 冻结 `F0～F6` 场景 manifest、样本哈希、对象数量、三档视口、状态复位步骤和 `E-C / E-S / E-F / E-N` 证据字段。
- 只允许新增审计脚本、夹具说明和生成报告，不修改正式应用交互或业务数据语义。

**最小验收**

- 七类来源全部进入清单，未分类表面为 `0`，排除项均有可审查理由。
- `F0～F6` 均有稳定构造方式；破坏性副本、地图指纹、历史基线和复位动作可重复。
- 生成工具在同一 checkout 重跑结果稳定，报告不依赖硬编码的 `26 / 28 / 22 / 16` 快照作为完成分母。
- 静态契约检查、生成器自身测试和 `git diff --check` 通过。

### Q-19：审计高频核心任务闭环

**任务目标**

按用户真实目标审计启动、恢复、生成、保存、导入、快速导出、地图导航、选择、对象详情、领域面板、列表定位、重命名及撤销 / 重做的完整闭环。

**封闭范围**

- 基于 Q-18 清单追踪“入口 → 组件事件 → callback → handler → command / API → effects → history → feedback”。
- 记录首次使用者与熟练使用者两种视角，检查可发现性、步骤成本、影响说明、成功反馈、退出与恢复。
- 明确全局入口与上下文入口的既有双情境；没有新证据时，不把第 57 项已批准的重生成入口并存重新判为冗余。
- 本项只完成 `E-C` 静态链路和待验证步骤，不运行浏览器、不整改问题。

**最小验收**

- 所有纳入范围的可见动作都能追到明确结果或登记为未知 / 无效候选，静态作用链没有静默跳过。
- 保存、导入、地图替换、selection 路由、历史和反馈的前置 / 退出条件均进入证据账本。
- 每个结论标注既有决定、心智模型依据、严重度、信心和是否附加 `INT-B`。
- 账本结构校验、相关静态回归和 `git diff --check` 通过。

### Q-20：审计注册画布模式与非注册直接操控

**任务目标**

覆盖运行时全部注册画布模式，以及未进入 `CANVAS_TOOL_MODE` 的选择、导航、标签、测量、拖动和列宽调整，建立完整直接操控生命周期矩阵。

**封闭范围**

- 从运行时代码生成注册模式分母，不继续沿用旧专题中的 `23` 或方案快照中的 `28` 作为硬编码完成条件。
- 每种注册模式记录入口、前置目标、光标、手势、预览、提交、取消、切换、Esc、面板关闭、地图替换和历史写入。
- 非注册矩阵覆盖基础选择 / 平移 / 缩放、手工标签拖动、测量控制点、主面板与固定浮层拖动、动作坞二级面板和表格列宽。
- 检查点击未移动、`pointercancel`、捕获丢失、模式竞争和异常恢复；只形成 `E-C` 与统一浏览器步骤，不改事件路由。

**最小验收**

- 当前注册模式未覆盖数为 `0`；非注册直接操控未分类数为 `0`。
- 每条生命周期都明确开始、移动、完成、取消、冲突、历史及恢复结果；未知结果进入问题账本。
- 现有画布工具回归清单与运行时分母的差异被记录，但不借审计任务修复业务行为。
- 矩阵结构校验、相关静态回归和 `git diff --check` 通过。

### Q-21：审计复杂面板、表单与批量任务

**任务目标**

审计高度、国家、省份、文化、宗教、军事、经济、外交、气候、导出等复杂工作区，确认首层 / 高级层级、表单事务、批量集合和长任务反馈是否可理解。

**封闭范围**

- 覆盖对象表格的筛选、排序、主选中、复选集合、地图高亮、定位、双击、列宽、虚拟列表、空态和导出选中项。
- 区分即时生效、草稿预览、显式应用和危险事务，建立“应用 / 套用 / 设为 / 保存 / 确认 / 提交”的实际动作词典。
- 追踪动作坞中立即执行、切换画布模式和打开二级编辑三种结果；检查禁用原因、点击外部关闭和草稿丢失风险。
- 本项只形成 `E-C` 与统一浏览器步骤，不统一业务行为、不删除入口、不新增接线。

**最小验收**

- Q-18 清单中的全部复杂面板、表格、字段和动作坞均有静态结论或明确未知项。
- 主选中、批量集合和地图高亮的关系有可验证规则；表单提交时机与历史边界可追踪。
- 样式问题至少引用设计 token、共享组件、既有视觉规则或可测量 DOM 几何之一。
- 账本结构校验、相关静态回归和 `git diff --check` 通过。

### Q-22：审计危险操作、异常路径与恢复契约

**任务目标**

系统检查删除、批量删除、合并、拆分、重生成、地图替换和下游重算，确认影响说明、确认等级、失败回滚、撤销 / 重做和重试路径与实际风险相称。

**封闭范围**

- 对照 Q-18 的 `F4 可控失败`、`F5 破坏性副本` 和 `F6 空态 / 边界`，为每条危险路径准备正常、取消、失败和恢复步骤。
- 追踪预检、浏览器确认、共享影响模型和领域自定义确认之间的差异，不为形式统一而忽略风险差异。
- 核对异步重复点击、执行中取消、失败后状态残留和旧结果晚到；性能问题只记录，除非它直接破坏当前交互闭环。
- 新增取消、恢复、事务或回滚语义一律标记 `INT-B`，本项不实施。

**最小验收**

- 每个危险动作都有影响范围、确认方式、历史能力、失败结果和恢复方案。
- 所有声称支持失败 / 取消 / 恢复的路径均准备 `E-F` 操作与结果断言，不能用偶发错误代替固定场景。
- 破坏性流程可由撤销或重新载入夹具恢复同一指纹，不污染后续统一验证。
- 静态作用链审查、夹具预检和 `git diff --check` 通过。

### Q-23：审计键盘、焦点、响应式与视觉表达

**任务目标**

在功能作用链已明确后，检查快捷键优先级、焦点流、Esc 退出层级、窄视口、页面缩放、长文本、点击目标、层级和状态样式，避免用视觉调整掩盖行为错误。

**封闭范围**

- 从当前代码生成快捷键和焦点入口分母，覆盖输入框抑制、画布模式、固定浮层、主面板、对象详情、撤销 / 重做和 Esc。
- 准备 `1280×720`、`720×720`、`576×576` CSS 压力样本，以及长中文名称、展开候选和系统字体放大变体。
- 检查所有编辑面板、悬停面板、比例尺、测量条和地图标签的层级契约，以及裁切、溢出、间距、对齐、状态色和目标尺寸。
- 只提出 DOM 语义、样式和反馈建议；新增键盘结果、焦点路由或退出语义时标记 `INT-B`。

**最小验收**

- 当前快捷键、焦点入口和 Esc 消费者未分类数为 `0`，优先级冲突均有可复现步骤。
- 三档视口及长文本变体都有统一浏览器检查表；每个视觉问题都有客观对照依据。
- 纯 UI 建议与功能变化提案已经拆分，不在同一候选中夹带行为修改。
- 静态契约检查、相关响应式 / 层级回归和 `git diff --check` 通过。

### Q-24：统一浏览器验证并形成整改候选批次

**任务目标**

复用同一浏览器和固定夹具，对 Q-19～Q-23 准备的真实用户任务、直接操控、复杂面板、危险路径、键盘和响应式矩阵进行一次统一验证，完成证据闭环并形成下一轮整改候选。

**封闭范围**

- 每条证据开始前执行 Q-18 状态复位契约；正常关键路径形成 `E-S`，失败 / 取消 / 恢复声明形成 `E-F`。
- 记录准确 URL、夹具、地图指纹、操作步骤、DOM 几何 / 截图、控制台与结果断言；不得以截图单独代替作用链证据。
- 将结论分为：合理保留、纯交互整改候选、`INT-B` 功能变更提案、阶段外 `FOLLOWUPS`。
- 只形成审计报告和候选批次，不修改正式应用、不把候选自动写入权威任务清单。

**最小验收**

- 交互表面未分类为 `0`、未知结果为 `0`；`E-N` 均有明确缺口和所需夹具，且没有被写成通过。
- 关键正常路径具有 `E-C + E-S`，声明的异常 / 恢复路径具有 `E-C + E-F`。
- 每个问题都有稳定编号、复现步骤、代码与浏览器证据、严重度、信心、整改建议及 `INT-B` 判定。
- 输出交互总表、问题证据账本、跨系统整改原则、功能变更附录和下一批准权威整改候选；用户批准前不实施。
- 审计报告一致性检查和 `git diff --check` 通过；本批不要求生产构建，因为没有修改正式应用代码。

## 明确不进入本批

- 不重新验收或重新实现第 28～52、54～100 项；本批只观察它们在当前整体交互链中的表现。
- 不直接修复审计发现的冗余、无效、样式、恢复、键盘或响应问题。
- 不删除现有功能，不改变命令、事务、selection、历史、画布模式、数据结构、持久化或导入导出。
- 不开展与交互闭环无关的生成算法、渲染性能、名称质量、3D / OBJ、真实 CRS、动态军事或贸易流扩展。
