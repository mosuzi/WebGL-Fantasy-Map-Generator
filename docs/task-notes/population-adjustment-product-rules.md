# 人口手工调整规则

本文冻结权威任务第 78 项首期人口调整语义。实现与验收只覆盖单一区域的手工增减，不扩展为人口迁移或人口模拟。

## 首期语义

- 首期只采用“区域手工增减”，不实现区域间迁移；操作会改变全图总人口，不要求总量守恒。
- 单次只允许选择一个有效国家、省份、文化或宗教作为目标。目标通过当前人口统计行确定，不接受任意多边形、跨类型集合或多个区域批量组合。
- `delta` 使用现有地图内部人口单位，与城市人口编辑字段一致；必须是非零有限数，单次范围为 `-1000000～1000000`，结果区域总人口不得超过 `1000000000`。

## 城乡与个体分摊

- 当前区域总人口大于 0 时，增减量先按现有乡村 / 城市人口比例分摊，再分别按目标 pack cells 和城市的当前人口占比分配。
- 当前某一侧为 0 时，该侧不凭空获得人口，全部增减量落在已有非零人口的一侧；当前为 0 的单个 cell 或城市继续保持 0。
- 整个目标区域人口为 0 时拒绝操作；首期不负责选择新人口落点。负向调整不得超过目标当前总人口，允许精确减到 0。
- 城市人口继续同步 `settlements.cities` 与 `pack.burgs`；不新增、删除或移动城市，不改变首都、省会、港口、类型、剪影和路线。

## 范围与事务

- 单次目标最多包含 `20000` 个 pack cells 和 `4096` 个城市；目标不存在、已删除、没有人口载体或超过范围上限时，结构化预检必须拒绝。
- 成功后同步 pack / grid 乡村人口、city / burg 城市人口、国家、省份、文化、宗教的城乡汇总、人口点、城镇摘要和市场需求摘要；经济交易、军事、外交和地区等人口下游标记为 stale，不在本项自动重算。
- UI 与 API 共用同一预检和单事务命令。失败完整回滚，一次应用只形成一条历史；撤销 / 重做精确恢复人口、统计、经济摘要和 stale。
- 本项不修改适居度、高度、人口比例设置、文化 / 宗教归属、行政边界或城市位置；旧图不新增持久化必填字段。

## 第 93 项：区域间守恒转移

- 来源和目标只允许为两个不同的同类型有效区域，类型仍限国家、省份、文化、宗教。不同类型的范围可能重叠，因此首期拒绝跨类型转移；同类型区域若被异常数据解析为共享 pack cell 或城市，也由预检拒绝。
- `amount` 必须为正有限数，单次最多 `1000000`。来源可转移人口为“来源当前总人口”和单次上限的较小值；目标容量为“目标距离 `1000000000` 总人口上限的余量”和单次上限的较小值。请求超过任一侧能力时整次拒绝，不做隐式截断，故合法预检中的实际转移量等于请求量。
- 来源与目标都必须已有非零人口载体。首期继续沿用第 78 项的零人口规则，不为零人口区域、零人口 cell 或零人口城市选择新落点。
- 来源减少和目标增加分别按各自操作前的乡村 / 城市比例分摊，再在各自非零 pack cells 和城市间按现有人口比例分配；因此双方各自保持原有城乡结构，不把来源城市人口绑定到目标城市，也不创建、删除或移动城市。
- 预检必须返回来源可转移人口、目标容量、请求量、实际量、双方前后总人口及城乡人口。只读预检不要求确认；UI 使用明确的“确认转移”动作，稳定 API `edit.population.transfer` 必须传入 `{confirm: true}`。
- 两侧变更合并为一条 `population-transfer` 历史事务，共用人口统计、人口点、城镇摘要、经济需求和 stale 刷新；失败、撤销、重做恢复同一份事务快照。全图人口只允许保留 Float32 pack 人口分摊产生的既有精度误差。
- 排除人口刷子、自动迁徙、时间模拟、适居度驱动、改宗、城市创建 / 删除 / 移动、跨类型换算和零人口落点；旧图不新增持久化必填字段。
