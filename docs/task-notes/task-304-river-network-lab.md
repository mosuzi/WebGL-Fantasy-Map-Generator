# 第304项：河流网络算法实验室与生成质量修复

## 当前状态与执行门禁

本专题已完成只读调查，`304-A` 实验室壳体与只读审计、`304-B` 父子 DAG 候选、`304-C` 汇流锚点候选、`304-D` 流量 / 宽度与碎线策略均已完成，`304-E` 隔离浏览器决策门已完成但结论为 **BLOCK**。候选仍停留在实验室；只有后续明确批准并重新满足性能 / 确定性门禁，才允许另行开封闭子任务接入正式算法。

实验室必须是独立原型，参考 `prototype/boundary-topology-lab/` 的“固定夹具、候选算法、结构化诊断、浏览器对照”模式。实验室可以读取正式生成器导出的只读快照，也可以在隔离上下文生成固定种子；不得接管用户当前已打开的 `http://127.0.0.1:5410/?debug=1` 标签页，不得刷新、覆盖、重新生成用户的 100k 地图。

## 目标与问题定义

需要把截图中的视觉现象拆成可测量的类别，而不是只调整河流颜色或线宽：

1. **离散细线**：河流对象存在，但路径过短、流量过低、宽度不足或被简化成孤立的可见片段。
2. **支流未接干流**：河流关系声明为父子关系，但子河口没有落在父河折线上 / 共享汇流锚点，或者 renderer 的两条独立 meander 造成视觉间隙。
3. **支流超过干流**：子河在汇流处的流量或视觉宽度超过接收干流，或父关系在归一化后发生变化但宽度没有重新计算。
4. **无效循环**：真实流向关系形成环，或几何折线形成闭合 / 回返；合法河网可以有多个支流和多次汇流，但不能把普通交叉误判成环，也不能把湖泊进出水误删。
5. **非汇流交叉**：两条没有父子 / 共享汇流语义的河流折线相交，视觉上像河网但水文关系不成立。

## 可复现步骤

1. 在隔离生成上下文中固定种子和目标规模，生成 10k、50k、100k 三档地图；不调用当前用户标签页的生成、刷新或存档操作。
2. 读取河流对象及其 `cells`、`gridCells`、`points`、`parent`、`basin`、`source`、`mouth`、`flux`、`discharge`、`width`，同时保留生成前后的结构摘要。
3. 对 cell 路径、父子关系、折线锚点、折线交叉、流量 / 宽度和可见碎片运行同一套审计，输出稳定的 issue ID、河流 ID、相关 cell、坐标、指标、证据等级和候选修复。
4. 将诊断样本送入实验室的固定夹具和候选算法对照。候选只写实验室内存快照，分别显示原始结果与候选结果，不能写回地图或存档。
5. 304-E 才允许在隔离系统 Chrome 中对相同种子做真实视觉对照，检查 console、page、health、WebGL、地图 checksum、schema 和存档往返；当前用户 Chrome 只做标签页身份保护，不作为实验对象。

## 现有证据

### 截图现象

截图中可见多处短而细的孤立线段、支流靠近但没有稳定贴合粗干流、支流视觉宽度疑似超过接收河道，以及右上角疑似回返 / 循环。截图不能单独证明数据层的 `parent` 循环，因此实验室必须同时做拓扑、几何和渲染分类。

### 代码路径证据

| 位置 | 观察 | 证据等级 |
| --- | --- | --- |
| `generator/rivers.js` 的流量累积和 `flowDown` | 流向按处理高度推进；父关系依据到达时的部分流量建立，没有统一的访问集合和后置 DAG 证明 | 强假设，需夹具确认 |
| `generator/rivers.js` 的 `defineRivers` | 每条河先独立生成 meander 折线并计算宽度；宽度发生在最终网络归一化前 | 已确认的结构风险 |
| `generator/river-network.js` 的 `normalizeRiverNetwork` | 检查父存在性、cell 连通、出口、basin 和循环，但不检查汇流几何锚点、非汇流折线交叉、视觉碎片和归一化后的宽度单调性 | 已确认的覆盖缺口 |
| 30 个固定种子只读扫描 | 8087 条河流中，探索性细线阈值命中 7752 条，支流宽度超过父河 147 条，原始折线相交 134 处；相交包含合法父子汇流 | 已观测，指标仍需标定 |
| 同批扫描 | 未复现父关系循环和折线自交 | 反证不足；截图循环仍待分类 |

上述数量不是最终发布门槛：细线阈值目前是实验室候选尺度，宽度比较受父关系和汇流后累计值影响，折线相交必须先排除合法汇流。

## 根因假设与证据等级

| 假设 | 解释 | 当前等级 | 验证方式 |
| --- | --- | --- | --- |
| H1：父关系使用部分到达流量，未建立严格无环流向 | 可能导致父子关系与最终累计流量不一致，并为异常回返留下空间 | 中 | A/B 对照“高度严格 DAG + visited + tie-break”与当前算法，检查所有固定循环夹具 |
| H2：子河和父河各自 meander，汇流处没有共享锚点 | 可以解释“看似接近但没有接上”和非汇流交叉 | 高 | 以共享 edge / confluence anchor 做几何距离、端点重合和折线相交分类 |
| H3：宽度在网络归一化前计算 | 父关系或 basin 被修复 / 丢弃后，`width`、`discharge` 与最终网络语义可能不一致 | 高 | 归一化后重新累计流量并重算宽度，比较单调性和旧输出 |
| H4：低流量、短路径和简化共同制造视觉碎片 | 当前 `MIN_FLUX_TO_FORM_RIVER`、`MIN_RIVER_CELLS` 和折线简化可能保留“存在但不可见为河”的对象 | 中高 | 用世界尺度、长度、宽度、流量分位数建立 fixture 和真实种子视觉门槛 |
| H5：截图右上角是父关系循环 | 也可能只是非汇流交叉、回返折线或湖泊进出水重叠 | 未证实 | 构造 cycle / crossing / lake fixtures，并输出关系环与几何环两类 ID |

## 实验室结构

已新增独立目录 `prototype/river-network-lab/`，不把候选算法直接塞进正式 generator：

- `src/fixtures.js`：孤立碎线、未贴合汇流、支流越级、A→B→A 关系环、合法汇流、非汇流交叉、湖泊进出水、边界河口等最小固定夹具。
- `src/audit.js`：输出重复 cell、父关系环、汇流锚点距离、无关交叉、流量 / 宽度越级、长度 / 宽度碎片和湖泊 / 河口观察项，并提供正式输出的只读快照函数。
- `src/algorithms.js`：在内存快照上执行确定性父子图分析、visited 拓扑排序和循环 / 缺失父级拒绝；候选失败不会静默降级。
- `src/algorithms.js`：增加父河折线最近点汇流锚点分析；只允许固定容差内的父子末端候选，超容差或保护出口保持拒绝 / 不吸附。
- `src/algorithms.js`：增加按拓扑序逆序累计流量、局部宽度单调性候选和碎线策略分类；策略只输出视觉决策，不删除或覆盖地图对象。
- `algorithms.js`：实现候选算法并明确每个算法的输入、输出、拒绝理由和修复范围；候选失败要作为实验结果显示，不能静默降级成当前结果。
- `src/app.js` / `index.html` / `src/styles.css`：固定夹具选择、只读河网视图、问题列表、指标卡片和夹具矩阵。
- `tools/river-network-lab-regression.mjs`：无头固定夹具与 10k / 50k / 100k 固定种子矩阵回归；生产构建只验证实验室不污染正式入口。

实验室的最小数据流为：

```text
固定夹具或正式只读快照
        ↓
拓扑 / 几何 / 水文 / 视觉审计
        ↓
候选算法（只改内存副本）
        ↓
同一审计 + 原始 / 候选对照
        ↓
304-E 正式接入决策
```

## 不可破坏的兼容性边界

- 旧地图仍可读取旧河流对象；在正式接入前不得改变 `river.cells`、`points`、`parent`、`basin`、`source`、`mouth`、`flux`、`discharge` 的存在性和含义。
- 实验室不得写入当前地图、LocalStorage、存档、历史栈、用户当前 Chrome 标签页或云端 provider。
- 不修改 `source/`；正式 generator 的任何改动必须经过 304-E 决策后另行限定。
- 合法多支流、湖泊进水 / 出水、河口入海、同一河网的多次汇流都必须保留；“所有折线相交均删除”“所有环均删除”“所有细线均加粗”均不是可接受修复。
- 任何候选算法都要输出拒绝 / 未分类原因，不能把无法证明的修复伪装成通过。

## 当前明确不应实施的方向

1. 直接调大或调小全局河流宽度、只提高最小流量阈值，无法区分断接、合法小河和数据层错误。
2. 通过删除所有短河或所有交叉来消除截图症状，会破坏真实支流、湖泊溢流和河口。
3. 在 `normalizeRiverNetwork` 后只修 `parent` 而不重建汇流几何、累计流量和宽度，会留下新的视觉不一致。
4. 在用户当前 100k 标签页中反复生成、刷新或直接编辑河流来做实验；实验必须使用隔离上下文、固定快照和可回滚的内存副本。
5. 直接把实验室候选算法接入正式 `rivers.js`，或把实验室夹具写入正式地图、schema、存档或 API。

## 304-E 统一验收记录模板

最终报告至少固定以下列：`规模`、`种子`、`原始河流数`、`候选河流数`、`关系环`、`几何自交`、`非汇流交叉`、`未贴合汇流数`、`流量越级数`、`宽度越级数`、`碎线数`、`合法湖泊 / 河口保留率`、`最大长任务`、`内存峰值`、`draw / renderer / overlay 次数`、`console / page / health / WebGL 错误`、`checksum`、`schema`、`存档兼容`和`视觉结论`。

只要任一硬门禁失败，结论为 `BLOCK`，候选只保留在实验室；所有硬门禁通过且截图问题类别有证据改善，才可提出独立的正式生成器实施项。
