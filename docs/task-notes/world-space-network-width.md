# 道路与河流世界尺度宽度

本文记录权威任务第 66 项的产品语义、实现边界与验收口径。活动状态和执行顺序仍以 [`../current-plan.md`](../current-plan.md#权威任务清单) 为准。

## 已确认的问题

- 道路基础线层当前按等级固定使用 `3.6 / 2.6 / 1.8 CSS px`，随后仅按设备像素比换算到渲染缓冲。
- 河流根据既有水文数据计算相对宽度，但最终仍钳制在 `1.1～9.5 CSS px`，适配视图下不能继续变细。
- 两类路径都先把世界坐标转换为屏幕坐标，再以屏幕像素生成线网格；相机缩放改变路径位置，却不改变基础线宽，因此全图适配时网络视觉权重过高。
- 道路和河流 picking 已分别使用独立的屏幕命中容差并换算到世界坐标，基础线变细不必等同于命中范围变小。

## 产品语义

“真实宽度”在本项目中指地图世界尺度下的制图语义宽度，不代表道路具有可信的现实米制宽度。

- 河流：继续使用流量、汇水结果、`widthFactor` 和 `sourceWidth` 等现有信息表达上游细、下游粗，再把语义宽度随相机投影到屏幕。
- 道路：继续使用 `primary / secondary / minor` 等现有类型和等级表达主次关系，再把各级语义宽度随相机投影到屏幕。
- 适配视图：次要路段或细小河段允许进入亚像素，必要时降低不透明度或按稳定层级隐藏，不能继续依靠固定屏幕下限保持醒目。
- 放大视图：线宽应随缩放增长，但仍要有防止异常数据产生巨型线宽的上限保护。

## 渲染与交互分层

1. 基础道路与河流线层使用世界尺度语义宽度，并按当前相机、画布尺寸和设备像素比投影。
2. 选中、悬停、编辑预览等强调层可以继续使用稳定的屏幕像素宽度，确保对象状态可辨识。
3. picking 继续使用独立的屏幕命中容差，不能因为适配视图下基础线进入亚像素就变得无法选择。
4. 实时画布、适配视图、连续缩放和 PNG 导出必须共用同一基础宽度语义；异步 mesh 构建继续受现有视口版本门禁约束。
5. 诊断信息应能证明语义世界宽度与投影 CSS 宽度的范围，专项回归不依赖肉眼猜测固定截图。

## 最小验收

- 固定地图在适配视图及至少两个代表性放大级别下，同一路段和河段的投影 CSS 宽度随缩放单调变化，不再固定为现有像素档位。
- 河流始终保持上游细于下游，道路保持主路宽于次路、次路宽于小路；异常输入不会产生负宽度、非有限宽度或覆盖大片地图的巨型线条。
- 适配视图下路网与河网不再压过地形、政治区和标签；进入选中或编辑状态后仍有清晰强调，既有 `7 / 9 px` picking 容差或等价命中能力保留。
- 连续平移、缩放和适配视图后，旧视口异步结果不能覆盖新相机对应的线宽；PNG 导出与实时画布表现一致。
- 新增专项宽度回归，既有路线 / 河流渲染门禁、生产构建和 `git diff --check` 通过，并在同一 Chrome 中集中确认适配视图与放大视图。

## 明确不做

- 不增加动态交通模拟、道路车流、现实单位换算或新的道路宽度存档字段。
- 不改路线拓扑、河网生成、路径平滑、颜色主题和编辑命令语义。
- 不因为基础线宽整改而降低对象选中、编辑或无障碍操作能力。
