# 全功能交互与可用性专项审计方案

## 文档状态与边界

本文是对当前 WebGL 地图生成器全部用户交互进行系统排查的专题方案。它只定义调查方法、证据格式、判断标准、覆盖矩阵和后续交付物，不修改现有功能逻辑，也不自动形成新的权威任务。

专题中的问题假设、整改建议和候选批次都不是活动待办。只有经用户确认并写入 [`../current-plan.md`](../current-plan.md#权威任务清单) 的编号事项才能进入开发。

本专题遵守以下边界：

- 保留现有生成算法、编辑命令、撤销历史、数据结构、导入导出格式和公开 API。
- 本轮先调查入口、操作顺序、状态表达、反馈、取消、恢复、键盘、布局和视觉层级，不直接改变功能结果。
- 不能因为功能低频、复杂或当前看起来价值较低就删除底层能力；先判断它应该留在首层、降为高级、合并入口、改变说明，还是确实需要产品裁决。
- 如果交互问题无法仅靠界面调整解决，必须单独写入“需要功能变更的提案”，说明原因、影响、历史与兼容风险，等待批准。
- 既有权威任务第 28～52、54～100 项不因本专题重新进入待办；旧审计结论只作基线，不把已经完成的事项伪装成新发现。

## 为什么需要重新做一次交互专项

此前的 [`../audits/ui-function-and-information-architecture-audit.md`](../audits/ui-function-and-information-architecture-audit.md) 和权威任务第 55～60 项主要解决了入口分组、面板共存、高复杂度界面分层、术语、状态样式、键盘与安全区等系统性问题。当前公共框架已经明显成熟，但功能规模继续扩大后，新的主要风险变成了：

1. 公共组件看起来一致，具体领域中的动作语义却可能不一致。
2. 单个按钮有接线，不代表用户能理解何时使用、是否生效、如何退出和如何恢复。
3. 单面板回归通过，不代表“从地图选中对象 → 打开领域面板 → 编辑 → 提交 → 撤销”的整条任务链自然。
4. 多入口不一定是冗余，低频功能也不一定无用；必须结合用户情境和真实结果判断。
5. 旧专题中的功能数量可能随实现继续增长，例如统一画布模式专题仍记录 `23` 个模式，而运行时代码当前已经有 `28` 个，说明交互清单需要从真实代码重新生成，不能只沿用历史文档。

## 交互表面分母与清单生成规则

“所有交互”的分母不能由某个目录下的组件数量代替。阶段 A 必须从当前 checkout 生成一份交互表面清单，作为审计覆盖率的唯一分母；上面的 `26 / 28 / 22 / 16` 只是在方案制定时的快照，后续代码增减时不得继续硬编码为完成依据。

清单至少覆盖以下来源类型：

| 来源类型 | 当前代表 | 必须记录的身份 |
|---|---|---|
| Vue 主面板与详情 | `*Panel.vue`，其中已包含控制面板与对象详情 | 文件、面板 id、角色、入口、持久化、关闭和主要状态 |
| 非 Vue 面板 | `development-panel.js` 等 | 创建函数、注册 id、显示条件和可见动作 |
| 常驻与读数组件 | `MapToolbar.vue`、`MeasurementReadout.vue` | selector、显示条件、点击 / 键盘行为 |
| 固定浮层 | 导出、高度图工作台、树状显示、动作坞二级面板 | overlay id、打开 / 关闭、焦点、拖动和安全区 |
| 画布与 overlay | WebGL canvas、测量 SVG、标签 / 图标 overlay、悬停面板 | 事件目标、手势、命中、层级和生命周期 |
| 共享交互组件 | 对象表格、字段、页签、动作坞、文件动作 | props / emits、默认行为和领域覆盖者 |
| 全局事件 | 快捷键、Esc、resize、scroll、文件选择、before / after 状态 | 监听作用域、优先级、禁用条件和清理方式 |

生成清单的每一行至少包含：`surfaceId`、来源类型、文件 / selector、用户入口、条件状态、事件或回调、结果类型、既有决策编号、证据状态、是否需 `INT-B`、`included / excluded` 和排除理由。worker、健康监测、内部桥接事件等没有直接用户交互的发现项可以排除，但必须留在报告中说明理由，不能静默丢弃。机器可读 JSON 和中文 Markdown 报告写入 `docs/generated/`，专题文档只保存结论。完成审计时要求清单中“未分类表面 = 0、未知结果 = 0”，而不是只满足某个面板数量。

## 以人的操作习惯为核心的设计原则

### 一条自然的操作闭环

用户完成一次编辑，通常按以下顺序思考：

1. **定向**：我现在看见什么，当前处于什么模式。
2. **找目标**：我要操作哪个对象或区域。
3. **找动作**：入口是否就在目标或当前任务附近。
4. **理解影响**：动作会立即生效、进入模式、打开表单，还是只做预览。
5. **执行**：点击、拖动、输入或选择。
6. **确认结果**：界面明确告诉我发生了什么、作用于谁、是否已经保存。
7. **退出或继续**：我能自然退出当前模式，或重复执行同类工作。
8. **恢复**：误操作时能取消、撤销、重做或回到原状态。

审计不只检查第 5 步“按钮能否点击”，而要检查完整闭环。

### 通用判断原则

- **识别优先于记忆**：常用动作应能从当前情境看见，不要求记住隐藏规则或快捷键。
- **上下文接近**：对象动作优先靠近对象、选中详情或领域面板；全局动作保留在全局入口。
- **渐进披露**：首层只承载高频、低风险、易理解能力；高级能力仍可达，但不与主路径争夺注意力。
- **动作语法稳定**：选择、定位、编辑、预览、应用、确认、取消、删除、重生成在不同面板中应表达同一类结果。
- **状态始终可见**：选中对象、当前编辑目标、活动画布模式、未提交预览和待重算数据不能只靠颜色或用户记忆。
- **直接反馈**：安全动作应立即反馈；异步动作应有阶段和完成状态；失败不能只留下瞬时 toast。
- **风险与阻力成比例**：安全、可撤销动作不应反复确认；高影响、不可逆或会覆盖数据的动作必须先说明影响。
- **允许后悔**：有撤销能力时明确可撤销；没有撤销能力时明确说明并提高确认等级。
- **避免惊讶**：打开面板、选择对象、按 Esc、切换工具、关闭面板和刷新页面的结果应符合用户预期。
- **视觉层级服务任务**：颜色、尺寸、间距、位置和图标首先表达主次、状态与风险，不只追求装饰统一。

### 判断依据的优先级

“用户会怎么想”不能只来自审查者直觉。每条心智模型结论都要标注依据，并按以下优先级使用：

1. 用户已经明确给出的反馈与操作习惯。
2. 项目中已批准并通过验收的交互契约。
3. 当前产品内同类高频组件的一致行为。
4. 常见桌面地图 / 编辑器的操作惯例；引用时必须写明只是外部惯例，不等于本项目用户事实。
5. 审查者启发式推断；只能作为待验证假设，不能写成“高频”或“大多数用户”的事实。

样式问题同样不以个人审美判定。必须至少提供一种对照：现有设计 token、同类共享组件、已批准视觉规则，或可测量的 DOM 几何（溢出、裁切、目标尺寸、间距、对齐、遮挡）。

## 审计覆盖面

### I01：启动、生成与地图替换

- 首次进入、浏览器地图恢复、生成新地图、换种子、GEO 导入、地图数据导入和高度图导入。
- 检查用户是否知道当前是在恢复、生成、替换还是重算；加载期间哪些操作不可用；失败后能否恢复。
- 重点关注“导入”和“生成”是否明确会替换当前地图、是否需要保存提醒，以及完成后 selection、编辑模式和面板状态是否自然。

### I02：地图导航与常驻工具

- 左键选择、鼠标中 / 右键平移、触控指针平移、滚轮锚点缩放、适配视图、比例尺、测量入口和工具栏。
- 检查操作是否符合地图软件习惯，面板滚轮是否误缩放地图，当前工具是否改变指针语义，适配视图是否容易找到。

### I03：悬停、拾取、选择与对象详情

- 悬停信息、地图点击、列表选择、定位、对象详情、领域面板同步和高亮。
- 检查“看见对象”“选中对象”“打开详情”“进入编辑”是否被清楚区分。
- 覆盖 Selection 策略中的 `16` 类领域绑定，以及没有领域面板的区域兜底。

### I04：主面板、详情面板和固定浮层

- 一个主面板、可选对象详情、标题拖动、手动位置、首次左侧落点、恢复、关闭、焦点返回、固定浮层和可拖动二级动作面板。
- 检查面板打开后是否遮住当前任务、关闭后是否回到合理焦点、用户拖动位置是否保持、二级面板是否因点击外部意外关闭。

### I05：控制面板与功能入口

- `7` 个页签、`6` 组管理入口、文件操作、生成、视图模式、样式、图层、单位和领域重生成。
- 检查入口名称是否符合用户目标，而不是内部模块名；同一功能的全局入口和领域入口是否各有明确情境。
- 控制面板集中重生成与领域面板重生成是第 57 项已经批准的“跨领域集中入口 + 上下文领域入口”，入口并存本身不再作为问题；只有出现新的用户反馈、浏览器行为证据或任务链成本证据时才允许重新评估。

### I06：对象列表与批量操作

- 筛选、排序、行选择、逐行定位、双击编辑、批量复选、列宽拖动、虚拟列表、空态和导出选中项。
- 当前只有部分对象表格把双击定义为编辑，其余表格只选择；需要检查差异是否来自真实任务，是否可发现，而不是强行让所有表格双击做同一件事。
- 逐行定位、地图点击和双击编辑不应互相抢夺含义。

### I07：字段、表单与提交语义

- 文本、数字、选择、颜色、滑杆、开关、备注和组合表单。
- 分类记录每个字段是即时生效、失焦生效、显式“应用”、预览后确认，还是只修改草稿。
- 检查“应用、保存、确认、设置、套用、提交”等动词是否与实际事务边界一致。

### I08：动作坞与二级编辑

- `18` 组动作坞中的直接动作、开关动作、画布模式和二级表单。
- 检查同一图标或颜色是否表达了不同结果；动作坞关闭、点击外部、切换对象和切换主面板时是否保留未提交草稿。
- 检查二级编辑面板的宽度、高度、候选列表、确认按钮位置、错误提示和滚动可达性。

### I09：画布工具模式

- 完整覆盖运行时 `28` 种模式，不使用旧专题的 `23` 项清单。
- 每种模式记录：入口、前置目标、光标、作用范围、鼠标手势、预览、一次性或连续、成功结束、取消、切换、关闭面板、Esc、地图替换和历史写入。
- 重点检查“按钮已经激活但用户不知道下一步点击哪里”“同一按钮既是入口又是退出”“松手提交与取消语义相反”等问题。

### I09A：非注册模式的直接操控

`28` 种 `CANVAS_TOOL_MODE` 不是全部直接操控。以下交互必须另建矩阵，不能塞进注册模式后遗漏：

- 基础画布的左键选择、鼠标中 / 右键平移、触控平移、滚轮锚点缩放和右键菜单抑制。
- 手工标签首次放置与后续拖动。
- 已保存测量对象的控制点拖动、键盘删除和路径编辑。
- 主面板标题拖动、动作坞二级面板拖动、导出浮层拖动、树状浮层拖动和高度图工作台拖动。
- 对象表格列宽拖动，以及其它由 pointer 捕获完成的共享组件交互。

每类直接操控都记录开始、移动、完成、点击未移动、取消、`pointercancel`、捕获丢失、与画布模式 / 面板 / 滚轮的冲突、历史写入和异常恢复。阶段 A 生成的交互表面清单决定这张矩阵的最终分母。

### I10：撤销、重做、取消与 Esc

- 主面板标题栏撤销 / 重做、全局快捷键、预览取消、画布模式退出、对象详情关闭和固定浮层关闭。
- 当前 Esc 同时承担关闭顶层浮层、停止编辑和清除选择等职责；必须验证实际优先级是否符合“先退出最内层临时状态，再退出编辑，最后清除选择”的用户预期。

### I11：危险动作、重生成和数据覆盖

- 删除、批量删除、合并、拆分、重新生成、地图替换导入、重算下游、批量覆盖和清空档案。
- 检查影响摘要、目标名称、数量、可撤销性、确认方式和执行后反馈。
- 浏览器原生确认、应用内预检、二次按钮和无确认动作必须说明为何不同。

### I12：反馈、加载、错误和恢复

- 状态横幅、预览容器、toast、文件错误详情、进度、空态、待派生和禁用原因。
- 检查反馈是否出现在用户注视区域，是否持续到用户理解，是否包含可操作的恢复动作。
- 禁用按钮必须能让用户理解缺少什么条件，不能只变灰。

### I13：快捷键、键盘与可访问性

- `22` 项快捷键、Tab 顺序、方向键页签、Enter / Space、Esc、焦点返回、可访问名称和禁用状态。
- 检查快捷键提示是否可发现、是否与输入框冲突、不可用时是否说明原因。
- 不把“有 aria-label”直接等同于可用；还要验证焦点顺序与可见操作顺序一致。

### I14：响应式、浏览器缩放与触控容错

- 桌面宽屏、窄视口、125% / 150% 页面缩放、系统字体增大、长中文名称和高 DPI。
- 检查点击目标尺寸、按钮间距、表单标签、下拉框、滚动底部、固定浮层和地图安全区。
- 暂不承诺完整移动端设计，但要避免在常见窄桌面窗口下出现不可达操作。

### I15：视觉语言与文案

- 主按钮、次按钮、危险按钮、开关态、选中态、编辑态、预览态、禁用态、图标、标题、分组、间距和空态。
- 检查样式是否准确表达功能，而不是只检查是否使用同一组件。
- 术语继续遵守既有“资源点 / 通用标记、地貌单元、测量 / 测量对象”等业务词表。

### I16：交互响应与中断

- 打开大型面板、首次懒加载、筛选、连续选择、拖动、缩放、批量操作和长任务。
- 只关注对操作感知造成的影响：是否点击后无响应、反馈晚于结果、操作期间能否重复触发、取消是否真正中断。
- 本专题不扩展为 WebGL 性能优化工程；发现性能根因时只记录需要单独立项。

## 问题分类

| 代码 | 类型 | 判定条件 | 常见处置 |
|---|---|---|---|
| `INT-R` | 冗余交互 | 同一情境中出现多个同权重入口，结果相同且用户无法理解差别 | 合并、降级或保留一个主入口 |
| `INT-U` | 无效 / 无用交互 | 可见动作没有接线、没有可观察结果、长期不可达，或只有技术数据而没有用户任务 | 解释用途、降为高级或提请移除；需要新增接线时自动标为 `INT-B` |
| `INT-F` | 流程不符合习惯 | 步骤顺序、入口位置或退出方式违背用户对当前任务的自然预期 | 调整流程和上下文位置 |
| `INT-S` | 状态不清 | 用户不知道选中了谁、正在编辑什么、是否已提交或如何退出 | 增加稳定状态与退出反馈 |
| `INT-C` | 同类行为不一致 | 同一类按钮、字段、列表或模式在不同领域中结果不同且没有理由 | 统一动作语法或明确差异 |
| `INT-V` | 样式表达错误 | 视觉权重、危险色、间距、尺寸、图标或布局与动作重要性不匹配 | 调整视觉层级，不改功能结果 |
| `INT-E` | 错误与恢复不足 | 失败、取消、撤销或重试路径缺失、不完整或不可理解 | 优先补说明和既有恢复入口；新增恢复语义归 `INT-B` |
| `INT-A` | 键盘 / 可访问性 | 焦点不可达、顺序错误、名称缺失、键盘结果与鼠标不同 | 纯 DOM 语义可直接建议；新增事件结果归 `INT-B` |
| `INT-P` | 响应中断 | 用户操作后长时间无反馈、可重复触发、取消无效或结果顺序错乱 | 只读反馈可直接建议；改变中断 / 并发行为或性能另行立项 |
| `INT-B` | 需要功能变更 | 仅调整入口、样式或反馈无法形成正确任务闭环 | 写功能变更提案，等待批准 |

### 纯交互建议与 `INT-B` 判定表

问题类型与是否需要功能变更是两个维度。任何问题只要涉及下表右侧内容，就必须附加 `INT-B`，不得以“只是补接线 / 补取消”名义直接实施。

| 可作为纯交互候选 | 自动归入 `INT-B` |
|---|---|
| 调整布局、间距、尺寸、分组、视觉权重和既有 token | 新增、删除或连接 callback |
| 在不改变可达性的前提下重排同一 handler 的入口 | 改变 handler、command、API 参数、目标或结果 |
| 修改文案、术语、帮助、危险提示和禁用原因 | 改变 history、事务边界、撤销 / 重做结果 |
| 展示运行时已经存在的只读状态，不改变分支和提交时机 | 改变 selection、编辑目标或领域面板路由 |
| 补充不改变事件路径的原生语义属性与可访问名称 | 改变画布模式、Esc、pointer / keyboard 生命周期或取消语义 |
| 使用同类组件与 DOM 几何修正裁切、溢出和层级 | 改变 LocalStorage、地图持久化、数据字段或导入导出 |
| 删除完全重复且确认调用同一 handler 的视觉入口，且不降低可发现性 | 新增自动保存、自动提交、自动重算、自动恢复或防重复执行逻辑 |

如果一项建议同时包含纯 UI 和功能变化，必须拆成两个候选；纯 UI 部分不能借机把功能变化一起带入。

## 如何判断“冗余”而不误删合理入口

以下情况通常不是冗余：

- 同一功能同时提供菜单入口和快捷键，分别服务发现与效率。
- 全局入口作用于整张地图，领域入口只作用于当前对象或当前领域。
- 列表逐行定位与地图直接点击分别服务“从数据找地图”和“从地图找对象”。
- 首层快捷动作与高级完整配置都存在，但使用频率和信息量明确不同。

只有同时满足以下大部分条件才判定为冗余：

1. 入口出现在同一情境或同一视觉层级。
2. 入口调用同一个命令并产生相同结果。
3. 前置条件、影响范围和风险相同。
4. 用户无法从名称或位置理解两者差异。
5. 移除其中一个不会增加关键任务步骤或降低可发现性。

## 如何判断“功能无用”

功能低频、复杂或面向高级用户都不能直接判为无用。必须至少完成以下检查：

- 可见入口是否能到达，禁用条件是否可能满足。
- Vue 回调是否真实注入；当前约 `267` 处可选回调需要抽样和自动检查，避免 `?.()` 把缺失接线变成静默无响应。
- 回调是否进入运行时 handler、命令或 API。
- 操作是否产生数据、视图、selection、历史、下载或稳定反馈中的至少一种结果。
- 结果是否对用户任务有意义，而不只是改变内部诊断字段。
- 是否已有更自然的入口完整替代它。
- 是否承担旧地图、导入导出、兼容或高级工作流，不能因为普通用户少用就删除。

## 单项交互证据模板

每一个被审计的交互使用同一张记录，不允许只写主观感受：

| 字段 | 内容 |
|---|---|
| 交互 ID | 稳定编号，如 `I09-state-add-01` |
| 用户目标 | 用户想完成什么，而不是组件名称 |

| 入口与上下文 | 从哪里看到、当前应选中什么 |
| 既有决定 | 相关权威任务、专题契约或“无既有决定” |
| 前置条件 | 地图、对象、图层、模式、权限或数据条件 |
| 当前步骤 | 实际点击、输入、拖动顺序 |
| 预期心智模型 | 预期及其依据层级：用户反馈 / 既有契约 / 产品内一致行为 / 外部惯例 / 启发式假设 |
| 实际结果 | 数据、视图、selection、历史、下载或反馈变化 |
| 状态反馈 | 进入、执行、成功、失败、忙碌、禁用 |
| 退出与恢复 | 取消、Esc、关闭、撤销、重做、刷新 |
| 输入方式 | 鼠标、键盘、触控板、快捷键 |

| 代码证据 | 组件、callback、handler、command、API、样式 |
| 浏览器证据 | URL、操作、截图 / DOM 几何、日志 |
| 对照组件 / 规则 | 样式 token、同类组件、已批准规则或可测量几何 |

## 严重度与排序

| 等级 | 含义 | 示例 |
|---|---|---|
| `P0` | 可能造成数据丢失、错误对象被修改、无法退出或不可恢复 | 删除目标不清、取消反而提交、导入无替换提示 |
| `P1` | 核心任务无法完成，或大多数用户会被明显误导 | 编辑态没有入口、按钮无响应、模式激活无提示 |
| `P2` | 能完成但步骤、表达或一致性明显不符合习惯 | 重复入口、提交动词混乱、双击行为不可发现 |
| `P3` | 视觉精修、低频效率或边缘场景问题 | 间距、图标、长文本、次要响应式问题 |

严重度不与修复成本绑定。信心另记为“代码确认、浏览器复现、用户反馈、待验证”，避免把假设写成结论。

## 调查方法

### 第一遍：静态可达性与作用链

从真实代码生成“入口 → 组件事件 → callback → 运行时 handler → command / API → effects → history → feedback”链：

1. 枚举全部可见按钮、表格行事件、动作坞、字段和快捷键。
2. 记录显示、禁用、选中和隐藏条件。
3. 追踪回调是否注入，是否可能静默无操作。
4. 追踪命令是否写历史、是否能撤销、是否只改变视图。
5. 标记同一个命令的所有入口，但暂不直接判为冗余。
6. 对照公开 API，只检查 UI 是否复用一致语义，不以“API 有能力”推导 UI 必须暴露入口。

### 第二遍：以真实任务链走查

不按文件顺序点按钮，而按用户目标走查：

1. 第一次生成地图并保存。
2. 导入地图、理解替换影响、失败后恢复。
3. 在地图上发现对象、查看详情、打开领域面板。
4. 在列表中筛选对象、定位、编辑字段、撤销。
5. 新增、移动、删除城市等一次性画布操作。
6. 使用高度、国家、省份、文化、宗教、生物群系等连续笔刷。
7. 使用路线、河流、湖泊、地区、标记、备注和测量等创建工具。
8. 合并 / 拆分国家、重生成领域、重算气候下游等高风险流程。
9. 批量选择、高亮、导出和清空筛选。
10. 用快捷键完成导航、切图层、开面板、撤销、重做和退出。

每条任务至少检查“首次使用者”和“熟练使用者”两种视角：前者重视可发现和解释，后者重视步骤、重复操作和快捷路径。

### 第三遍：异常、边界与冲突

- 无地图、无对象、无选择、空列表、筛选为空、孤儿对象。
- 两种模式竞争、模式中切换面板、关闭面板、按 Esc、地图替换。
- 异步操作重复点击、操作中取消、执行失败、旧结果晚到。
- 窄视口、长名称、下拉候选过长、系统字体放大、页面缩放。
- 鼠标、触控板和键盘路径不一致。
- 固定浮层、主面板、对象详情、悬停面板、比例尺和地图标签的层级冲突。

## 固定场景、状态复位与证据等级

### 固定场景矩阵

阶段 A 在 `docs/generated/` 生成夹具 manifest，记录 seed、cells、地图摘要、样本文件哈希和适用任务。最低需要以下场景：

| 场景 | 用途 | 最低要求 |
|---|---|---|
| `F0 启动 / 加载` | 恢复、生成中、无可交互地图和加载失败 | 可重复触发，不依赖人工抢时间点 |
| `F1 标准地图` | 高频选择、编辑、面板、快捷键 | 固定 seed、`10k` 级规模、对象种类完整 |
| `F2 长列表 / 复杂地图` | 虚拟表格、筛选、批量和复杂面板 | 固定 `100k` 级或等价长列表样本，记录对象数量 |
| `F3 旧图 / 导入` | 旧 schema、缺省字段、浏览器缓存和往返 | 使用仓库内稳定样本或生成后冻结哈希 |
| `F4 可控失败` | 非法文件、缺字段、失败恢复、错误详情 | 失败原因确定，不依赖网络偶发故障 |
| `F5 破坏性副本` | 删除、合并、拆分、重生成、覆盖和撤销 | 每条流程使用可丢弃副本，结束后恢复同一指纹 |
| `F6 空态 / 边界` | 无选择、空列表、孤儿对象、零数据和禁用条件 | 通过夹具或测试入口稳定构造，不污染其它场景 |

视口复用既有门禁：`1280×720` 桌面基准、`720×720` 窄视口，以及 `576×576` CSS 等效压力样本（125% 页面缩放与根字号 `20px`）。长中文名称、展开候选和系统字体放大另作为状态变体，不伪装成新的随机场景。

### 状态复位契约

每条浏览器证据开始前都要：

1. 恢复指定夹具并核对地图指纹与对象数量。
2. 清理 selection、editing、活动画布模式、未提交预览、固定浮层和非目标面板。
3. 恢复约定视图、图层、主题、单位、面板位置和历史基线。
4. 记录前置的 `undo / redo` 数量及当前目标。
5. 破坏性流程完成后撤销并核对指纹；无法完整撤销的流程直接重新载入夹具。
6. 下一条证据不得复用上一条未确认的中间态。

### 证据等级

| 等级 | 含义 | 对路径通过的支持 |
|---|---|---:|
| `E-C` | 代码链与静态契约已追踪 | 否；只证明接线意图 |
| `E-S` | 真实浏览器成功路径已完成并核对结果 | 完成 `E-C` 后，支持正常路径通过 |
| `E-F` | 真实浏览器失败 / 取消 / 边界路径已完成并核对恢复 | 完成 `E-C` 后，支持异常路径通过 |
| `E-N` | 当前条件无法稳定构造，已记录原因和所需夹具 | 否；只能留下明确缺口 |

审计收口要求“未分类 = 0、未知结果 = 0”。关键用户路径必须有 `E-S`，声明具备失败 / 取消 / 恢复能力的路径必须有 `E-F`；`E-N` 不得写成通过，也不得用一次偶然失败替代稳定夹具。

## 初步问题假设

以下仅是根据代码和历史文档形成的调查假设，尚未经过完整浏览器矩阵，不是整改结论：

1. **验证既有重生成双情境是否仍然清楚。** 第 57 项已明确把控制面板“目标领域 + 单按钮”和领域面板入口定义为有意的集中 / 上下文双入口；本专题只检查当前文案、影响摘要和跳转是否仍符合该决定。没有新的用户反馈或浏览器证据，不得把入口并存本身重新报告为冗余。
2. **对象表格的双击语义可发现性不足。** 当前约 `11` 个面板双击进入编辑，其余表格只选择；差异可能合理，但界面没有明显告诉用户哪些行支持双击。
3. **可选回调可能掩盖静默无响应。** 大量 `callbacks.onX?.()` 是组件复用手段，但必须确认每个可见动作在正式挂载路径中都有对应 handler。
4. **动作坞包含三种完全不同的结果。** `panel: false` 可能立即执行或切换画布模式，普通动作则打开二级编辑；相同图标按钮外形可能不足以表达“下一步去画布操作”。
5. **画布模式清单已经发生文档漂移。** 旧专题记录 `23` 个，运行时为 `28` 个；新增的移动、中心选择、适居度、拓扑等模式需要重新检查状态提示和退出链。
6. **Esc 的职责可能过多。** 固定浮层注册表、全局停止编辑 / 清除选择、动作坞和各类画布工具都可能响应 Esc，需要验证最内层状态是否优先退出。
7. **选择对象后的路径可能分裂。** 领域面板打开时更新领域面板，关闭时打开对象详情，这符合既有方案 B，但用户可能无法预测同一次地图点击为何在不同现场产生不同界面。
8. **表单提交动词和事务边界可能不统一。** “应用、套用、设为、保存、确认、提交”可能分别表示即时命令、草稿提交或高风险事务，需要建立动作词典。
9. **危险动作的确认方式可能不一致。** 国家合并 / 拆分使用预检，名称库部分删除使用浏览器确认，其它删除走共享影响模型；需要检查差异是否与风险相称。
10. **控制面板“简介”同时承担文件中心。** 保存、导入和导出位于简介页，熟练用户可能不把项目文件操作与“简介”联系起来。
11. **批量选择、高亮、主选中和普通行选择可能混淆。** 同一表格可能同时存在主选中行、复选框批量集合和地图高亮集合，必须验证三者视觉和清除动作。
12. **禁用状态可能缺少原因。** 公共组件能禁用动作，但领域面板未必都提供缺失条件说明。
13. **“点击外部关闭”可能丢失草稿。** 动作坞二级面板支持点击外部关闭，需要检查未提交输入是否可安全丢弃、是否应提醒或保存草稿。
14. **首层按钮数量仍可能过高。** 管理入口已经分组，但高度、军事、经济、国家等复杂面板内部仍需要以真实任务频率复核首层与高级区。
15. **反馈通道可能互相竞争。** 状态横幅、详情、toast、文件状态和调试健康日志并存，需要确认用户能看见最重要的当前结果。

## 交付物

完整审计完成后应形成五类材料：

1. **交互表面与功能—交互总表**：由当前代码生成完整表面分母，再覆盖所有可见功能、入口、条件状态、结果、历史和恢复方式。
2. **问题证据账本**：每个问题都有稳定编号、复现步骤、代码 / 浏览器证据、严重度和信心。
3. **跨系统整改原则**：只归纳真正重复出现的模式，如画布工具入口、表单提交、危险动作和批量选择，不为单个面板过度抽象。
4. **需功能变更附录**：把无法通过交互层解决的问题单列，不混入纯 UI 整改。
5. **准权威候选批次**：按依赖和风险整理候选，但只有用户批准后才写入当前权威任务清单。

生成的截图、DOM 几何和机器报告应放在 `docs/generated/`；手写结论继续放在 `docs/task-notes/` 或 `docs/audits/`，不得在多个文档维护不同的当前待办。

## 推荐执行阶段

### 阶段 A：冻结真实交互总表

- 生成全部 Vue / 非 Vue 面板、常驻组件、固定浮层、共享组件、画布 / overlay 和全局事件表面，再追踪入口、回调、handler、命令、快捷键与画布模式。
- 冻结 `F0～F6` 场景、样本哈希、视口、复位契约和证据等级。

- 输出未接线、不可达和结果未知的调查列表。

### 阶段 B：审计最高频闭环

- 生成 / 恢复 / 保存 / 导入 / 快速导出。

- 列表筛选、定位、重命名、撤销 / 重做。

### 阶段 C：审计所有画布直接操作

- 按 `28` 个运行时模式逐项走完进入、预览、完成、取消、切换和恢复；同时完成基础选择 / 导航、标签与测量点拖动、面板 / 浮层拖动和列宽拖动等非注册模式直接操控矩阵。

### 阶段 D：审计复杂面板与批量任务

### 阶段 E：审计危险操作与异常恢复

- 先提交审计结果，不直接开发。

- 用户确认优先级、保留 / 合并 / 降级方向后，再转成封闭编号任务。

## 需要功能变更时的提案格式

发现 `INT-B` 时必须另写：

1. 当前功能结果和当前交互为何无法形成闭环。
2. 仅改入口、文案、样式或反馈为什么不足。
3. 建议改变的命令、事务、预览、历史或数据语义。
4. 对旧地图、浏览器缓存、导入导出、公开 API 和撤销历史的影响。
5. 可选方案及用户取舍。
6. 最小验收和回滚策略。

未经批准，不实施以下类型的变化：

- 改变按钮最终调用的领域命令。
- 把即时生效改为批量事务，或反向修改。
- 改变 selection 自动打开面板的策略。
- 改变 Esc、关闭面板或地图替换时的数据处理。
- 删除功能、数据字段、导出内容或兼容入口。
- 新增自动保存、自动提交、自动重算等会改变结果的行为。

## 专题完成门禁

只有满足以下条件，才能说“所有交互已经排查”，而不是“抽查了几个面板”：

- 代码生成的交互表面清单覆盖 Vue 主 / 详情面板、非 Vue 面板、常驻组件、固定浮层、共享组件、画布 / overlay 和全局事件；未分类表面为 `0`。方案快照中的 `26` 个 `*Panel.vue` 已包含控制面板和对象详情，不重复计数。
- 所有可见按钮和动作坞动作都能追到有效结果或明确判为问题。
- `28` 个画布模式全部完成生命周期矩阵。
- 全部非注册模式直接操控完成开始、移动、完成、取消、冲突和恢复矩阵。
- `22` 项快捷键和 `16` 类 Selection 绑定完成真实任务检查。
- 所有危险动作都有影响范围、确认、历史和恢复结论。
- 全部表格完成选择、定位、双击、批量、空态和长列表检查。
- 桌面、窄视口、页面缩放和键盘路径均有浏览器证据。
- `F0～F6` 固定场景、样本哈希和状态复位契约可复现；正常关键路径具有 `E-S`，失败 / 取消 / 恢复声明具有 `E-F`，未知结果为 `0`，`E-N` 没有被写成通过。
- 每个问题都区分“纯交互可修”和“需要功能变化”。
- 审计结论先交用户确认，没有自行写入新的权威任务。
