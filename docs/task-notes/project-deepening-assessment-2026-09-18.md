### C-02：当前存档格式及恢复说明校准

**依据。** [存档手册](../wiki/存档与导入导出.md) 仍称 `.webfmg` 为 gzip JSON，[旧图手册](../wiki/旧图兼容.md) 将浏览器固定存档列为 gzip-base64。现行 [压缩保存](../../app/webgl-generator/src/runtime/map-file-io.js) 先编码 [v3 容器](../../app/webgl-generator/src/runtime/webfmg-v3-container.js)，[浏览器存储](../../app/webgl-generator/src/runtime/browser-map-storage.js) 优先保存压缩二进制记录。文档/schema v2 与容器 v3 是不同版本轴。

**建议范围。** 校准现行用户手册、当前 AI 接手资料和仍作为现行说明引用的导出矩阵；区别新写入格式与可读旧格式，说明完整文件不持久化本次撤销栈。历史验收记录保留历史语义，不全库替换 v2 或 gzip 字样。

**最小验收。** 明确“当前默认写入 / 可读取旧格式 / JSON 交换 / 浏览器恢复”的对应关系；版本常量和入口对得上；变更链接有效；既有 Wiki 审计通过；不改变存档字节、扩展名及迁移代码。

**边界与依赖。** 与 C-01 独立。首个门为逐条对照实际编码入口和常量；规模：小。格式描述引用源码常量，不能把链接 / 关键词审计通过当作语义正确的唯一证据。

### C-03：准确的保存状态与离开提醒

**依据。** [MapRevisionTracker](../../app/webgl-generator/src/runtime/map-revision.js) 在执行、撤销等操作后继续推进 revision，不能以 revision 相等判断内容是否回到保存点。[持久字段登记](../../app/webgl-generator/src/runtime/canonical-map-field-registry.js) 含 persisted presentation；[存档入口](../../app/webgl-generator/src/runtime/app.js) 还采集当前单位及主题。当前没有找到完整的已保存内容基线和离开提醒接线。

**建议范围。** 为当前地图提供“有修改 / 最近手动保存或导出时间 / 保存目的地”；统一 UI、API、快捷键的保存结果记录。内容基线由正式存档内容定义，不由选择、面板位置、缩放等会话动作决定。地图事实、实际随档的视觉内容和单位分别纳入，导出时刻等非内容元数据排除。

**关键规则。**

- 分别记录本地下载、浏览器手动槽、云端的内容凭据，显示哪一个目的地保存到了哪一份内容；PNG、GeoJSON、只在内存创建 payload 均不算完整地图保存。
- 本地下载只能确认文件已交给浏览器，文案不能声称已验证磁盘落盘；云端上传真正成功、浏览器事务提交成功后才能更新对应凭据。
- 保存开始后若又修改内容，旧保存结果不能把新内容标为已保存；失败、取消或远端冲突不清除未保存状态。
- 保存 A → 编辑 B → 撤销到 A 应恢复对应保存状态；撤销栈被截断或创建新分支时仍要正确，不能只比较栈长度。
- 导入 / 恢复设置与其来源相符的基线；新生成地图明确为尚无手动保存。页面离开仅在确有未保存内容时提示，浏览器无法显示的场景不承诺绝对拦截。

**最小验收。** 覆盖命名 / 人口 / 备注 / 持久化样式及单位、纯浏览动作、撤销重做、保存中再编辑、保存失败、下载与云端差异、整图替换；内容识别不在每次输入时同步序列化全张 100k 地图。旧档导入后不因补默认值无限显示新增修改。

**边界与依赖。** 不新增云同步、文件系统权限或自动保存；不改变唯一地图 revision owner。首个门是保存内容归属表与状态机反例；规模：中。C-02 的格式说明可复用，但不是实现阻塞依赖。

### C-04：独立的自动恢复点与可选择恢复

**依据。** [浏览器存储](../../app/webgl-generator/src/runtime/browser-map-storage.js) 使用固定 `current` 记录；[持久文档身份](../../app/webgl-generator/src/runtime/persisted-document-identity.js) 可用于分组，但同一文件复制或多标签导入会共享 documentId，不能仅据此判定同一写入者。

**建议范围。** 在不覆盖手动存档槽的独立存储中保存滚动恢复点。首期建议用户主动开启，按内容变化合并请求、在操作空闲时写入；每个文档写入分支最多保留最近 3 个已成功版本，并设总字节预算。具体总预算须在实施首阶段用代表性 100k 档案实测后冻结。

**关键规则。**

- 复用 C-03 的内容凭据，连续无变化不重复存；捕获开始与提交时核对地图实例和内容来源，旧地图任务不能写成新地图恢复点。
- 先完整写入并提交新记录，再淘汰旧恢复点；容量不足或写入失败保留原可用恢复点。单个文件已超预算时解释并停止自动写入，不删除手动存档凑空间。
- 同文档多标签 / 副本分支分开保存或显式冲突处理，不相互覆盖；不宣称能识别用户是否把副本视为另一个世界。
- 启动时展示名称、时间、规模和来源，用户选定后才替换地图。损坏点可跳过，原记录保留供抢救。
- 自动恢复点显示为恢复保障，不冒充已导出本地文件或已同步云端；恢复沿用整图导入与历史清空语义。

**最小验收。** 正常写入、重复跳过、刷新后的选择恢复、写入中止、容量不足、坏记录、同文档多写入者、地图切换竞态、自动功能关闭，以及 3k / 100k 真实页面。不能依赖 `beforeunload` 中完成异步压缩或写入。

**边界与依赖。** 硬依赖 C-03。不提供跨设备同步，不持久化闭包形式的撤销命令，不承诺浏览器清站点数据后仍可恢复。首个门是独立存储的原子写入 / 淘汰测试；规模：中至大。

### C-05：城市修改后的关联更新提示与引导

**依据。** [城市面板](../../app/webgl-generator/src/ui/vue/components/CityPanel.vue) 已说明设施与人口修改不自动重算经济、道路、军队；[属性命令](../../app/webgl-generator/src/runtime/city-attribute-commands.js)、[人口事务](../../app/webgl-generator/src/runtime/city-population-transaction.js) 保留这一行为。[依赖 registry](../../app/webgl-generator/src/core/dependency-registry.ts) 已能描述投影失效，[规划配方](../../app/webgl-generator/src/runtime/planner-recipe-registry.js) 也已有多步语义，不能新增一套竞争的地图 owner 或万能调度器。

**建议范围。** 只覆盖城市六设施和直接人口编辑这两类起因，汇总“哪些内容可能需要更新、由什么修改引起、已有入口在哪里、更新会改变哪些对象”。首期提供跳转与单个现有动作，不提供无人确认的一键全更新。

**关键规则。** 区分显示刷新、统计计算、经济链重算和道路 / 军事从空重生成；不要把它们统一称为无损刷新。人口潜力重算是用户意图，不能自动覆盖手工人口。经济更新、道路重生成等是否消除了提示，应基于相应来源及成功结果；失败、部分范围完成和仅打开面板不能清空提示。撤销起因后重新判断，不累加永久提示。

**最小验收。** 首都迁移能解释旧 / 新城市和所属国影响；人口修改的四类即时所属统计继续正确；不改变现有人口、路线、军队或锁；提示在操作、撤销重做、成功 / 失败重算、保存回读后保持一致。旧档缺记录时明确“没有本版本跟踪记录”，不能声称所有派生一定最新。普通界面不泄漏内部协议术语。

**边界与依赖。** 与 C-03 可独立实现；涉及经济 / 道路结果清除时需引用 C-01 的归因结论。复用现行持久化及派生状态分类；若需新增可选字段，只回填空 / 未知状态。首个门是两类起因的来源—影响—完成事件矩阵；规模：中。

**依据。** [object-query-api](../../app/webgl-generator/src/runtime/object-query-api.js) 已支持跨类型查询、文本匹配、字段白名单和分页；[place-analysis-api](../../app/webgl-generator/src/runtime/place-analysis-api.js) 支持完整名称解析。主要工具栏没有面向用户的统一入口。

**建议范围。** 增加一个轻量查找入口，仅覆盖国家、省份、城市的名称 / 全名和明确 ID；结果展示类型与行政归属，选择与定位分开，定位复用既有相机、高亮、专用面板路由。排序确定，优先精确名称、其次前缀和包含匹配，同名不能直接选第一个。

**最小验收。** 中文同名、空结果、稀疏 ID、已删除对象、有效城市 ID 0、改名、撤销、整图切换；支持键盘上下选择、Enter 定位和 Esc 关闭，输入法组合输入不误触；文字按普通文本显示。输入新查询或地图改变后旧结果不得接管选择。查询与定位不增加编辑历史；100k 数据下按需查询，不对每个按键全量创建重型对象快照。

**边界与依赖。** 无硬依赖；作为 C-08 的目标选择器可复用。首期不搜索私人备注全文，不引入联网搜索、向量索引、自动拼音或自然语言写操作。首个门是现有跨类型查询适配及同名排序测试；规模：中。

### C-07：交易的现有路网可达性与路径诊断

**依据。** [economy.js](../../app/webgl-generator/src/generator/economy.js) 的 `createProductionAndDeals` 以市场数组环状选择交易方，`tradePartyDistance` 用坐标直线距离；[settlements.js](../../app/webgl-generator/src/generator/settlements.js) 已有 road / trail / searoute、`packCells` 与几何路径。海路可能没有有效城市端点，不能只按 `from / to` 建城市图。

**建议范围。** 对用户选中的交易提供按需只读诊断，分别展示现有直线距离和可解释的现有网络路径长度，标注陆路、海路、换乘、无现成通路或资料不足，并可高亮选用路径。首期不改交易对象、运费、税收和市场配对。

**关键规则。**

- 以正式路线及真实拓扑建立图；同一合法道路节点可以相接，视觉交叉、相邻但未连接、隔海相近不能自动连通。
- 市场先解析中心 burg，再映射 pack cell；城市 ID、burg ID 和 pack cell ID 不混用。进出海路须解释合法港口连接，不能因共用行政区或几何接近而换乘。
- 路径长度由采用的路线几何累计；共享边不得重复收费或重复累加。“最短”只针对已声明的长度权重，不冒充最快或最便宜。
- 未铺路不等于绝对禁止运输；显示“现有路网未连通”。缺端点、损坏旧几何或超出诊断支持能力属于“资料不足”，不冒充不可达。
- 对同一输入缓存路径图与查询结果，路线编辑、港口变动、市场中心变化或整图替换后正确失效；旧锁定异常对象只作诊断，不成为全图生成硬门。

**最小验收。** 已连接、断开、绕行、纯海运、陆海换乘、几何交叉不连通、共享边、孤立市场、端点缺失、路线撤销恢复；诊断前后地图内容与历史不变；3k / 100k 按需查询和高亮实测。

**边界与依赖。** C-01 的道路归因影响诊断样本解释，但实现不能擅自补路。按需查询，不做所有城市两两最短路；战争封锁、通行权、容量和时间成本留给 D-01。首个门是小型人工网络的路径及失败分类；规模：中至大。

### C-08：孤儿备注重新绑定与正文抢救

**依据。** [NotesPanel](../../app/webgl-generator/src/ui/vue/components/NotesPanel.vue) 对孤儿备注提供删除 / 导出，禁止继续编辑；[object-notes](../../app/webgl-generator/src/runtime/object-notes.js) 与 [导入校验](../../app/webgl-generator/src/runtime/note-import.js) 约束 note id 为 `kind:objectId`。对象重生成时数字 ID 复用还可能使旧备注指向新对象，这类潜在错绑不能只靠“对象存在”来排除。

**建议范围。** 允许编辑仍被识别为孤儿的纯文本正文，并手动选择一个现存对象重新绑定；首期目标限国家、省份、城市。每次操作预览旧记录与目标，原对象名称只作提示，不用于自动迁移。

**关键规则。** 新目标没有备注时，迁移记录身份并保持正文、创建时间等用户内容；新目标已有非空备注时首期拒绝覆盖并解释，不能静默拼接或丢弃任一正文。原 note key 的删除、新 key 的写入和引用刷新必须是单事务，undo 精确恢复原键与字段存在性。只处理用户选定且能确认的孤儿；ID 复用的对象世代治理另评，不声称本项解决所有备注错绑。

**最小验收。** 孤儿正文可保存、有效目标可绑定、同名目标不误选、目标冲突拒绝、预检后目标删除或整图替换拒绝、撤销重做和旧备注导入 / 完整保存回读；所有不相关备注不变。

**边界与依赖。** 建议复用 C-06 的选择能力，不以 C-06 全局 UI 为硬依赖。富文本、AI 正文、图片附件、人物图谱和双向链接不进入本项。首个门是 note 身份迁移、冲突及精确撤销；规模：中。

### C-09：PNG 导出预设与明确像素尺寸

**依据。** [导出界面](../../app/webgl-generator/src/ui/vue/components/ControlPanel.vue) 已有 1～4 倍、四类裁剪和七类覆盖元素开关；[PNG 合成](../../app/webgl-generator/src/runtime/map-file-io.js) 根据当前导出帧与倍率确定输出尺寸并临时调整后恢复相机。缺的是方便复用的输出配置及显式尺寸契约。

**建议范围。** 保存、命名和调用本浏览器的 PNG 配置；配置包含裁剪方式、标注类别、透明选项和目标像素尺寸。全幅 / 固定世界范围导出在窗口尺寸变化后仍输出指定像素尺寸；当前视口模式继续遵从当前可见范围，不声称跨窗口内容相同。

**关键规则。** 首期锁定宽高比，由输入宽或高计算另一侧；尺寸冲突明确解释。世界范围预设须记录适用地图并校验边界，不把 A 图坐标默默套到 B 图。申请渲染资源前检查尺寸及像素预算，超限可解释拒绝；目标分辨率应参与地图和标注绘制，不能只拉伸一张低分辨率截图冒充高质量导出。

**最小验收。** 配置保存 / 重开、非法配置恢复、两种窗口宽度下固定全幅尺寸正确、覆盖元素开关与画面一致、超限不破坏地图、导出失败后相机与图层恢复；保留旧倍率参数的 API 兼容并确认真实 PNG 像素与标签布局。

**边界与依赖。** 与其它候选独立；具体输出尺寸上限先由现有 GPU / canvas 约束及实测冻结。首期不提供 PDF、SVG 重建、地图册、多页排版、DPI 印刷承诺或超大分块拼图。首个门是配置归一、尺寸及兼容测试；规模：中至大。

## 4. 原五个深化方向的复核记录

### D-01：让网络可达性参与实际交易与运费

依赖 C-07，但只读可达性通过并不自动批准改变经济。需要先决定：未铺路地区可否越野贸易、海路换乘权重、外交封锁是否生效、孤立市场如何供需、手工或锁定交易如何保护、交易候选怎样确定而不受数组排序影响。

建议下一次方案先固定一个确定性静态规则，显式重算才采用；旧交易保留旧距离 / 成本语义，区分估算与网络距离，不能把 `distance` 的含义悄悄改掉。再用连接 / 断路 / 修路和市场顺序置换验证价格、税收及贸易结果的因果关系。相关外交输入缺失或路径未知不能变成全图硬拒绝。产品与性能风险：高。

### D-02：制造原料约束——9 月 19 日恢复保留

资源已经通过 `applyResourceSupplyToMarkets` 进入 stock、resourceSupply、供需与价格；当前配方未限制城市产量。[源码](../../app/webgl-generator/src/generator/economy.js) 这只是现行静态模型的边界，不再定义为必须完善的缺口。

9 月 18 日曾按用户批注撤回；9 月 19 日用户改为保留此方向。恢复研究配方、原料与产量关系，但先区分静态产能约束和动态库存消耗，定义存量 / 流量单位、资源竞争、循环配方与重复操作幂等性。当前只恢复候选，不直接修改既有经济生成，也不默认批准时间推进和完整供应链。

### D-03：动态结算——9 月 19 日恢复保留，仍排除赔款

[和平条款](../../app/webgl-generator/src/runtime/diplomacy-edit-commands.js) 明确 `economicSettlement: record-only`。更关键的是 `collectStateTreasuries` 会把国家 treasury 重写为交易税与人头税之和，它目前不是稳定的累计现金余额。直接做 A 减 / B 加会在下一次经济重算中被覆盖。

用户于 9 月 19 日恢复保留动态结算方向，应先定义结算触发、周期、持久余额与派生税收的区别，保证重复请求不重复入账、重算不冲掉余额、撤销和旧档兼容；尚未批准具体模型。赔款要求没有撤销：现有结构化赔款位于命令归一化、API schema 与测试 / 配方示例中，第 395 项仍删除新输入及现行宣传，普通和平与自由文本保持，旧外交纪事只作为历史文字回读。恢复财政方向不恢复赔款，登记也不等于产品已删除。

### D-04：交战预估模型——按静态定位撤回扩展建议

现有 [轻量规则](../../app/webgl-generator/src/runtime/military-edit-commands.js) 接受用户指定结果后施加固定损耗；军事生成已有地形、征募和设施作用，这不等于存在可验证的战斗概率模型。

本批不新增胜率、预期损耗、交战模型或结算。若用户需要双方对照，应使用地图上已有的兵力、兵种与地理事实，只读展示且注明统计口径，可归入 S-02 的区域对照讨论；不能把静态比较包装成战争预测。现有手选结果功能未被本轮要求删除，不擅自扩大第 395 项范围。

### D-05：局部道路 / 经济重算与多步统一更新

当前中央范围选择只为省份开放指定国家、为城市开放指定国家 / 省份。扩大到道路 / 经济时，跨边界道路、市场腹地和交易两端会跨越用户选择区，不能把全图算法套一个过滤器就称局部重算。

需先定义范围内外所有权、跨界对象切分还是整体更新、范围外统计允许变化的边界、锁对象及稳定 ID、分阶段失败后的历史与恢复。C-05 只引导现有动作；“一键更新”若分步提交必须如实说明部分成功，若承诺一次撤销则要另外设计原子复合事务。先选单一领域与单一范围口径做方案，不能将全部组合纳入本批。
