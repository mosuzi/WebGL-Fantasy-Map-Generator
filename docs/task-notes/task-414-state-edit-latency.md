# 第 414 项：国家编辑响应与前置计算

## 实际链路

国家画笔与新增国家是主线程编辑事务、局部 cell 属性更新、政治边界后台刷新、标签刷新；它们不经过整图 `render.prepare` 安装链路。换用 WebGPU 只能改变绘制端，无法消除这段编辑计算。浏览器的 LongTask、长帧和输入事件由性能观察器采集；主线程阻塞期间，浏览器先缓冲条目，恢复后写入开发面板。画笔预览、提交、建国、改色和标签刷新有独立样本与分段耗时。

## 已证实的热点及修复

- 旧建国流程对同一目标多次查找 pack cell；现在一次检查结果传入事务，建国阶段记录检查、快照、首都、政治汇总、省份修复和省份极点耗时。
- 国家新增与画笔分别重扫全图计算国家和省份统计；现在一次遍历同时汇总。省份极点的格内点到全部边界点距离，原为两层逐项比较；大集合改用精确最近邻树，小集合仍用直接比较。专项与直接比较结果一致。
- 旧存档新增国家后强制改色，GPU 调色板更新后又重建整张 cell 表面，单次 `setColor` 为 `1387.6ms`。纯改色现在更新调色板、受影响平滑边缘和当前帧；不具备 GPU 常驻条件时仍走原重建路径。
- 国家画笔首次预览只改归属，旧通路仍向 GPU 上传身份、地形、数值三张纹理。现在比较补丁前后的原始字节，只上传真正变化的通道；身份单通道、全通道、回滚与第二次上传失败恢复均有专项断言。
- 画笔和建国的正式标签刷新安排在画面绘制机会之后，并单独记录标签构建和 HTML 布局；最新笔迹有令牌校验，旧的延后任务不得覆盖新图。
- 延后标签执行时读取当前渲染资源绑定，避免玩家紧接着改色后旧绑定覆盖新版本。新增国家或刷出新首都城市时执行完整覆盖层更新，让首都图标和城市标签进入画面。

## 性能证据

| 场景 | 修改前定位 | 最终复验 |
|---|---:|---:|
| 指定 100k 旧档强制改色 | `setColor 1387.6ms`，LongTask `1578ms` | `setColor 22.7ms`，逐次输入 LongTask `0` |
| 指定 100k 旧档普通建国 | 首次仪表化 `81.4ms` | 完整链路 `87.2ms` |
| 指定 100k 旧档原首都建国 | 首次仪表化 `63.6ms` | 完整链路 `62.3ms` |
| 指定 100k 旧档刷回原国 | 首次仪表化 `41.7ms` | 完整链路 `45ms` |
| 固定生成 100k 画笔 | 先前提交约 `79.6ms`，其中同步标签约 `34.2ms` | 提交 `36.8ms`，预览最大 `20.1ms`，标签独立 `43.1ms` |

最终独立验收前，100k 指针手势还有 `66ms` LongTask，随后窄诊断为 `53ms`；无变化的移动事件均不足 `8ms`，首笔改变 `86` 格时局部 GPU 刷新为 `29.9ms`。只上传变化通道后，首笔 GPU 刷新为 `5.6ms`，预览最大 `20.1ms`、提交 `36.8ms`、撤销通过；目标手势浏览器 LongTask `0`、健康事件 `0`、WebGL 错误 `0`。最终同窗长帧最高 `101.2ms`，其脚本阻塞未达到产品 LongTask 门。

旧档是 `krichars (3).webfmg`，SHA-256 为 `CF7402BC2BEA22AD1FCDE441444479F880DC0DB15D55520EF5A1A399D335DA61`。在隔离的正式构建 Chrome 中导入；没有改动用户已打开的标签页。生成小图、生成 100k 和旧档的新增、原首都重选、画笔、邻国撞色修复、删除与撤销均通过；正式 WebGL 错误、页面错误和操作窗口健康事件为 `0`。100k 画笔另测预览、提交、标签与撤销，交互卡顿为 `0`。

旧档窄夹具曾把四个独立操作放在同一个 `page.evaluate`，即使改色已经降至 `26ms`，浏览器仍报告累计 `205ms` LongTask；改为每次输入单独派发后为 `0`。这项夹具修正对应真实玩家交互的任务边界，未改变产品超限门。其余诊断重试的现象与实质调整保存在本地 `work/task414/retry-log.md`。

`state-add` 与 `state-brush-commit` 的耗时是同步命令完成时间，不能解释成标签最终呈现时间。`state-label-refresh` 另记排队等待、构建、布局及排队到 DOM 更新的总时长；开发面板分别显示。标签完成后的实际屏幕合成由浏览器控制，以上时长不冒充 GPU 呈现时间。窄夹具还覆盖同一输入任务内“涂抹后立即改色”，等待标签并再次绘制，确保资源版本一致。

最终固定 100k 画笔标签独立执行 `43.1ms`，排队 `177.4ms`，排队到 DOM 更新 `220.5ms`；连续旧档操作中最高一次排队到 DOM 更新 `328.4ms`。这些是异步标签完成延迟，不计入上述同步画笔提交，也没有形成 `>200ms` 主线程 LongTask。
