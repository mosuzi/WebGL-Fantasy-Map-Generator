# 图层控制、无人区命名与云存储专项

本文冻结权威任务第 236～241 项的实施边界。六项按编号顺序执行；每项达到最小验收后立即进入下一项，不把调查中发现的其它改进自动纳入本批。

## 第 236 项：图层信息架构

控制面板的图层页按“地形水文、政治边界、地图对象、地区、标注辅助”分组。地区在首层提供一个复合入口，继续保留 `zones / zoneEvents / zoneNatural / zoneWilderness / zoneLabels` 五个底层状态；标记入口同理组合 `resources / markers`。复合入口必须区分全开、全关和部分开启，既有 API、偏好键、渲染器与存档格式不变。

## 第 237 项：网格单元默认关闭

渲染器已经默认关闭 `gridCells`，本项只让控制面板在无显式偏好时使用相同默认值。用户已经保存的开关状态继续优先，定位诊断主动打开网格的既有行为不变。

## 第 238 项：自动无人区语义命名

自动无人区根据连通分量及共享边邻域生成稳定名称，优先使用足够明确的城镇、省份或文化语义，国家仅在单一边界明显占优时兜底。序号只用于同名消歧，不再暴露内部地区 id。旧图加载不静默改名，手工名称与锁定对象保持；新图生成或用户显式重生成地区时才更新自动名称。

## 第 239 项：隐藏纹章入口

只移除控制面板中的“实验功能 / 纹章统计”入口。纹章数据、生成、存档、对象查询、内部面板注册及旧图兼容全部保留，不改变公开 API 分母。

## 第 240 项：下拉箭头间距

调整共享 `UiSelectField` 的箭头容器，使箭头更靠近右边框，同时保留长文本空间、焦点、禁用、展开和窄屏行为。直接使用 Element Plus 或原生 `select` 的少数例外不在本项范围，除非真实浏览器证明它们受同一共享问题影响。

## 第 241 项：可配置云存储

新增 Dropbox 与 Google Drive 云端地图存储。两者复用现有完整地图 JSON / gzip 序列化和安全导入链，提供连接、断开、新建、列出、明确目标后的覆盖与载入；覆盖和载入均须用户确认，云端副作用不进入地图撤销历史。

- Dropbox 使用 App Folder、短期令牌与 authorization code + PKCE；Google Drive 使用 `drive.file` 和 Google Identity Services token model。
- Dropbox app key、redirect URI 与 Google client ID 通过统一的 `VITE_FMG_*` 环境变量配置；仓库只提交空值示例。它们是公开 client identifier，不得填写 client secret、refresh token 或用户 token。
- 第 241 项当时把 access token 只保存在内存；第 262 项后，短期 token 只扩展到当前标签页 `sessionStorage`。Dropbox 的 PKCE verifier 与 state 仍只在握手期间写入 `sessionStorage`，完成后立即清理。任何 token 都不得进入日志、导出文件、公开 API 或错误详情。
- 不实现后台同步、自动保存、远端删除、分享链接、任意云盘文件浏览、文件夹管理、冲突合并或 headless 云写入。
- 未配置时两个 provider 可见但禁用，并明确指向自部署配置说明；不回退到原作硬编码 app key。
- 无项目方 OAuth client 与测试账号时，以 fixture、mock transport 和系统 Chrome 完成协议与 UI 验收，并明确保留 live provider 未联调状态。

## 第 262 项：刷新后恢复当前标签页云连接

第 262 项实施前，provider 只把短期 access token 保存在 JavaScript 闭包，应用刷新会重建 registry，因此即使令牌仍有效也必须重新连接。第 262 项把这段生命周期扩展到当前标签页会话，不引入长期凭据或后台能力。

- 成功连接后默认把 access token、绝对到期时间和 provider / origin / 配置 / scope 指纹写入 `sessionStorage`；不增加用户开关。
- registry 初始化只恢复结构有效、未过期且指纹完全一致的记录。关闭标签页、过期、401、配置变化、记录损坏或主动断开后均不得恢复。
- registry 与面板普通销毁只释放当前内存引用和到期计时器，不能把刷新流程误当成用户主动断开；用户点击断开仍清除会话并尝试远端 revoke。
- Google Identity Services 继续使用 token model 与 `drive.file`，但不再强制每次 `prompt: "consent"`；首次或新增权限仍由 Google 正常触发授权，令牌到期后仍须用户手势重新获取。
- refresh token、LocalStorage、IndexedDB、地图文件、日志、错误详情、公开 API、跨标签页共享、后台同步与自动保存继续排除。

验收必须覆盖两 provider 的写入与重建恢复、过期 / 损坏 / 配置变化拒绝、401 清理、主动断开清理与 revoke、普通 dispose 保留、Google 无强制 consent，以及系统 Chrome 同一标签页刷新和断开后刷新反例。

## 统一验收

- 静态专项覆盖复合图层三态、网格默认、无人区命名稳定性、纹章入口隐藏、下拉箭头几何和云存储 registry / OAuth / 远端文件操作。
- 旧偏好、旧地图 JSON / gzip、浏览器存储、对象查询、独立底层图层 API 与地图导入链保持兼容。
- 系统 Chrome 覆盖图层页、首次网格开关、默认种子无人区名称、管理页、共享下拉框和云存储未配置 / mock 状态；地图 checksum、历史、相机不被保存操作改变。
- 生产构建、相关回归和 `git diff --check` 通过，`source/` 无改动。
# 第 248～251 项：地区管理与图层控制复核修正

## 现场结论

- 共享 `UiRegenerationLockActions` 没有自身布局样式；在地区管理当前宽度下，五个操作按钮纵向排列但相邻间距为 `0px`。
- 地区重生成后的 `map.zones / pack.zones` 与管理列表已经获得语义名称，画布仍保留旧“荒野 4”；重生成刷新集合缺少 `line-layers` 和 `labels`。
- 地区表格先显示 `ID` 再显示名称，窄面板和快速扫读时容易把 `0 / 1 / 2 / 3` 误认为地区名。
- 第 236 项把五个地区状态压成了单一复合入口。底层状态始终独立，但用户失去了按事件、自然、自动无人区和名称分别控制的入口。

## 收敛方案

- 批量操作区使用统一网格和 `8px` 间距，不修改任何选择或锁定事件。
- 地区重生成把 `line-layers / labels` 纳入刷新；旧自动编号名兼容有无空格的“荒野 / 荒原 + 数字”，只有显式重生成才迁移。无 `nameMode` 且不符合自动编号模式的旧名称按人工结果保护。
- 地区列表先显示“名称”，再显示“编号”；编号继续可见、可排序，不伪装成名称。
- 地区图层显示五个入口：`zones / zoneEvents / zoneNatural / zoneWilderness / zoneLabels` 分别对应“全部地区 / 事件地区 / 自然地区 / 自动无人区 / 地区名称”。不修改底层字段和渲染判定。

## 验收重点

- 浏览器量测默认和窄屏按钮间距；验证多选、锁定禁用态不变。
- 在同一张图执行地区重生成，比较列表与画布名称，并验证撤销 / 重做。
- 逐个切换五个地区图层入口，确认总开关与子开关的可见结果、`aria-pressed` 和偏好状态一致。
- 运行地区、图层信息架构、响应式、生产构建与差异检查；`5411` 服务保持运行。

## 第 248～251 项完成结果

- `1440 / 390 / 320px` 下批量按钮相邻间距均为 `8px`，document 横向溢出为 `0`。
- 旧“荒野 4”在显式重生成后由列表与画布同步替换为语义名称；撤销 / 重做同步，旧手工名保护回归通过。
- 地区五级图层入口完整且可逐项关闭 / 恢复；底层状态键、偏好和地图数据未迁移。
- 系统 Chrome 专项、聚焦回归、扩展回归、复杂工作区审计、生产构建和差异检查通过；只记录既有同步大事务的输入停顿性能遥测。
