# 第 417 项：旧存档恢复与导入诊断隔离

## 现象与原因

用户线上浏览器保存的是有效的 `WEBFMG3` 文档。它包含新建国家的活动城市 `#949 / #950`，但缺少对应的 `burg #4822 / #4823`；`settlement_cell_identity_invalid / missing-burg` 在加载时拒绝提交。国家编辑命令写入了新城市和 burg，地图副本写集却漏掉 `pack.burgs`、城镇 cell 镜像及部分政治派生数据，因而浏览器保存取得不完整副本。菜单中显示的 `0B / API 文档` 是没有文件对象时诊断默认值，不能据此判断用户存档损坏。

## 修复边界

- 国家命令副本同步新增的城市、burg、grid / pack cell 镜像和派生过期标记。新建首都即时写入 grid 城镇代表索引；画笔撤销恢复原值。直接 JSON、压缩导出与保存入口均校验城市 / burg 身份，禁止写出无法回读的地图。
- 旧档迁移只在 burg 缺失且城市 ID、burg ID、grid / pack cell 对应、陆地和坐标均有效时合成缺失记录。沿用城市名称、人口、国家、文化、位置与视觉资料；活动 burg 冲突、异常稀疏 ID、空坐标和水域记录继续明确拒绝。迁移在完成全量校验后才写入目标地图，不覆盖尚未成功提交的浏览器原始存档。
- 普通界面隐藏文件大小、MIME、诊断代码和失败阶段等技术详情；浏览器存档和恢复点失败不在菜单留下红色技术块。调试模式仍可查看、清除和导出完整诊断，且来源不再伪称“API 文档”。GEO 与高度图的 UI 包装不再用第二次原始错误覆盖友好状态。

## 验收证据

- 隔离浏览器载入用户原始 `WEBFMG3` gzip 副本：城市 `#949 / #950`、对应 burg、国家首都和两层 cell 镜像一致；原始保存记录哈希保持。保存再读回后，继续新增国家生成城市 `#951` / burg `#4824`，再次保存读回仍一致。恢复、首次保存、再次读回、建国、再次保存、最后读回的目标 LongTask 上限分别为 `148 / 0 / 170 / 125 / 0 / 195ms`，目标浏览器错误为 `0`。原始浏览器标签页未刷新或修改。
- 正式浏览器兼容夹具覆盖旧 v2、缺失 burg 迁移、故意损坏存档、普通 / 调试模式诊断、原记录不改写与直接 JSON 导出拒绝不完整地图；目标 LongTask 最大 `78ms`，页面错误 `0`。专项覆盖异常大 ID、空 cell / 坐标、水域、grid 与 pack 不同 feature ID 空间、国家增删 / 画笔撤销 / 首都补建与副本写集。
- 首次空白地图启动对照曾出现 `214 / 225ms` 单次任务，独立启动专项目标复验的冷启、热启、慢加载和错误恢复最高 `140ms`；它不涉及旧档恢复或建国目标窗口。`build:app`、`typecheck:core`、`check:ui-layout`（709 状态、问题 0）、相关 Node 专项通过，独立集成复核 `ACCEPT`。

私有存档探查脚本、完整地图、原始截图与浏览器运行记录仅保存在忽略的 `docs/generated/task-417-recovery/`，不提交入库。
