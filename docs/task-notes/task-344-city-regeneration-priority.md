## 现场证据

- 精确标签页：`http://127.0.0.1:5410/?debug=1`，原 `stage-2-1`、实际 `100000` grid / `4.3万` pack。
- 正式控制面板选择“城镇”并点击“重新生成城镇”，稳定返回：`重设失败：请求包含 27 个数据不一致的省份，全部省会重评均已拒绝。`
- 当前数据为 `21` 国、`235` 省、`949` 城、`218` 港、`607` 路；WebGL error `0`，编辑历史为空，失败前没有提交或撤销项。
- 第 343 项已移除领域重建前的省会预检，但城镇重建内部 `reassessGeneratedProvincialCapitals` 对 `no-valid-candidate` 仍返回硬拒绝，导致整批城镇事务回滚。

## 产品判定

- 用户主动城镇重生成的主目标是替换城镇、港口和道路；省会候选不足属于该次重建需要收敛的派生状态，不得反向否决整批用户操作。
- 修复模式必须消除悬空 `province.burg` 与错误省会标记；若目标省份确无可用城市，可保留省份领土中心并清空其省会引用，省份系统标记为待派生。
- 显式锁对象保持原值；锁导致省份无法收敛时保护该对象并继续其它省份，不把单对象冲突扩散为整批拒绝。
- 手工省会重评不是主动城镇重生成，继续采用严格检查并向用户报告无候选或镜像错误。

## 实施结果

- `repairInconsistentCurrent` 模式遇到省份没有任何 city / burg / pack / politics 一致候选时，不再返回 `no-valid-candidate` 硬拒绝；改为形成 `cleared-no-candidate` 修复计划。
- 修复计划保留省份领土中心与所属国家，清空 politics / pack 两侧的悬空 `burg`，并移除该省份与旧引用城市 / burg 的错误省会标记。普通手工检查未启用修复模式，仍按原语义拒绝。
- 未扩大省份锁对城镇重生成的闭包，也未改变城镇选址、数量、间距、港口或道路算法；显式城镇 / 道路锁、事务、Worker owner 与撤销门保持原行为。

## 验收证据

- 专项构造无领土、无城市候选且省会悬空的活动省份：手工重评拒绝；城镇 Worker 成功，politics / pack `burg` 均归零，其它有领土省份仍保持唯一省会镜像。
- 浏览器 Worker 专项在城市重生成前制造同类孤立省份，结果 `committed=true / pending=false / invalidated=false`，单历史、单 revision、撤销、Loading、非性能 health 与 WebGL 均通过。
- 完整 Worker 十一类终验为 `protocol=PASS`、`workerFallbackParity=true`、`undoRedo=true`，`cities.executed=true`，退出码 `0`；局部城镇重生成、城镇 / 道路锁、22 入口锁矩阵与生产构建通过。
- 用户精确 Chrome 原标签页正式点击“重新生成城镇”成功：`949 -> 1218`，港口 `218 -> 252`，道路 `607 -> 341`；提交后健康事件为空、WebGL error `0`。Ctrl+Z 恢复 `949 / 218 / 607`，history `undo 0 / redo 1`；撤销只记录 100k 主线程约 `9.7s` 的性能告警，无应用、协议、owner 或回滚错误。
