# 国家合并、拆分与政治拓扑编辑产品规则冻结稿

本文档对应权威任务第 74 项。当前状态为 **规则、实现与同一 Chrome 交互验收均已完成**。本文冻结产品规则、数据不变量和最小验收边界；最终完成状态和顺序仍以 [`../current-plan.md`](../current-plan.md#权威任务清单) 为准。

## 当前入口与验收状态

- 国家面板提供两条紧凑闭环：合并固定配置来源，选择相邻目标国与幸存国；拆分固定来源国，多选完整旧省，选择新国首都并可覆盖默认名称。外部 selection 变化不重置配置来源。
- 两条路径都先调用纯只读预检，显示首都、旧 / 新省、军事 / 战争、市场 / 路线 / 备注和 stale 影响；输入变化立即使旧预检失效，只有当前预检有效时才允许显式确认。
- 稳定 API 新增 `edit.states.inspectMerge / merge / inspectSplit / split`。写入口必须传入 `confirm: true`；UI 与 API 共用 runtime action、`EditHistory` 和本文件冻结的同一拓扑命令，不存在独立分省按钮或 API。
- 成功结果的 `selectionTarget / redirects / topologyRefresh` 与 command effects 统一驱动 selection、高亮、编辑目标、面板列表、政治边界、国家 / 省份标签、picking 和派生显示；失败发生在 UI prepare 之前，地图事务回滚后不会留下 selection 或面板半态。
- 拓扑命令执行前 / 后的 selection、国家面板目标、editing object、持久高亮和来源国由应用层随命令记录；唯一通用 history 执行器只对 `domain=state-topology` 恢复对应快照，因此 API、快捷键和其它撤销 / 重做入口一致，普通领域不重复同步。动态专项已用真实 console API 覆盖合并、多省拆分、撤销 / 重做、失败不变与非法输入不进历史。
- 观察使已复用同一 Chrome 完成真实合并、含原首都省拆分、自动补都、非法全省拆走拒绝、确认提交、Ctrl+Z / Ctrl+Y、面板列表、省会和保存重载验收；连续两次健康窄重载无 console、FMG health、页面或 WebGL error，第 74 项已达到 Completed。

## 操作边界与共同事务规则

- 合并一次只处理两个有效国家，且两国必须存在共同陆地边界；不接受隔海接触、仅点接触、多国批量合并或已 tombstone 国家。
- 拆分选区必须由一个或多个完整旧省组成，不允许切开旧省。选区和来源国剩余领土都必须陆地连通，并且双方至少各有 `1` 个有效省和 `1` 个有效城市。
- 合并和拆分都必须先执行只读预检，再以一条命令、一个事务和一条历史记录提交。预检失败、实施中任一步失败或最终不变量校验失败时，不得留下国家、省份、城市、外交、军事、经济、路线、备注、selection 或派生状态的部分写入。
- 撤销必须恢复实施前完整语义和引用关系，重做必须复用首次成功结果，不重新随机生成名称、颜色、徽章、省份或军事 ID。

## 国家 ID 与档案生命周期

### 合并

- 用户必须显式选择幸存国；幸存国保留原国家 ID。
- 被并国写为 tombstone，保留原 ID 和档案槽位；国家数组、外交关系数组和其它按 ID 索引的集合不得 `splice`，不得压缩、重排或复用 ID。
- politics / pack 若共享数组或对象，保持共享别名；若是独立副本，分别同步但不得把它们合并为同一引用。

### 拆分

- 新国家 ID 只能在当前全局最大国家 ID 之后追加，不填补空洞，不复用 tombstone ID。
- 新国家档案同时写入 politics / pack 镜像，并遵守原地图共享或独立镜像语义。

## 名称、政体、颜色与徽章

### 合并

- 幸存国保留自己的名称、政府 / 政体、国家类型、扩张参数、颜色和徽章。
- 被并国的上述字段不覆盖幸存国，也不拼接成复合名称或混合样式。

### 拆分

- 新国家默认名称、颜色和徽章以地图 seed、新首都所在地文化、新国家 ID 为稳定输入确定性生成；同一地图、同一选择和同一输入必须得到相同预览与提交结果。
- 用户可以在提交前覆盖新国家名称；首期不提供政体、颜色或徽章继承向导。
- 新国家政府 / 政体、国家类型和扩张参数复制来源国；来源国自身保持不变。

## 首都与国家中心

### 合并

- 幸存国保留原首都；被并国原首都降为普通城市。
- 被并国原首都的旧省会身份只属于重新分省前的旧态；受影响国家自动重新分省后，所有省会身份按新省中心统一重设。

### 拆分

- 拆分预检必须显式指定新国家首都，且目标必须是拆分选区内的有效城市。
- 如果来源国原首都仍在剩余领土，来源国继续保留该首都。
- 如果来源国原首都被划入新国家，旧国从剩余有效城市中按以下稳定优先级自动择都：
  1. 当前仍属于旧国剩余领土的有效省会优先；
  2. 城市人口降序；
  3. 所在 cell 适居度降序；
  4. 港口城市优先；
  5. burg ID 升序；
  6. city ID 升序。
- 旧国没有候选城市时，拆分预检必须拒绝，不能留下无首都国家，也不能隐式把新首都划回旧国。
- 每个受影响国家都必须同步 `city / burg capital`、城市 group、`state.capital / capitalName / center / gridCenter / religion`；state 的 religion 取最终首都所在地宗教。国家 pole、统计和标签位置在同一事务内刷新。

## 文化与宗教

- 合并和拆分都不修改任何 cell、city 或 burg 的文化与宗教归属。
- 合并保留幸存国国家级文化与宗教值；被并国国家级值不覆盖幸存国。
- 拆分新国的国家级文化与宗教取新首都所在地。来源国若自动择都，同步其最终首都对应的国家级宗教；不得因此重生成文化或宗教版图。

## 外交、宗藩与战争

### 合并

- 幸存国对第三国的既有关系优先并保持；被并国的联盟、敌对、宗藩关系不转移、不覆盖幸存国关系。
- 被并国对应的关系索引槽位保留，不执行 `splice`；按 tombstone 语义清理活动引用，不把第三国索引整体左移。
- 所有涉及被并国的活动战争必须关闭，并向既有外交系统纪事写入结构化结束记录；不得把被并国战争自动继承给幸存国。

### 拆分

- 新国家与所有有效国家的初始关系均为 `Neutral`，不继承来源国联盟、敌对、宗藩或活动战争。
- 新国家初始无宗主、无附庸、无活动战争；外交关系数组按新 ID 追加索引，不压缩旧槽位。

## 军事继承与引用修复

- 本项不全量重新生成军事。
- 合并时，被并国军团转入幸存国；幸存国原军团保持归属。
- 拆分时，军团优先按当前 cell 所在最终领土归属；当前 cell 无法判定时，再按 base 所在最终领土归属。两者都无法判定时预检列入错误，不能猜测归属。
- 所有转移军团必须按稳定旧顺序和新 owner 确定性重编号，生成显式旧 ID → 新 ID 映射；同步修改军团 ID、战斗事件、对手引用和其它链式引用。不得留下旧 owner ID、悬空对手或重复军团 ID。
- 涉及被并国的活动战争按外交规则关闭；拆分新国不自动创建战线、战役或战争。

## 市场与经济

- 市场 ID、市场中心、覆盖 cell、交易、税务和其它既有经济数据保持，不因国家拓扑变化执行全量经济重算。
- 只按市场中心城市的最终国家同步 `market.state`，并保持 pack / economy 市场镜像一致。
- 经济标记为 stale，交由既有经济重算入口后续恢复；本事务不得静默重分市场、重建交易或重算税务。

## 路线

- 路线 ID、端点、几何、等级、视觉、备注和资源摘要身份保持，不因国家合并 / 拆分重新寻路。
- 同一事务内只刷新路线的国家 / 省份摘要、pack 路线镜像和 cell 路线索引；无关路线对象和几何逐字节不变。

## 备注、系统纪事与运行时引用

- 幸存国备注原样保留。
- 被并国备注继续挂在 tombstone 档案上，不拼接到幸存国正文；合并另向既有系统纪事写入记录。
- 拆分不复制来源国备注，新国家备注为空。
- 省份备注与徽章遵守后文的省份 tombstone 规则，不复制到新省。
- 合并成功后，指向被并国的 selection、持久高亮和编辑目标转向幸存国；拆分成功后 selection 指向新国家。撤销 / 重做必须恢复对应引用状态。

## 受影响国家自动重新分省

自动重新分省是合并 / 拆分事务的内部步骤，不是独立 UI 或 API：

- 合并的受影响国家只有幸存国；拆分的受影响国家只有来源旧国和新国。
- 受影响国家的全部旧省写为 tombstone；其它国家的省份对象、cells、城市字段、备注、徽章、数组槽位和用户数据必须逐字节不变。
- 对每个受影响国家，令有效城市数为 `C`，省份比例为 `R = clamp(provincesRatio ?? 20, 0, 100)`：
  - `C = 0`：整个国家操作拒绝；
  - `C = 1`：目标省数 `T = 1`；
  - `C >= 2`：`T = clamp(ceil(C × R / 100), 2, C)`。
- 国家首都是第一个省中心。其余中心按城市人口降序、所在 cell 适居度降序、burg ID 升序选择，直到达到 `T`。
- 重新分省前清除受影响国家城市 / burg 的旧 `provincial`；每个新省中心统一设为省会，并同步 city / burg 与 province 的中心引用。
- 省域只在所属国家最终陆地内从全部中心执行多源扩张；同成本时较小的新省 ID 胜出。结果必须覆盖该国全部陆地，并保证每个新省单连通且包含自身中心；任一条件失败则回滚整个国家操作。
- 新省 ID 从全部现存和 tombstone 省份的全局最大 ID 加 `1` 起连续追加，不复用空洞；任何新 ID 超过 `65535` 时预检拒绝。
- 旧省 tombstone 保留名称、可选字段、用户数据、备注和 coa，不被新省继承。
- 新省名称和颜色只作用于新省，复用既有命名 / 配色能力并在固定地图 seed、所属国家、新省 ID、中心城市和文化输入下确定性生成；新省备注为空、coa 为空。
- 新省的 `center / gridCenter / pole / burg / state`、统计、标签和 politics / pack 镜像在同一事务内同步。

## 统计、邻接与 stale 传播

- 同步受影响国家 / 省份 / 城市的数量、人口、面积、中心、pole、省会、首都、邻国和派生摘要；刷新标签、selection、picking、对象索引和导出读取的 politics / pack 镜像。
- 外交、宗藩、战争和军事 ID 映射属于结构性一致性修复，必须在事务内完成，不能只标 stale 后留下悬空引用。
- `economy / diplomacy / military / zones / state-markers` 标记 stale；本项不在事务内全量重生成这些系统。

## 预检最小输出

合并 / 拆分预检至少返回：

1. 操作类型、源国家、幸存国或新国家、最终国家 ID 与名称预览。
2. 邻接、选区完整旧省、选区 / 剩余领土连通性、双方省份和有效城市下限。
3. 首都保留、降级、指定或自动择都结果及完整排序证据。
4. 受影响旧省 tombstone、新省目标数、中心、预计 ID 范围和 `65535` 上限。
5. 城市、军团、市场、路线、战争、备注、selection / 高亮和 stale 系统影响摘要。
6. 任何拒绝原因、警告和受影响对象列表；非法预检不得修改地图或历史。

## 失败回滚、旧图与持久化兼容

- 一次操作只形成一条 `EditHistory`。失败注入必须覆盖国家写入、首都处理、重新分省、外交 / 战争、军事重编号、市场 / 路线摘要和最终一致性检查等阶段，并证明任一阶段失败均恢复事务前状态。
- 不新增完整地图必填字段。旧图缺少外交、军事、经济或备注域时按空域处理，不因缺少可选系统拒绝基本拓扑操作。
- 完整 JSON、gzip、浏览器缓存和旧导出文件继续走现有迁移 / ensure；pack / politics 为同一引用或独立副本都必须保持原别名语义。
- 撤销 / 重做、完整地图往返、对象解析、GeoJSON / 数据导出和旧 tombstone 样本必须保留 ID、镜像、备注、coa、战争关闭纪事和军事引用结果。

## 明确排除项

本项不实现：

- 任意 cell 手工拆省或切开旧省的国家拆分；
- 多国合并、链式合并或非邻接国家合并；
- 独立“按国家重算省份”的 UI / API；
- 名称、政体、外交、宗藩、经济、军事、备注或徽章继承向导；
- 全图省份、城市、路线、经济、外交或军事重生成；
- 路线重寻、边界平滑、飞地清理或其它拓扑美化扩展。

## 用户确认结果

用户已确认整体采用本文矩阵，包括：显式幸存国、追加 ID、被并档案 tombstone、拆分完整旧省与双侧连通下限、原首都划走后的确定性自动择都、受影响国家事务内自动重新分省、外交不继承、军事局部转移与重编号、市场 / 路线保留、备注不拼接、旧图兼容和上述排除边界。后续实施不得在没有新产品决定的情况下偏离本稿。
