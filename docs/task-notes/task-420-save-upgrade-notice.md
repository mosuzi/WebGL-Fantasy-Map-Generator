# 第 420 项：旧存档打开时的自动升级提示

## 范围

打开旧存档时告知玩家正在按现行结构整理，成功后通告完成；升级过程没有同意或取消。只处理本次打开的提示和来源判定，保留替换当前地图的确认及原始存档保护。

## 首败与复验记录

1. 浏览器存储兼容夹具首轮：历史同版存档缺失 burg 的断言观察到已修复地图，却未观察到升级提示。Node 对同版缺失 burg 及浏览器包装输入的窄探针均返回 `upgrade.needed=true`，说明迁移链可报告修复。检查读存储优先级发现：夹具先保存了当前二进制存档到 IndexedDB，再写入时间戳早于该记录的旧档 LocalStorage；读取入口选择了更新的 IndexedDB，导致“缺失 burg”场景实际未被打开。本次调整让该旧档和损坏档的 LocalStorage 时间戳晚于当前存储记录，预期浏览器会真实打开指定旧档并记录整理前 / 完成后的两个提示。下一次只复验浏览器存储兼容目标门。
2. 第二轮：旧版、当前版、文件与同版城镇回填的提示断言均通过；新加的旧文件场景在 `legacy-file-import` 计时窗口出现 `568 / 722ms` LongTask。该窗口从把大段夹具文本送入页面之前开始，混入测试专用文本传输和 File 构造，不能据此认定产品导入卡顿。本次从页面当前地图构造旧文件，准备完成后重置 LongTask 计时，仅覆盖正式导入入口；保留文件导入的提示断言与产品性能硬门。下一次只复验同一浏览器存储兼容目标门。
3. 第三轮：夹具准备与导入已分窗，正式旧 JSON 文件导入仍有 `694ms` LongTask；产品导入计时中的主线程 canonical 解码为 `682.1ms`，而 Worker 的解析与渲染已并行。这是原先将全部字节输入一律放到主线程并行解码导致的旧 JSON 路径卡顿。本次让普通 JSON 字节文件使用已有可分片 Worker canonical handoff，保留 WEBFMG3 及非 JSON 压缩字节的原并行路径；预期文件导入主线程 canonical 解码为 `0ms`、无超过 `200ms` LongTask，升级提示仍完整。下一次先重建应用，再只复验浏览器存储兼容目标门。

## 集成复核与补齐

独立复核发现同版 v2 的小型子存储内部字段缺失会被迁移补齐，却可能不显示整理提示。现对备注、测量、标签、显示单位、商品/市场、主题、外交、洋流、锁与地区已发行回填形态做轻量判定，并以只缺一个字段的 v2 夹具验证。第一次 blocker-only 复查另发现 `display` 已存在但 `units` 整体缺失的单字段漏报；已让该情形纳入判定，并增加专项断言。冻结 0.2.12 `.webfmg` 也经真实 Worker 验证升级来源和提前进度。

同一复查还指出：城镇 cell 镜像单点失配会在校验前被重建，却没有升级来源。现仅在地图导入提供回调时比较既有镜像与本次重建结果，发现真实差异才发出整理提示；补充只改一个 grid cell 镜像的旧 v2 夹具，防止正常重建误报。

浏览器 `.webfmg` 目标首轮失败：冻结 0.2.12 二进制夹具只有 3 个格点，缺少完整 polygon/compact surface 基础容器；它原本用于迁移与容器解码，不能证明可游玩地图的正式渲染。未修改这个历史夹具。另以当前已发行 WEBFMG3 容器编码器一次性生成并冻结 10,004 格、5,525 pack cells、731 城镇的完整 v2 地图，只删除旧时期曾缺失的 notes 存储，作为浏览器打开集成夹具；压缩文件 `tools/fixtures/webgl-map-v2-playable-legacy-notes.webfmg` 的 SHA-256 为 `e0418f77d6aff1b5bc5e93926542b69bf242d2ee03672c7d84c1aac87393ded3`。旧 0.2.12 文件继续在真实 Worker 中逐字节验旧容器，完整文件只用于验证浏览器渲染、提示和性能。本次目标复验只运行浏览器存储兼容门。

完整 `.webfmg` 浏览器首轮已成功打开，但连续打开旧档时，上一份地图的完成 toast 尚在，新一次开卷提示前被夹具观察到旧“完成”。这是两次操作的视觉反馈交叠。本次在 Worker 识别新旧档升级时收起上一条 toast，让本次进度与完成通告形成单一序列；重建后仅复验浏览器目标门。

第二轮同一提示序列仍先记录旧“完成”：`runMapReplace` 的加载快照会先让出浏览器一帧，测试刚清空事件数组时旧 toast 仍可见，故观察器把上一轮反馈重新记入本轮。产品导入入口已在实际执行前收起旧 toast；本次夹具在开始二进制导入前等上一轮 toast 自然消失，再重置观察窗口，核对本次操作自己的提示顺序。下一次仍只复验浏览器存储兼容目标门。

最终独立验收首轮发现同版 v2 的湖泊溢流、河网、地区类型、洋流细项和地图名称会被归一补齐，却未进入整理提示。原因是预检只列出部分旧字段，实际归一链的结果未统一反馈给提示判定。本次在各归一结果形成时比较对应的小型语义字段：地图名称、洋流模型、河网关系与诊断、湖泊溢流、地区类型与上下文，保留原有快速预检以提前通告已知旧档。预期只删任一字段的完整 v2 存档均得到一次提示，完整当前存档仍无误报；先做 Node 单字段窄复验，再做正式浏览器当前档与旧档目标复验。

最终验收第二轮：前述八个单字段探针通过后，验收者发现外交关系计数、pack 外交镜像、单个国家关系及旧式 document 显示设置会被迁移恢复，但未报告整理。此前只比较新 map 的部分归一结果，外交归一发生在后续步骤，显示设置也没有进入比较。本次在外交归一前后比较外交文档与两个国家镜像，并比较显示设置的归一前后结果；新增四个单字段探针。预期四项均仅报告一次整理，完整当前版仍无误报，随后只做迁移专项与正式浏览器目标复验。

本轮迁移专项首败：升级后再保存打开的当前档被误报。最窄诊断定位到外交统计的 `pairs` 在空国家数组下由 `0` 算出 `-0`；序列化二者完全相同，原比较器用 `Object.is` 视为不同。本次把数值 `0` 与 `-0` 视为相同，同时保留 `NaN` 的同值判定；预期当前档不再误报，四个外交 / 显示探针仍能识别真实缺字段。只重跑迁移专项。

第二次窄复验首败：原“完整商品展示字段”夹具把 `map.pack` 整体替换为只有商品与市场的对象，顺带删除了原有外交镜像，故新判定正确报告需要整理。此夹具测试的是商品字段，应保留原 `pack` 的其余资料；本次只在既有 `pack` 上添商品与市场，预期完整商品夹具无误报，单字段商品缺失仍报告。只重跑迁移专项。

第三次窄复验同一断言仍失败：检查发现该极小当前档原本完全没有 `pack`，在其上增加商品会首次创造 `pack`，而外交归一随之补建 `pack.diplomacy`；仅展开原值并无可保留的镜像。实际商品单字段夹具应先走一次正式保存形成完整当前基线，再从该基线删商品字段。本次按此改夹具，预期基线不提示、单字段缺失提示。只重跑迁移专项。

最终验收第三组只读探针指出地图选项、河流镜像、锁条目和既存 burg 的身份字段也有静默补齐。前两者由当前 schema 归一写回，锁被去重或编号化，burg 在 cell 一致化阶段被重写；此前只识别缺失整条 burg 和 cell 镜像。本次比较归一前后的选项、河流镜像与锁仓，并在 burg 既存记录的修复写回前报告真实差异；补入对应单字段夹具。预期这些旧档都出现一次整理提示，当前档保持无提示，先只重跑迁移专项。

## 本地验收证据

- `regress:map-migration`：冻结 v1、历史 v2、0.2.12 二进制及完整可游玩旧 `.webfmg` 均通过；另以完整当前档为基线，逐项删除湖泊、河网、地区、洋流、地图名、外交、选项、镜像、锁与既存城镇字段共 `22` 个单字段反例，均只报告一次整理。备注、显示单位、商品 / 市场、缺整条 burg 与 cell 镜像专项也通过；当前版回读无误报，原始资料与历史字节保持。
- `regress:map-file-io-worker`：真实 Worker 对冻结 0.2.12 `.webfmg` 给出 `upgrade.needed=true` 与提前的 `upgrade` 进度；普通 JSON、压缩包装和 100k 数据路径通过。`regress:settlement-route-identity` 与 `typecheck:core` 通过。
- `regress:browser-storage-compatibility`：正式 Chrome 的旧浏览器缓存、缺失 burg 同版档、旧 JSON 文件和完整旧结构 `.webfmg` 均记录 `opening→completed`，没有升级确认；当前版恢复与损坏档均无升级通告。10,004 格二进制地图完整打开，原浏览器记录成功 / 失败均保持；有效导入的 console / page 错误为 `0`，损坏档的预期 health 诊断保留，目标 LongTask 最高 `82ms`，超过 `200ms` 为 `0`。普通 JSON File 不再主线程完整解码，`canonicalDecodeMs=0`。
- `build:app`、`check:ui-layout`（709 状态、问题 0）、`audit:ui-copy`、`regress:map-storage-user-copy` 与 Impeccable 检测（结果 `[]`）通过。视觉检查保留既有地图浮层样式，整理文案不泄露内部术语。
