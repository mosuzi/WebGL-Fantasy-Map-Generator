# 重生成对象锁定体系

## 状态

- 对应权威任务：第 205 项。
- 来源：用户直接要求。
- 当前阶段：阶段 A 已完成；阶段 B～F 待实施。
- 阶段 A 基线：`regenerationLocks v1`、单项 / 批量 / 按领域清空命令、删除清理与撤销恢复、旧图回填、六个公开 API、三类新增通用对象引用均已落地。机器矩阵为 `14` 个列表页、`15` 类行和 `22` 个重生成入口，双向差集为 `0`。

## 目标

为所有具有稳定列表行、且会被“重新生成 / 重新扩张 / 重算”替换或改写的地图对象提供“重生成锁定”：

1. 每一行显示锁定 / 未锁定图标，可直接切换。
2. 列表支持批量选择后统一锁定或解锁。
3. 当前列表可以进入地图多选模式，点击地图累积同类对象，再统一锁定或解锁。
4. 直接重生成、局部重生成和复合世界重建都必须保护对应锁定对象。
5. 锁定状态写入地图存档，旧浏览器缓存、旧 JSON、旧 gzip 存档缺少该字段时自动回填为空。

这里的“锁定”只表示“禁止重生成器改写对象”，不是通用只读权限。显式重命名、移动、编辑和删除仍按各自既有规则执行；删除对象时必须同时清除其锁定记录。

## 当前源码分母

### 纳入的列表页与对象类型

当前实现必须以 `14` 个列表页、`15` 类可锁定行作为封闭分母：

| 列表页 | 锁定对象类型 | 会改写它的入口 | 锁定时必须保持 |
|---|---|---|---|
| 国家 | `state` | 国家重生成、完整世界重建 | ID、名称、政体、首都、领土 cell、政治镜像 |
| 省份 | `province` | 国家 / 省份重生成、完整世界重建 | ID、名称、所属国家、省会、领土 cell、政治镜像 |
| 城镇 | `city` | 城镇重生成、完整世界重建 | ID、名称、位置、归属、港口 / 首都 / 省会身份、视觉与镜像 |
| 道路 | `route` | 道路、国家、省份、城镇、河流及完整世界重建 | ID、类型、端点、路径、名称、视觉与备注 |
| 河流 | `river` | 河流、气候 / 高度 / 海底及完整世界重建 | ID、名称、水文属性、路径、河口、视觉与备注 |
| 资源点 | `marker` | 资源点、气候 / 高度 / 海底及完整世界重建 | ID、资源语义、位置、视觉、备注和手工属性 |
| 外交 | `diplomacy-relation` | 外交、国家及完整世界重建 | 规范化国家对、关系、战争 / 贸易摘要和引用 |
| 宗教 | `religion` | 全量宗教重生成、单宗教重新扩张、完整世界重建 | ID、名称、中心、参数、覆盖 cell、社会镜像 |
| 文化 | `culture` | 单文化重新扩张及会重新扩张文化的复合链 | ID、名称、中心、参数、覆盖 cell、社会镜像 |
| 军事 | `military` | 军事、国家 / 外交及完整世界重建 | 军团 ID、所属国家、驻地、编成、兵力、态势和相关摘要 |
| 地区 | `zone` | 地区及完整世界重建 | ID、名称、类型、覆盖 cell、视觉与摘要 |
| 地貌单元 | `feature` | Feature / 岸线、高度 / 海底及完整世界重建 | ID、陆水类型、分组、成员 cell、岸线 / 港湾关系和统计 |
| 洋流 | `ocean-current` | 洋流重算、气候世界重算、海底重设 | ID、名称、路径、海盆、冷暖性、强度和环流属性 |
| 经济 | `economy-market` | 经济链重算、市场归属应用、资源 / 世界重建 | 市场 ID、归属 cell、整行供需 / 库存 / 价格 / 展示数据 |
| 经济 | `trade-flow` | 经济链重算、市场归属应用、资源 / 世界重建 | 交易 ID、买卖双方、商品、数量、价格、路径和摘要 |

经济面板中的商品定义不会被 `rebuildEconomyFromMarketAssignments` 替换，只作为重算输入，因此 `good` 不进入首期锁定分母。若以后新增“重新生成商品目录”，必须先把 `good` 加入本表和机器分母，再实施入口。

### 明确排除

以下内容不属于本专题的列表行锁定：

- 高度、气候、生物群系和人口面板中的聚合统计行：它们不是具有独立生命周期的对象记录。
- 名称库样例预览、导出预览和运行时统计：它们不写入地图对象集合。
- 完整新地图生成、完整地图导入和 GEO 地图替换：这些操作会替换地图身份；锁定仓随新地图或导入文件一起替换，而不是跨地图强行继承。
- 手工重命名、移动、改色、修改参数和显式删除：锁定不升级为通用编辑权限。
- 标签位置锁定、marker `pinned`、视觉 `manual` 等既有字段：它们语义不同，不得复用或覆盖。

### Source 行为参考

参考实现已经在城镇、文化、资源标记、省份、宗教、道路和国家等路径使用“只重生成未锁定对象”的交互，并为城镇、道路、marker 提供单项或全量锁定入口。这证明“锁定只保护重生成、并不禁止普通编辑”是可理解的产品语义。

正式应用不能直接搬用 source 的分散布尔字段和各自生成后过滤方式。本专题以当前独立 WebGL 应用的 14 个列表页、事务历史、对象引用、复合世界重建和旧存档链为准，采用统一版本化锁仓与生成前约束。

## 入口闭包

锁定不能只接入面板上的按钮。实现时必须从当前源码生成并核对以下入口闭包：

1. `generate.regenerate` 的 `11` 类受约束重生成：`features / routes / rivers / cities / states / provinces / markers / diplomacy / religions / military / zones`。
2. `oceanCurrents.regenerate`、`oceanCurrents.rebuildWorld` 和海底重设链。
3. 气候下游重算、高度 `base / downstream / all` 重建。
4. 文化与宗教 `applyExpansion({mode: "reexpand"})`。
5. 经济链重算与市场归属应用。
6. 国家、省份、城镇、河流等重生成内部继续调用的下游生成器。

复合入口必须按实际改写的领域逐层消费锁定。例如国家重生成同时重建省份与道路时，不仅保护锁定国家，也必须保护锁定省份和锁定道路。任何新重生成入口若未登记其读写领域，静态门禁必须失败。

## 持久化数据契约

### 独立版本化仓

在地图根对象新增独立子仓，不向每类对象散布同名字段：

```js
regenerationLocks: {
  version: 1,
  entries: [
    {kind: "state", id: 2},
    {kind: "diplomacy-relation", id: "2:7"}
  ]
}
```

约束如下：

- `kind + id` 是唯一键；外交关系使用规范化国家对，普通对象继续使用其稳定 ID。
- `entries` 在序列化前按 `kind`、规范化 ID 排序并去重，保证 checksum 和存档差异稳定。
- 仓内只保存身份，不复制对象快照。重生成事务开始时按锁定身份从当前地图捕获快照。
- 不复用标签 `locked`、marker `pinned / lock` 或视觉 `manual`，避免语义串扰。
- 旧图缺失、字段损坏或引用已删除对象时，兼容层回填空仓并报告被清理的孤儿记录；不得阻止旧图加载。
- 浏览器缓存、完整 JSON、gzip、撤销 / 重做和导入后再导出必须共用同一 normalize / validate 路径。

### 历史与 revision

- 单行切换锁定是一条编辑命令；批量锁定 / 解锁无论对象多少都只形成一条历史。
- 成功切换令地图 revision 恰好 `+1`；no-op、取消和校验失败不进入历史、不递增 revision。
- 锁定不需要危险确认；批量目标包含非法或不可锁定对象时整批原子拒绝。
- 删除对象的原命令负责同步移除锁记录，撤销删除时同时恢复锁记录。

## 重生成保护契约

锁定的含义是“同一重生成事务前后，该对象的受保护快照不变”，不是“生成后把名字抄回去”。

每条重生成链统一执行：

1. 解析本次会改写的领域与范围。
2. 捕获范围内锁定对象、其成员 cell、镜像和直接引用快照。
3. 把锁定对象作为生成约束传入领域生成器；为锁定 ID 预留身份空间。
4. 只在剩余空间生成未锁定对象。
5. 校验锁定快照、对象引用、cell 归属和领域不变量。
6. 成功后沿用第 202 项单事务 / 单历史提交；任一步失败则整图回滚。

禁止采用“完整生成后无条件覆盖旧对象”的通用补丁，因为这会制造 ID 冲突、悬空 cell、重复首都、断裂道路或无效经济引用。

### 冲突策略

- 锁定对象与当前地形、作用范围或其它锁定对象冲突时，不得静默解锁、缩小领土或移动对象。
- 整个重生成事务以稳定业务 code `regeneration_lock_conflict` 拒绝，并返回冲突对象、领域、原因和可选修复建议。
- 锁定对象不在本次局部重生成范围内时只计入“范围外保留”，不重复写入。
- 某领域全部有效对象均已锁定时，重生成返回成功 no-op 摘要，不增加地图历史；重生成扰动序号也不前进。
- 复合链在下游遇到冲突时必须恢复上游已完成步骤，保持第 202 项的完整事务边界。

## 列表与地图多选

### 共享表格能力

扩展 `UiObjectTable` 的可选锁定列，不在 14 个面板中复制按钮实现：

- 可选属性：是否显示锁定列、锁定 ID 集、锁定状态解析器。
- 事件：单行锁定切换、带修饰键的行批量选择。
- 行尾使用 Element Plus 的锁定 / 解锁图标；图标按钮必须具有“锁定以防重新生成 / 解除重生成锁定”的 `title` 与 `aria-label`。
- 普通模式下单击行继续作为主选中，不破坏定位、双击编辑和详情联动。
- 进入“批量锁定选择”模式后，单击行切换批量集合；复选框始终可直接加入 / 移除，`Shift` 支持当前排序和筛选结果中的连续范围。

### 同一批量集合

列表多选和地图多选必须写入同一个面板会话集合：

- 工具栏显示“已选 N 项”，提供“锁定选中”“解锁选中”“清空选择”和“在地图多选”。
- 地图多选使用一个共享注册画布模式，以当前面板提供的对象类型和 pick 适配器为上下文，不为每个领域复制模式 ID。
- 普通点击切换对象，`Shift / Ctrl / Meta` 追加或移除；不支持地图 picking 的对象必须在实施阶段补齐适配器，不能退化为只支持列表。
- 选择过程只改变会话集合和临时高亮，不修改地图，也不进入历史；点击应用后才提交一条批量锁定命令。
- `Esc`、关闭面板、切换地图或切换到其它画布模式时取消地图多选并清理临时高亮，不提交锁定变化。
- 100k 地图下使用现有 picking / 对象索引和受限高亮，不在 pointermove 中扫描全表。

Feature、洋流和经济市场当前不在通用持久对象高亮分母中；实施本专题时必须补齐统一对象引用与 picking / 高亮适配，不能因此从地图多选验收中排除。

## 公开 API

锁定体系继续遵守第 195、200 项的 AI 友好约束：

- 读取：列出某领域锁定项、读取单对象锁定状态、分页查询带 `regenerationLocked` 投影。
- 预检：校验对象引用、领域支持、重复项、孤儿项、预计变化数和当前 revision。
- 写入：单对象设置、批量设置、按领域清空；全部参数化并与 UI 共用同一命令。
- 结果：返回 `changed / unchanged / rejected`、规范化对象引用、历史摘要和 map revision。
- 业务 code 至少覆盖 `unsupported_lock_kind / object_not_found / lock_batch_empty / lock_batch_invalid / regeneration_lock_conflict / inspection_stale`。
- 所有新增方法进入 `API_METHODS`、方法元数据、`info.describe`、schema registry、稳定性与能力矩阵；不开放裸 map 或任意属性写入口。

公开引用优先复用现有 `OBJECT_KIND` 与 object resolver。Feature、洋流和市场若需要新增对象类型，必须同步对象发现、定位、字段投影、JSON 序列化和 API 聚合分母，不能建立只供锁定功能使用的第二套私有身份系统。

## 最小验收总表

1. 14 个列表页、15 类可锁定行和所有重生成入口的机器分母双向差集为 `0`。
2. 每行锁图标、列表点击 / 复选框多选、地图多选和批量锁 / 解锁均可用且键盘可达。
3. 任一重生成入口都不会改写它实际涉及领域中的锁定对象。
4. 冲突时整笔拒绝并回滚，不静默解锁，不留下半生成数据。
5. 锁定变化可撤销 / 重做，批量只产生一条历史，revision 语义稳定。
6. 旧浏览器缓存、旧 JSON、旧 gzip 缺少锁仓时可加载、回填、保存和再次读取。
7. UI 与公开 API 共用同一锁仓、预检、命令和稳定业务 code。
8. 原版 `source/` 只作行为参考，不修改其代码；正式实现全部位于独立 WebGL 应用。
