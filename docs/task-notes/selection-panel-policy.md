# Selection 面板分发策略

本文档记录权威任务第 37 项采用的方案 B：选择对象时只更新已经打开的领域面板；对应领域面板关闭时，统一显示对象详情。selection handler 不负责打开领域面板，用户仍可通过菜单、快捷键或面板内显式动作打开领域面板。

## 统一规则

| 对象类型 | 领域面板 | 领域面板已打开 | 领域面板已关闭 |
|---|---|---|---|
| 国家 | 国家管理 | 更新已打开面板 | 对象详情 |
| 城市 | 城市管理 | 更新已打开面板 | 对象详情 |
| 省份 | 省份管理 | 更新已打开面板 | 对象详情 |
| 文化 | 文化管理 | 更新已打开面板 | 对象详情 |
| 宗教 | 宗教管理 | 更新已打开面板 | 对象详情 |
| 河流 | 河流管理 | 更新已打开面板 | 对象详情 |
| 湖泊 | 湖泊管理 | 更新已打开面板 | 对象详情 |
| 地区 | 地区管理 | 更新已打开面板 | 对象详情 |
| 路线 | 路线管理 | 更新已打开面板 | 对象详情 |
| 贸易流 | 经济管理 | 更新已打开面板 | 对象详情 |
| 外交关系 | 外交管理 | 更新已打开面板 | 对象详情 |
| 标记 | 标记管理 | 更新已打开面板 | 对象详情 |
| 标签 | 标签命名管理 | 更新已打开面板 | 对象详情 |
| 测量对象 | 测量管理 | 更新已打开面板 | 对象详情 |
| 军团 | 军事管理 | 更新已打开面板 | 对象详情 |
| 区域 | 无独立领域面板 | 对象详情 | 对象详情 |

地图拾取、非领域列表选择、API `select / locate` 和编辑后的 selection 刷新都使用同一条规则，不再根据政治着色模式自动打开省份、文化或宗教面板。显式“打开国家”等菜单动作继续使用原有 `openSelectionAwarePanelForState()`，不属于 selection 自动分发。

## 例外

1. 选择来自同一个领域面板时，`sourcePanelId` 证明该面板已经处理本次行选择；分发器只清理可能残留的对象详情，不重复更新或打开面板。政体面板作为国家选择的等价来源面板。
2. 外交着色主题下选择国家继续切换外交主体。这是当前地图主题的直接交互，不打开国家管理面板。
3. 用户主动关闭河流面板产生的单次抑制标记继续生效，关闭动作不会被同一轮 selection 通知反向恢复成其它面板。
4. 二级编辑期间仍由既有编辑交互锁和 `SelectionStore` 维护编辑对象；统一分发器不调用任何领域面板 `open()`，因此不会用选择通知把焦点切换到另一个领域面板。
5. 对象详情现在允许国家、城市和河流作为兜底对象，不再因旧的强制领域面板策略主动拒绝这三类对象。

## 实现与回归

- `selection-panel-policy.js` 保存对象类型与领域面板绑定，并通过纯函数返回来源面板、更新已打开面板或对象详情三种结果。
- `app.js` 的全部 selection handler 复用同一个路由 helper；handler 段内禁止调用领域面板 `open()`。
- `pnpm run regress:selection-panel-policy` 覆盖 15 类绑定、区域兜底、来源面板、政体等价来源、外交主题、河流关闭抑制、`sourcePanelId` 和定位来源语义。
- 本项按快速迭代约定只要求纯代码回归、相邻门禁和生产构建，不把未执行的浏览器操作表述为真实 UI 验收。
