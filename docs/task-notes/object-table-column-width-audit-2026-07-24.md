# 对象列表默认列宽审计

> 状态：权威任务第 197 项已完成。审计分母固定为当前 24 个 Vue 宿主中的 27 张 `UiObjectTable` 实例；本文只判断默认宽度是否合理，不改变用户拖拽列宽的能力。

## 一、审计口径

按内容职责把列分为六类：

| 类型 | 建议默认范围 | 说明 |
|---|---:|---|
| 选择 / ID | `34～64px` | checkbox、短整数 ID |
| 短枚举 | `60～96px` | 类型、状态、政体、纹理等短分类 |
| 数值 | `60～102px` | 数量、面积、人口、距离、价格等 |
| 普通名称 | `104～150px` | 国家、城市、省份、对象名称 |
| 长文本 | `120～240px` | 摘要、涉及国家、来源—去向组合 |
| 定位动作 | `48px` | 共享固定列，不参与业务列调整 |

判断同时考虑：

- 中文内容常见长度，而不是只按表头字数。
- 面板默认宽度和表格是否本来就允许横向滚动。
- 同一语义在不同面板中是否使用一致默认值。
- 用户是否仍可通过既有拖拽调整覆盖默认值。

## 二、全量结论

### 2.1 保持现状的类型

- ID / 选择：当前 `34～64px`，合理。
- 短枚举：当前 `60～96px`，政体、类型、状态、纹理等均与内容长度匹配。
- 数值：当前 `60～102px`，面积、人口、距离、价格和统计值已有单位余量。
- 普通名称：当前 `104～150px`，国家、城市、省份、文化、宗教、路线端点等需要保留 4～8 个中文字符。
- 长文本：备注摘要 `240px`、地区涉及国家 `130px`、外交文化 `120px` 等属于有意保留的阅读空间，不应因首都列问题一并压缩。
- 定位列：共享固定 `48px`，与图标按钮和 sticky 行为匹配。
- 洋流管理：新增的一张表使用共享组件推导出的名称 / 性质 / 位置 / 强度宽度，在 `500px` 面板内与选择、定位列共同适配，不需要单独扩宽或压缩。

### 2.2 需要调整的同语义列

仅发现 `capitalName` 明显沿用了普通名称宽度：

| 面板 / 表格 | 旧默认 | 新默认 | 理由 |
|---|---:|---:|---|
| 国家编辑 / 国家列表 | `112px` | `80px` | 首都通常为 2～4 个中文字符，112px 持续浪费横向空间 |
| 政体管理 / 当前政体国家列表 | `112px` | `80px` | 与国家编辑保持同一语义和宽度 |

`80px` 可以容纳 4 个 12px 中文字符、单元格内边距及省略号余量；更长的特殊首都名称仍可由现有省略显示与列宽拖拽处理。

## 三、偏好迁移

旧列表偏好可能已经把当时的全部默认宽度写进 localStorage，因此只修改源码默认值不能保证用户看到新宽度。

本项采用带版本的一次性、逐列迁移：

- 仅把旧值恰好为 `112px` 的 `capitalName` 迁移为 `80px`。
- 其它自定义值原样保留。
- 迁移后记录列宽版本；用户之后即使主动拖回 `112px`，也不会再次被覆盖。
- 国家编辑与政体管理分别维护自己的表格 key，互不污染。

## 四、不在本项调整的内容

- 不统一缩小所有名称列。
- 不取消横向滚动。
- 不改变 32～640px 的手动拖拽范围。
- 不重置筛选、排序、tab、家族筛选或其它列表偏好。
- 不修改表格数据、排序、定位、选择、高亮或导出逻辑。

## 五、完成验证

- 静态专项回归动态扫描 24 个宿主、27 张表，确认两处首都列默认值均为 `80px`。
- 偏好回归确认旧默认 `112px -> 80px`，自定义 `148px` 保持，完成迁移后主动改回 `112px` 仍保持。
- 真实 Chrome 中国家编辑表格的首都表头为 `80px`，表格总滚动宽度由 `738px` 降为 `706px`，其余列宽不变。
- 生产构建通过，仅保留既有大 chunk 警告；`git diff --check` 通过。
