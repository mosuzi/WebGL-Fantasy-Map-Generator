# 保存到夸克网盘可行性调研

本文是权威任务第 70 项的正式调研报告。官方公开证据核验日期为 **2026-07-16**；活动状态仍以 [`../current-plan.md`](../current-plan.md#权威任务清单) 为准。

## 结论摘要

三选一结论固定为：**当前不建议集成。**

截至核验日，第一方公开页面能够证明夸克网盘面向用户提供网页上传、客户端上传、存储、同步、分享和客户端目录备份，也能够证明夸克扫描王另有面向开发者的文档 AI 开放平台；但没有发现面向普通第三方 Web 应用的夸克网盘上传 OpenAPI、OAuth 授权、CORS、文件管理或商业接入契约。这一结论表示“公开证据空白”，不表示官方绝无相关能力。

当前唯一可以直接交付的路线是：继续导出本地文件，由用户通过夸克官网或官方客户端上传。用户也可以主动把文件保存到已经由夸克客户端监控的本地备份目录，但应用只能确认本地保存，不能确认云端同步完成，更不能把它描述为“已保存到夸克网盘”。完整地图 JSON、gzip JSON、PNG 和 GeoJSON 均为普通文件，可以复用上述路径。

本次不制作 PoC，不登录夸克账号，不调用网页私有接口，不处理 Cookie、token 或扫码登录，也不创建真正的集成任务或修改应用。

## 公开证据空白

截至核验日，没有在上述第一方公开页面中发现面向普通第三方 Web 应用的以下夸克网盘契约。以下项目应统一标记为“公开证据空白”或“未知”，不得写成“官方绝无”：

- 个人或企业开发者申请条件、审核材料、费用、调用配额与生产开通流程；
- OAuth 2.0、授权码、PKCE、scope、refresh token 与 revoke；
- 上传 endpoint、文件 / 文件夹 API、目录选择、目录创建或目录 ID；
- 浏览器 CORS 白名单与预检规则；
- 同名冲突、覆盖、自动重命名和版本规则；
- 分片、断点续传、并发、校验和、幂等、取消与重试；
- 上传完成回调、webhook、回调签名和最终一致性；
- 文件撤销、回收站、永久删除和删除确认；
- 网盘 API 错误码、限流、沙箱、监控和 SLA；
- 普通第三方地图应用的商业使用、品牌展示和数据处理许可。

消费端 6TB、100G、会员容量与大文件权益不能补足这些空白；扫描王 API Key、5MB 输入限制、套餐和错误码也不能作为网盘 API 契约。

## 四条路线评估与数据流

### 纯浏览器直传

判定：**当前不可实现，也不应制作 PoC。**

理想数据流：

```text
用户浏览器
  -> 夸克官方 OAuth / PKCE 授权
  -> 浏览器获得最小上传 scope
  -> 浏览器直接上传到官方 endpoint
  -> 返回文件 ID、目录和校验结果
```

当前缺少 OAuth、scope、上传 endpoint、CORS、目录和错误处理契约。不得以网页 Cookie、抓取私有请求、扫码登录自动化或要求用户粘贴 token 的方式替代官方授权。

### 项目后端代理

判定：**只有取得正式合作和官方服务端契约后才可能；当前不能实现。**

理想数据流：

```text
浏览器生成导出文件
  -> 项目后端接收文件或上传会话
  -> 官方授权码换取并安全托管 token
  -> 后端按官方分片协议上传
  -> 官方返回文件 ID
  -> 前端显示可验证结果
```

增加后端不能自动解决授权合法性。服务协议明确禁止未经书面同意代理认证凭据；在正式许可之外保存 token、代用户自动登录或代理认证均不可接受。即使未来获批，后端还必须承担 token 加密、用户映射、撤回、删除、审计、限流、隐私告知和运营责任。

### 官方客户端同步目录

判定：**可作为用户辅助降级路线，但不是应用内云直传。**

可证数据流：

```text
用户在夸克客户端主动选择自动备份目录
  -> FMG 通过浏览器下载或文件保存器把文件保存到该本地目录
  -> 官方客户端检测目录变化
  -> 官方客户端自行上传到网盘
```

边界：

- 浏览器必须由用户主动选择保存位置，不能静默写入任意目录；
- FMG 不持有网盘凭据，也不控制官方客户端；
- FMG 无法可靠确认客户端是否安装、登录、暂停、离线或上传成功；
- UI 只能报告“已保存到本地备份目录”，不能报告“已保存到夸克网盘”；
- JSON、gzip JSON、PNG 和 GeoJSON 都是普通文件，可复用同一路径。

### 本地导出后由用户上传

判定：**当前唯一完全可交付、证据充分且风险最低的路线。**

```text
FMG 导出 JSON / gzip JSON / PNG / GeoJSON
  -> 浏览器下载本地文件
  -> 用户打开夸克官网或官方客户端
  -> 用户选择文件或文件夹上传
```

这条路线不新增凭据、后端或供应商耦合，四类导出可以直接复用。产品文字必须明确为“下载后上传”或“导出后在夸克上传”，不得包装为“一键保存到夸克网盘”。

## 最终判定

**当前不建议集成。**

理由如下：

- 未取得公开的夸克网盘上传 OpenAPI、OAuth 与浏览器 CORS 契约；
- 未确认普通第三方或商业地图应用的申请资格与使用许可；
- 协议禁止未经书面同意获取用户身份凭据、代用户自动登录或代理认证凭据；
- 目录、分片、冲突、回调、删除、错误码、配额和 SLA 等实现必需项均属于公开证据空白。

当前应保留标准本地导出，并在需要时向用户说明两种安全路线：手工通过官网 / 客户端上传，或主动保存到用户自己已经启用的官方客户端备份目录。若未来收到官方书面确认与完整开发契约，再另立权威任务，将路线重新评估为“需要后端或正式合作”。

## 安全、合规与产品风险

- **认证风险**：无 OAuth 时，任何 Cookie、网页 token、扫码登录自动化或私有请求复用均越过安全门禁。
- **协议风险**：未经书面同意不得代理认证凭据；消费会员许可不能替代开发者或商业合作许可。
- **隐私风险**：地图可能包含用户命名、备注和自定义文本；上传会引入新的数据处理、告知、删除和日志脱敏责任。
- **内容风险**：用户对上传内容的合法性负责，项目不能因增加云入口而弱化提示。
- **浏览器风险**：没有 CORS 契约时，纯前端可能在预检阶段失败。
- **大文件风险**：高 cells 地图和 PNG 可能需要分片；单文件、分片和并发规则未知。
- **一致性风险**：同名覆盖、重复上传、取消、断点、幂等与最终文件 ID 语义未知。
- **删除风险**：用户 UI 删除、个人信息删除、回收站和 API 永久删除是不同语义。
- **可观测性风险**：客户端同步结果对 FMG 不可观测，不能把本地保存成功当作云上传成功。
- **供应商锁定风险**：未来导出层仍应输出通用 blob，不把地图 schema 或导出格式绑定到夸克专有结构。
- **权益漂移风险**：消费端容量、100G 传输和会员权益会调整，不能作为程序常量或服务承诺。

## 失败降级

- 云端能力不可用或授权失败时，始终保留本地导出，不删除临时结果，也不覆盖用户已有文件；
- 客户端同步路线只报告本地保存结果，并提示用户到官方客户端确认上传；
- 未取得官方授权时，不显示“一键保存到夸克网盘”，只保留“导出后在夸克上传”的说明；
- 所有失败提示都不得要求用户提供 Cookie、token 或执行扫码登录自动化；
- 不把网盘不可用解释为地图导出失败，JSON、gzip JSON、PNG 和 GeoJSON 继续独立可用。

## 若未来获批的改动面

以下只是影响面估算，不是当前任务或实施承诺：

- **前端**：导出面板的云保存入口、授权状态、进度、取消、重试、目录选择与同名策略；
- **导出层**：继续复用现有 JSON、gzip JSON、PNG、GeoJSON blob 生成，不修改地图 schema；
- **后端**：OAuth callback、token 加密、刷新 / 撤回、用户映射、分片上传、幂等、审计和限流；
- **安全与文档**：隐私告知、授权 scope、删除政策、日志脱敏、数据处理协议和供应商降级；
- **测试**：授权、上传、冲突、断点、取消、配额、限流、撤回与删除专项。

## 正式合作前必须书面确认的 12 个问题

1. 是否接受个人开发者，还是仅接受企业或签约合作方？
2. 应用审核材料、费用、调用配额和生产开通流程是什么？
3. 是否提供 OAuth 2.0 授权码与 PKCE？scope、refresh 和 revoke 如何定义？
4. 是否允许纯浏览器调用？生产 CORS 白名单如何申请？
5. 文件夹创建 / 选择、同名、覆盖和自动重命名分别如何处理？
6. 单文件与账号上限、分片大小、并发、断点、校验和、幂等键是什么？
7. 是否提供 webhook？失败重试、回调签名和最终一致性如何保证？
8. 删除是进入回收站还是永久删除？如何确认清理成功？
9. 错误码、限流、沙箱、SLA 和技术支持渠道是什么？
10. 地图 JSON、gzip JSON、PNG 和 GeoJSON 是否均允许上传？
11. 第三方应用品牌展示、隐私政策、数据处理协议、日志留存和跨境边界是什么？
12. 后端是否可以持有加密 refresh token？撤回授权后多久必须删除？

## 若未来获批的最小验收草案

只有在官方书面许可、完整开发文档和测试环境齐备后，才可另立权威任务并执行以下草案：

- 使用脱敏测试账号完成官方授权码与 PKCE；
- scope 只包含所需目录及上传 / 删除权限；
- 上传一份不含真实用户信息的小型地图 JSON；
- 验证目录、同名冲突、返回文件 ID 和下载校验；
- 验证取消、网络中断重试、配额和限流错误；
- 使用官方分片流程验证较大 PNG；
- 使用同一通用 blob 路径验证 GeoJSON 和 gzip JSON；
- 撤回授权后确认 token 失效；
- 删除测试文件并确认回收站或永久删除语义；
- 确认 Cookie、token 和密钥不进入地图 JSON、LocalStorage、日志或截图；
- 确认所有失败均可降级到本地导出；
- 测试结束后按官方契约清理文件、授权和服务端记录。

当前没有公开契约支持 PoC，因此本次正确停机点是提交调研结论。调研完成不等于集成获批，不创建真正集成任务，也不修改应用。
