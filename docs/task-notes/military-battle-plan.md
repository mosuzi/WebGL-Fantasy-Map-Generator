# 军事对象与战斗事件计划

## 背景

当前 WebGL 版已经在 `app/webgl-generator/src/generator/military.js` 中生成国家军团数据，并在国家详情中显示军力摘要。用户侧还没有军团图层、军团总览、军团编辑、战斗推演或战斗事件备注链路。

原版入口：

- `source/Fantasy-Map-Generator/public/modules/ui/regiments-overview.js`
- `source/Fantasy-Map-Generator/public/modules/ui/regiment-editor.js`
- `source/Fantasy-Map-Generator/public/modules/ui/battle-screen.js`

## 原版行为摘录

- 军团总览按国家列出 regiments，显示国名、图标、军团名、各兵种数量、总兵力，并支持筛选国家、百分比模式、添加军团和导出 CSV。
- 军团编辑可改军团名称、陆军/海军类型、徽记、兵种数量、驻地、旋转角度、基地位置、拆分、附加、删除和攻击模式。
- 战斗界面会根据攻击方/防御方、地形、城市、河流、海军/空军/登陆等条件定义战斗类型与名称。
- 战斗模拟记录双方军团、距离、士气、战斗阶段、骰子、伤亡和幸存者，最终可应用结果或取消。
- 原版战斗结果会和备注/legend 链路相连，形成可追溯事件。

## WebGL 版建议边界

第一阶段不要直接复刻战斗模拟。理由：

- 当前地图对象编辑器还在成形，军团图层和对象详情需要先稳定。
- 战斗模拟会改写军团兵力、生成事件、影响注记，必须先有军事对象数据契约和撤销/导入导出策略。
- 原版 UI 大量依赖 SVG group 拖拽、旋转和 jQuery dialog，需要改写成 WebGL overlay + Vue 浮层。

## 阶段计划

### 阶段 1：只读军团总览

- 新增“军事总览”浮层，懒加载 Vue 面板。
- 列出国家、军团名、类型、位置、基地、各兵种数量、总兵力。
- 支持按国家筛选、排序、定位军团位置和导出 CSV/JSON。
- 开发模式下显示 state id、regiment id、cell、base cell、生成诊断。

验收：

- 打开面板不改变 checksum。
- 军团数量、总兵力和 `map.military.metadata` 一致。
- 定位能跳到军团坐标或所属国家中心。

### 阶段 2：军事图层

- 新增“军事”图层，绘制军团 icon、名称或简化兵力符号。
- 先用 HTML/SVG overlay 或 WebGL 点 sprite；不急于实现旋转和基地线。
- 悬停显示军团摘要，点击选择并打开对象详情。

验收：

- 图层关闭后无军团绘制和 picking 负担。
- 军团图标点击区域完整，不只响应像素点。

### 阶段 3：军团轻量编辑

- 支持重命名、改图标、改兵种数量、改陆/海类型。
- 支持移动军团位置和基地位置，但需要先定义 undo command。
- 完整地图 JSON 保存编辑后的军团数据。

验收：

- 修改军团不会触发全图重新生成。
- 撤销/重做能恢复兵力、位置和名称。

### 阶段 4：战斗事件记录

- 先做“创建战斗事件”而不是完整模拟：选择攻击方、防御方、地点、名称、类型和备注。
- 事件进入 `map.battles`，可作为 marker/备注显示在地图上。
- 战斗事件与对象注记系统联动，支持导出和完整地图保存。

验收：

- 创建事件不强制改变军团兵力。
- 完整地图导出再导入后，战斗事件和关联备注保留。

### 阶段 5：战斗模拟

- 复刻原版的双方军团、士气、阶段、骰子、伤亡和应用/取消流程。
- 应用结果时生成 EditHistory command，能撤销所有军团兵力变化和事件记录。
- 战斗类型推断参考原版：field、naval、siege、ambush、landing、air。

验收：

- 取消模拟不改变地图数据。
- 应用模拟后军团幸存者、伤亡、事件备注和总兵力摘要一致。

## 暂缓项

- 完整军团编队 UI、旋转控制和拖拽基地线。先做数据和只读图层。
- 战斗 wiki、复杂阶段文本和所有原版随机叙事。可后续逐步补。
- 把军事结果自动反馈到外交、经济或人口。当前先保持军事系统内部闭环。
