# 界面排版与提交校验

普通动作按钮保持单行，空间不足时让整颗按钮换行。不要用缩小字体、裁切、自动省略或允许中文字折行掩盖容器不足。图标按钮使用共用 32px 命中区域；布局可按用途采用自适应网格或换行的 flex 行。

## 组件规则

`UiButton` 默认使用单行规则。搜索结果、存档文件卡片等本来就包含多个信息层次的内容按钮必须明确写出 `wrap-reason="原因"`；原生按钮使用 `data-layout-multiline="原因"`。例外只允许多行，不豁免越界、裁切或重叠。

不要对所有按钮设置 `white-space: normal` 或 `overflow-wrap: anywhere`。在 flex 行中使用带 `width: 100%` 的按钮时，必须同时检查旁边的标签、说明和字段是否被挤压。普通文本和说明仍可正常换行。

## 提交前检查

```powershell
pnpm run setup:ui-layout-hook
pnpm run build:app
pnpm run check:ui-layout
```

安装只修改当前仓库的 hooksPath。遇到已有 hook 配置或本地 pre-commit 时拒绝覆盖，由维护者把 `node tools/ui-layout-commit-gate.mjs` 接入原检查。新克隆需要安装一次。

检查使用隔离 Chrome 和地图，自动启动 production 预览，不操作用户现有标签页。产物默认写入临时目录的 `fmg-ui-layout`，可通过 `UI_LAYOUT_OUT` 指定。完整报告保留执行状态、问题控件、例外原因、未覆盖项与截图。

构建保存界面源码指纹。验收前必须核对构建来源，验收期间源码变化也不能签发凭据。Git 提交门再与暂存文件逐一核对：修改共用样式、组件、检测器或新增界面文件后，旧凭据自动失效。仅改文档不强制重跑。

## 覆盖与判定

- 固定正式面板清单与运行时比对，新增面板而未更新清单会失败；每个面板先等待真实内容加载，不能只检查空壳。
- 桌面、690px 窄屏和 Chrome 实际 125% / 150% / 200% 缩放；覆盖控制面板页签、样式类别、经济和资源页签、可用列表选中 / 空筛选、展开区、菜单、搜索结果 / 空态与公开对象类型。
- 创建带长中文的备注和测量夹具；忙碌 / 错误 / 长按钮文案用真实按钮 DOM 做独立排版压力检查。这证明共用样式能容纳状态变化，不冒充所有异步业务、云账号连接或错误恢复的功能验收。
- 按实际文本矩形检查按钮行数和裁切；检查按钮间重叠、控件越界、图标 / 共用按钮尺寸及面板横溢。表头排序、列宽拖柄、数值步进是复合控件，不按普通动作按钮判行数。滚动表格按其滚动边界检查，不把合法内部滚动当成页面溢出。
- 未执行必需状态直接失败；没有对象的非必需列表明确记录原因，不计为已覆盖。固定要求国家 / 城市 / 标签 / 备注 / 测量 / 河流 / 湖泊详情和城市编辑、搜索、压力状态完成。
- 反例验证必须抓住折行、裁切、重叠，且多行例外不能掩盖裁切。提交门的缺失 / 过期 / 新增文件反例也必须拒绝。

可以用 `node tools/webgl-generator-ui-layout-browser.mjs --panel=city,state` 做桌面与窄屏定向检查；`--survey` 用于汇总调查，允许保存全部问题。两者都不会签发完整提交凭据。正式检查发现第一个问题即停止，保存证据，按仓库规则做窄修和目标复验后再收口。

几何检查不能替代观感判断：色彩层次、纸纹密度、文字疏密仍需代表截图人工复核。自动门保障已列出的状态与规则，不宣称穷尽任意数据、浏览器和所有交互组合。
