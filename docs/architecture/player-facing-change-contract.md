# 玩家可见改动的完整性约定

本约定针对已经反复返工的玩家体验问题。每个面向玩家的任务在动手前按实际改动选择下表中命中的影响域，并在当前权威任务或专题记录里写清**玩家动作、预期结果、受影响的派生状态、旧数据边界和正式验收入口**。未命中的域写明原因即可，不为完成表格制造无关测试。用户新指令和当前批准范围优先；本文不授权新增功能。

已有细则继续由[界面排版](./ui-layout-contract.md)、[生成与重生成关系](./generation-validation-relations.md)、[存档逐版兼容](./save-version-compatibility.md)和根 `AGENTS.md` 的性能、浏览器、重试规则负责。本文规定这些细则之间的衔接与玩家能观察到的结果。

## 从反复返工中固定的判断

| 触发条件与既有反例 | 执行约定 | 必须观察到的证据 |
|---|---|---|
| 新增玩家入口、定时任务、自动保存或启动服务 | 新能力必须有当前权威范围的明确授权，写明触发时机、退出方式、数据作用域和既有流程。 | 命中新增能力时，正式入口可用、只在约定时机运行，旧的相关操作仍可完成；没有授权时不实施。 |
| 撤销已存在的能力；“意外恢复”曾在第 389 项获批，后由第 427 项撤销 | 逐一清理受影响的界面、启动接线、监听、定时器、后台写入、不可达分支及专属夹具；保留旧用户数据，明确旧数据的去向。 | 正式页面无已撤销入口；旧偏好开启仍无相应后台动作；受影响的手动保存与导入仍可用，旧记录未被暗中清空。 |
| 修改单字段弹框、图标动作或数值图层文案；曾出现 HEX 文本挤出、冗余标题/按钮、图标大框与“人口柱”等实现词 | 玩家操作只有清楚的一条完成路径。无需预览或危险确认的单行字段用 Enter 应用并关闭，输入法选字不提交；该字段的空值、同值、失败草稿、焦点与撤销保持正确。纯图标用一致的透明命中区与可访问名称；普通文案用玩家概念命名。 | 字段改动核对真实键盘输入与点击；图标改动核对命中区和可访问名称；文案改动核对玩家可见名称。界面改动按实际布局在窄屏和 200% 缩放检查文本与控件，并通过适用的 `audit:ui-copy`、`check:ui-layout` 门。 |
| 用户说“其它同理”“所有类似”或“全局审查”；曾只修一个输入框或一个列表入口 | 先从共享组件与正式入口清点同类项，记录总数、命中项和不适用理由；优先修共享根因，再逐类核对实际状态。截图中的一个对象只是复现入口，不自动缩小用户授权的同类范围。 | 清单中的每类有正式入口或静态不适用证据；抽样不能冒充全量覆盖，漏项计为未完成。 |
| 修改列表选择、画布拾取或二级弹框；曾出现高亮国家未在列表选中、政体弹框藏到国家面板下 | 涉及选中身份时将“当前对象”与批量选择、锁会话分别建模，换图或对象失效时重验身份。涉及浮层时由共享层级管理，父面板升层后弹框仍可操作；外点、焦点和 Esc 按可见层级处理。 | 选中链路改动核对正式画布点击后的对象种类/ID、列表 `aria-current`、筛选/虚拟行与 Ctrl 多选；浮层改动核对重叠处 `elementFromPoint`、候选点击及逐层 Esc。只验命中的链路。 |
| 建国、删国、涂抹疆域等用户编辑；曾出现旧首都无法建国、涂抹后无首都或重复首都、邻国撞色 | 在事务工作副本上先执行用户变动，再对本次受影响对象做局部 `ensure/backfill`，最后按该入口现行最小提交硬门校验并原子提交。建国建立完整新国资料，保留城镇自有资料；改变疆域后对仍存在且有领土的受影响国家重验并修复唯一合法首都、标记与镜像；新国取色优先避开所有邻国，调色盘确实耗尽才可重复。可精确撤销的单国删除直接执行，不擅加二次确认。 | 按实际动作选取旧首都建国、刷走首都、无城镇补都、连续涂抹、邻国相接或删国夹具；核对单次历史、撤销/重做、受影响资料和失败回滚。重生成的额外边界按[生成关系契约](./generation-validation-relations.md)，软关系不升级为硬门。 |
| 改国家色、国界平滑、cell 归属、主题、标签或数值层；曾出现边界虚影、异色三角、古地图花色、新国标签异样和落在海上的国名字形 | 从规范地图事实列出受影响的派生消费者：grid/pack 镜像、GPU 基础面与修正层、调色板、边界、标签、拾取、PNG；只重建并验证命中的消费者。cell 归属变动必须整格生效，残留三角不能在落笔结束后留存。主题按其色彩语义计算显示色；国家标签继承统一样式，按每个可见字形的方框及描边、阴影检查本国陆地。字间空白与标签中点可以落在海上，点击空白处应命中其下的地图。降雨圆点不超过 cell，人口按已批准的圆柱投影、高宽比例和底图夹角显示。 | 颜色/边界/cell 改动在正式复合图检查近景与全图、受影响显示组合及稳定的原始 canvas 像素；标签改动查样式、位置和可见避让；拾取或导出受影响时分别查对应 ID 或 PNG；编辑和开关改动查前后及撤销/往返。对应操作窗口的页面/WebGL 错误为零。 |
| 画笔、建国、冷启动、视图切换、导入或改色出现迟滞；曾以 WebGPU 对照掩盖渲染前计算耗时 | 以玩家发起动作到可见结果为一次操作，按命中的阶段记录事件处理、候选计算、派生重建、GPU 上传、绘制和标签；阶段账本留在调试模式。指针热路径避免逐次全图扫描、重复对象化与同步大批量重建；只优化实测热点。绘制后端对照须使用同一复合场景和同一计时边界。用户指定存档或标签页时，在其原图验证，随机图只作基线。 | 按迟滞入口分别测冷启动、点击、拖涂、撤销、视图切换或导入；在与问题相称的 3k/10k、代表性 100k 及用户指定原图上，记录目标窗口最长 LongTask、响应总时长、命中阶段和结果。`>200ms` 按根 `AGENTS.md` 阻断。 |
| 改持久字段、保存格式、旧档校验或导入路径；曾把本程序旧档判坏 | 旧数据先逐版迁移和补全，再按当前结构校验；失败保持原存档及当前地图，保留用户自填资料、稳定身份与明确锁。只要改动会改变旧数据的读取或判定，就必须为这些旧路径建立兼容证据。 | 按受影响格式选冻结旧版浏览器缓存、JSON、`.webfmg` 和代表性用户地图，依[存档契约](./save-version-compatibility.md)回读；核对升级结果、原始档保持与未来版本精确拒绝。纯生成算法或纯显示改动不强制跑无关旧档格式。 |
| 改用户编辑、兜底校验或后台生成；曾把可补全关系当成玩家操作门槛 | 编辑先执行、局部修复、再按现行最小提交硬门校验并原子提交；后台生成先构造、修复与校验，最后提交前台。生成与重生成遵守[生成关系契约](./generation-validation-relations.md)的基础物理、身份、事务和锁硬门；软关系不得升级为硬门。 | 按命中的入口核对可修复缺失被补全、命中硬门的无效结果被拒绝且原状态不变；编辑入口查单次历史与撤销/重做，生成入口查前台只收到完整结果。 |
| 任一浏览器夹具或性能门失败；曾点在面板上、比较未稳定画面、把浮层截图当地图或沿用过时断言 | 先证实夹具真的操作了目标页面、地图、对象、cell 与模式；画布用原始像素或正式 canvas，异步画面等到稳定帧，性能观察窗只覆盖目标操作。首败写明现象、原因、实质调整和窄复验点；夹具错误与产品错误分别记账。 | 每个关键断言附可核对的前置条件、实际执行状态和观察窗口；未命中的断言不记通过，未运行的门不写通过；按根 `AGENTS.md` 的同错重试上限执行。 |

普通玩家界面只呈现操作结果与必要的下一步。完整诊断、内部代码、存储后端和错误字段留在调试模式；不能把它们作为菜单内容或常驻说明。需要提示旧档升级时，在打开流程内用现行古风文案告知整理进度与结果，不增加玩家同意步骤。

以上每一行都适用同一失效处理：产品结果不符时留在当前授权范围做最窄修复与目标复验；夹具自身失效时先核对前置条件，再修夹具并复验目标断言；缺少授权、需要新产品决策或修复超出当前封闭范围时冻结该点请用户裁定。按根 `AGENTS.md` 记录同错重试次数与每次实质调整；未命中条件、未取得证据或仍有失败的门不得记为完成。

## 地图的编辑表示与局部更新

地图接入后，玩家可编辑的字段、对象行、坐标和邻接关系使用普通对象与数组。磁盘上的字节、分区和用于传输的列在打开时解包。绘制所需的顶点、纹理与拾取索引从可编辑地图派生，可按同一批对象或格子更新。地图事实只有一个写入来源。

日常编辑按稳定身份定位对象，记录实际写入的字段、格子或关系边，以及必要的新增和删除。一次操作、撤销、重做与后台副本使用同一写集。派生结果按真实依赖扩展，例如水陆变化可沿相连岸段追踪，行政人口合计可沿所属关系追踪。局部影响可能延伸到笔圈以外，边界由依赖决定。新建、整图替换和用户显式指定全图的重新生成可以构建完整结果。

验收需分别记录业务数据写入范围、派生计算范围和图形资源刷新范围。在旧档上验证修改、撤销和重新打开，核对未受影响的对象身份、手填字段及派生结果，统计整图重建次数。单独的局部补丁接口或小图的用时不能证明某个实际编辑入口已经局部化。

## 每项任务的最小记录

在当前任务条目或专题记录中保留以下五项，直接写真实值，不用空泛的“已自查”：

1. **玩家动作与完成状态**：从哪个正式入口操作，最终玩家会看到什么；无需新入口时写明。
2. **变动闭包**：规范数据和受影响的画布、列表、标签、拾取、导出、存档、后台任务；域不适用时说明依据。
3. **不可破坏内容**：用户自填资料、旧存档、手动保存、单次历史、撤销/重做、已批准的显示设置。
4. **目标场景**：至少一条真实正式入口；需要时包含旧档、100k 复合图、近景边界、窄屏/放大、失败回滚。夹具明确证实目标条件已命中。
5. **结果证据**：用户结果、受影响对象数量、像素或 DOM/拾取、错误与 LongTask，首败和复验序号；写明没有运行的门及原因。

做完静态检查只说明静态阶段通过。玩家可见的修改在正式浏览器完成对应动作后才算验收；具体门禁按影响域升级，不机械运行无关的全量套件。发现用户指令与旧计划或旧夹具矛盾时，先用最新授权校准当前任务，再校准夹具和历史记录的解释，不能让过时预期挡住用户操作。
