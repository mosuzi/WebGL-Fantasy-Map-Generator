# 政体系统与国家国号规则

本文档记录国家政体第一刀的设计边界。它替代旧的“按文化类型直接抽国家形制”方案，后续调整国家命名、外交、经济或军事时应优先参考这里。

## 背景

国家后缀不能再使用“朝”。“朝”更像后世写史时对政权时代的称呼，不适合作为地图中一个国家自称的正式国号。国家名应由“根名 + 国号后缀”组成，后缀需要同时参考政体、国家规模、文化类型和自我定位。

## 国号后缀原则

- 小国默认使用 `国`，例如 `齐国`、`芮国`。
- 番邦、君主制或封建王权可使用 `王国`，但不是所有小国都要自称王国。
- 大型专制集权国家或自诩正统的大国可使用 `帝国`。
- 共和政体的大国可以使用 `共和国`；小国共和仍可能只使用 `国`。
- 联邦制大国可使用 `联邦共和国`，中等国家可使用 `联邦`。
- 邦联制使用 `邦联`，部族联盟使用 `部盟`，草原君主使用 `汗国`，神权国家可使用 `教国`。
- 少数小国会随机自诩为大国，以便出现野心过盛的小型帝国或完整共和国。

## 当前政体类型

第一刀政体定义位于 `app/webgl-generator/src/generator/governments.js`：

- `君主制`
- `帝制官僚`
- `封建王权`
- `共和制`
- `商业共和国`
- `联邦制`
- `邦联制`
- `神权制`
- `汗廷`
- `部盟`
- `军府`
- `寡头制`

生成权重会参考文化类型和国家规模。例如游牧文化更容易生成 `汗廷 / 部盟`，海洋文化更容易生成 `商业共和国 / 共和制`，大国更容易生成 `帝制官僚 / 联邦制`。

## 系统影响

政体不是纯展示字段，当前已经接入三类派生系统：

- 经济：影响税率、贸易倍率和 `economicPower`。
- 外交：影响同政体亲和、专制与共和冲突、宗教政体冲突、扩张倾向和附庸概率。
- 军事：影响征兵倍率、兵力上限、军团目标数量和兵种比例。

这些数值修正刻意保持温和，只用于塑造倾向，不应把地形、人口、资源和外交关系本身完全覆盖。

## UI 与数据契约

- 国家对象保留 `form/formName/fullName` 兼容旧面板、标签和导出。
- 新增字段包括 `governmentKey / governmentLabel / governmentFamily / governmentCategory / governmentEra / governmentSize / selfStyledGreat / government`。
- 国家管理面板的二级操作新增“调整政体”，修改后会进入撤销栈，并把经济、外交、军事标记为待派生。
- 国家 GeoJSON 导出会写入政体字段，完整地图数据导出会随国家对象自然保存。

## 后续计划

- 增加专门的“政体管理”面板，用于批量查看、筛选和调整政体分布。
- 让政体影响国家合法性、文化同化、宗教改革和贸易政策。
- 让战争、革命、内战、附庸化等事件可以改变政体。
- 补充政体图层或外交矩阵中的政体过滤器。
