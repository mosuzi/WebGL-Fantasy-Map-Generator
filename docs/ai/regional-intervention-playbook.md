# 复杂区域干预行动手册

本文面向“保持世界基本关系，同时改善局部结果”的地图任务。示例只使用匿名区域 A / B / C，不预设任何存档、专名、方位或对象编号。默认 AI 必须先从当前地图解析目标，再把自然语言要求转换为可量测区域、约束和事务。

## 统一闭环

1. **确认运行时与地图身份**：读取 `info.mapSummary`、checksum、documentId、revision、`derivedStale`；离线只读优先无头 API，当前标签页写入使用受控桥。
2. **解析对象与空间**：用 `objects.query / get` 找对象，用 `analysis.defineRegion` 固定目标区、对照区、保护区和排序 cell 集。不要从显示名猜 id，也不要混用 Grid / Pack id。
3. **冻结事实基线**：对每个区域调用 `analysis.describeRegion`，再按问题调用降水、人口、国力或地形诊断；保存样本数、统计口径、证据 cell、对象集合、锁、历史和必要截图。
4. **把要求写成不变量**：至少列出海陆、疆域、主峰 / 山脊 / 山口、河流出口、城市、路线、人口载体、对照区和允许漂移。每条都要能由 API 或固定画面复验。
5. **先排动作顺序，再预检**：地形改变应先于地理派生重建，气候改变应在地理关系稳定后执行，人口调整放在自然承载和网络确定之后。每个写动作都走公开 inspector / execute、revision、requestId、确认和阶段快照。
6. **同口径复算**：每步后重新调用相同分析，比较目标、对照和保护区；出现超限即回退最近阶段，不用后续写入掩盖失败。
7. **完成存档与视觉验收**：导出新存档并重新加载，验证关键 cell / 对象 / 聚合仍一致；涉及地形或图层时关闭开发面板，用相同相机、主题和图层保存全图及局部 before/after。

## 模式一：保持大地形关系的梯度自然化

适用症状：高山区存在孤立尖峰、邻接高差突变或杂乱锯齿，但主山脊、山口、海岸和大陆关系必须保持。

### 取数与聚合

- 先以 Pack 区域确定山地语义范围，再经 `gridId` 回到 Grid 高度写入层。
- 调用 `analysis.diagnoseTerrain` 获取 slope / roughness P90、突变与粗糙证据；另外统计高于邻居中位数的孤立尖峰、`h >= 50` 连通块、最高峰及其一环。
- 分别验收每个山地区域，不用合并均值掩盖单区失败。

### 约束与动作

- 保护海平面分类、选区外同水陆一环之外的高度、主峰邻域、主山脊主分量、主要山口和河流出口。
- 优先用 `edit.height.inspectSelectionSmoothing / applySelectionSmoothing` 对有限选区和羽化边界操作；不要用全图邻接均值，也不要裸写高度数组。
- 平滑后再执行所需的高度派生重建，并在重建前用 `regenerationLocks` 保护不能被重生成替换的路线、城市或其它对象。锁定保护对象，不替代 cell 高度范围约束。

### 成功条件

- slope / roughness 分位数和孤立尖峰显著下降，同时高山区保留率、峰值、relief、山脊连通和海陆分类在预设容差内。
- 河流可能在重建后重新编号，因此出口应同时按河口地理位置、末端 cell 邻域和局部尺度匹配，不能只比较 river id。
- 高度全图与局部画面不存在规则环纹、大面积平台、新内海或海岸缺口。

## 模式二：地形雨影下的区域承载改善

适用症状：目标区整体偏干、人口偏低，同时又要求保留山地屏障和政治疆域。

### 先区分三个问题

1. **自然承载不足**：降水、温度、生物群系或 suitability 低。
2. **已有承载但开发不足**：候选 cell 合理，但城市、路线、市场或现有人口载体不足。
3. **统计假象**：目标区与对照区面积、海拔带或 stale 状态不同。

### 取数与因果

- 目标区至少拆为屏障区、核心承载区和迎风 / 背风侧；调用 `analysis.explainPrecipitation`、`climate.getAtmosphere` 和 `analysis.diagnosePopulation`。
- 对照区必须不在地形编辑范围内，且气候带、海拔或海陆背景可比。先冻结排序 cell 集和基线 mean；若对照漂移超限，不能把全局普涨解释成局部改善。
- 低降水与高山共现只支持“潜在屏障”推断；主导风向、水汽路径和两侧差异共同成立后才能称为雨影证据。

### 安全顺序

```text
有限地形调整（如确有必要）
→ features / rivers / routes 等地理派生重建
→ 重新冻结地理与对照基线
→ 气候参数调整
→ 验证目标与控制区
→ 人口 inspector / apply
→ 复算人口、承载和 stale
```

气候重算会重新定义生物群系、适居度和默认人口评分。若任务要保留现有人口，浏览器气候写入必须显式使用 `preservePopulation:true`；地理派生重算只有 `features / routes / rivers` 支持同一选项。该选项保护人口数组，不免除适居度、气候和行政聚合复验。

### 成功条件

- 目标降水和人口进入预先定义的区间，人口增量主要落在适宜且不过陡的既有人口载体。
- 屏障的高度带、峰脊和证据数量保持，疆域、省份、城市集合和非目标人口不变。
- 未受干预控制区保持在允许漂移内；全图画面没有同步整体变亮。

## 模式三：跨障碍的同政权发展差距

适用症状：同一政治实体在山脉、荒野或其它障碍两侧发展不均，希望较弱一侧接近对照侧，但不改变疆域和保护区。

### 取数与判断

- 分别定义弱侧 A、对照侧 B 和障碍保护区 C。先比较 cell 数；面积差较大时同时报告总量与每 cell 指标。
- 用 `analysis.compareRegions` 比较气候、宜居度、人口、城市和路线，用 `analysis.comparePower` 读取透明代理分数；正式经济、军事和外交仍需对应领域对象验证。
- 用 `analysis.diagnosePopulation` 判断 A 是承载不足、缺少人口载体，还是道路 / 聚落 / 市场连接不足。人口为零且事务返回 `zero-population` 时，应报告能力边界，不能绕过事务制造载体。

### 约束与动作

- 冻结 A / B 的疆域、名称、首都、省份、城市和路线集合，冻结 C 的高度、归属、城市、路线和人口。
- 所有地理与气候变化完成后再冻结案例基线；否则后续派生重建会把自然承载变化误算成人口事务效果。
- 优先使用 `edit.population.inspectAdjustment / applyAdjustment` 增长 A；不从 B 转移人口来制造“平衡”。人口调整前后都比较 B 和 C，要求其漂移在容差内。
- 若必须重建可能影响受保护对象的系统，先以 `regenerationLocks.inspect / setMany` 锁定对象，重建后逐项比对并解除本次锁。旧存档加载可能补齐路线镜像的可选字段，语义比较应以正式路线对象、稳定路径点和 cell 链路为准。

### 成功条件

- A 的人口增长达到下限，A / B 人口比和代理国力比进入目标区间；改善主要来自已授权人口事务。
- B 的人口与代理分数、C 的全部保护字段及 A / B 的城市路线集合在容差内保持。
- 只能声称“透明代理接近”；若要声称正式国力相当，还需重算并比较经济、军事、外交和地区效果。

## 失败与回退模板

每个阶段输出以下结构：

```text
地图身份：documentId / revision / checksum
目标区域：定义、count、哈希、统计口径
对照与保护：定义、允许漂移、不变量
诊断：直接事实 / 推断 / 未验证假设
候选动作：方法、inspection、影响范围、派生重建顺序
验收：目标指标、控制指标、保护对象、history、locks、derivedStale、视觉
结论：通过 / 回退到阶段 N / 当前 API 能力不足
```

存档回读不是附加项。最终文件必须重新加载并复算；人口数组、Grid 镜像和国家 / 省份 / 文化 / 宗教聚合不能因兼容归一化改变，重复加载也不能累加零号未归属桶。
