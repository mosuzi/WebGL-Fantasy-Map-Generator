# 现有功能与界面信息架构审计

## 审计目的

本审计用于在继续权威任务第 45～52、54 项之前，先梳理正式应用已经积累的功能入口、面板层级和浮层关系。当前阶段只确认问题、优先级与建议处置，不删除功能、不调整 UI、不修改运行时代码。

> 状态更新（2026-07-15）：用户已批准把本审计结果收束为 `docs/current-plan.md` 的权威任务第 55～60 项。第 55 项已完成，覆盖 UIA-01、03、05、06、13；第 56 项已完成，覆盖 UIA-02、11、14；第 57 项已完成，覆盖 UIA-04、10、12及破坏性动作分层。本文继续保存审计时的问题证据和设计背景，剩余范围、顺序与验收以权威任务清单为准。

审计重点包括：冗余按钮、与当前设计体系不一致的 UI、复杂度与收益不匹配的功能、同类功能分散、低优先级功能、浮层遮挡，以及信息架构、状态反馈、可访问性和审计覆盖等补充问题。

## 证据范围

- 静态盘点 `app/webgl-generator/src/ui/vue/components/`、`app/webgl-generator/src/ui/panels/`、`PanelManager`、控制面板和全局样式。
- 当前有 26 个主要 `*Panel.vue`，合计约 14,793 行；这些面板内有约 111 个按钮、129 个共享字段组件、32 个内容 section、26 张对象表格和 21 组列表底部动作栏。
- `ControlPanel.vue` 的“管理”页当前平铺 25 个功能入口，下方另有 8 个重生成入口；入口有视觉上的两列排列，但没有领域分组、主次层级或使用频率区分。
- 2026-07-15 在 `1280×720`、开发页 `http://127.0.0.1:5410/` 实查：控制面板约为 `600×698`，国家编辑面板约为 `560×698`；两者分别位于 `(352,14)` 与 `(400,128)`，国家面板几乎整块覆盖控制面板。该结果不是窄屏特例，而是当前默认坐标聚集和多面板共存机制的直接结果。
- 现有 `webgl-generator-panel-layout-audit.mjs` 主要检查单面板溢出和最小宽度，不检查多面板碰撞、恢复多个持久化面板、固定高级浮层，也不评估按钮分组和功能层级。因此旧报告“无布局问题”不能代表当前信息架构和遮挡体验合格。

## 核心结论

当前主要问题不是“缺少入口”，而是入口和能力已经超过单层浮动面板能够清楚承载的规模。继续直接增加功能，会同时放大查找成本、重复操作、遮挡和维护成本。应先确定一套主次分层：高频基础动作留在首层，领域管理按组进入，低频高级能力折叠，实验性或暂缓能力退出主入口。

## 建议的信息架构

### 地图常驻工具栏

- 控制面板
- 测量
- 适配视图
- 撤销 / 重做（仅在有历史时突出）

常驻区只放高频、跨领域、能立即作用于地图的动作，不放纹章统计、名称库或领域重生成。

### 控制面板

- **项目**：新建 / 生成、保存、导入、快速导出。
- **生成**：seed、规模、尺寸、模板；高级气候默认收起。
- **视图**：专题主题、图层、显示单位。现有“视图 / 图层 / 单位”可在不丢能力的前提下重新确认是否需要三层 tab。
- **管理**：只保留领域分组入口，不再展示同权重的长按钮墙。
- **高级**：诊断、实验功能、低频格式和暂缓能力。

### 管理领域分组

1. **地形与环境**：高度、气候、生物群系、水体地貌。
2. **政治与社会**：国家、省份、城市、政体、文化、宗教、外交、人口。
3. **网络与经济**：路线、河流、湖泊、经济、军事。
4. **标注与对象**：地区、资源标记、标签、备注、测量对象、名称库。
5. **实验 / 暂缓**：纹章，以及尚未达到核心使用价值的高级档案型功能。

“资源点”和“通用标记”需要在命名和入口上明确区分；“测量”负责创建，“测量对象”负责管理，两者应在同一工具组内形成清楚的前后关系。

## 建议的功能处置级别

### 保留在首层

- 整图生成、保存 / 导入、快速导出。
- 高度基础画笔、国家 / 省份 / 城市核心编辑。
- 常用图层、适配视图、测量、撤销 / 重做。
- 路线、河流、湖泊、地区、资源标记、标签和备注的基础管理。

### 合并或重新分组

- 视图、图层与单位的入口层级。
- 国家编辑与政体管理、测量工具与测量对象、资源点与通用标记。
- 领域面板动作与控制面板重生成入口。
- 对象表格的逐行定位、双击和底部“定位选中”。

### 降为高级

- 高级气候参数。
- 高度条件数学变换、多步地形程序、色板诊断与 GPU 统计。
- 军事战报档案、链路筛选和轻结算。
- 导出的范围坐标、格式专属图层白名单和诊断选项。
- 名称库的格式诊断和高级绑定信息。

### 暂缓或退出主入口

- 纹章统计与纹章深化。
- 动态军事、复杂战斗模拟和继续扩大战报系统。
- 在没有稳定用户场景前继续增加新的独立浮动统计面板。

退出主入口不等于删除数据结构。涉及旧地图、完整地图 JSON、导入导出或渲染兼容的能力，应保留迁移和读取路径。

## 还需要纳入后续整理的问题

1. **高频程度与入口深度**：用真实使用频率决定首层、二级和高级，而不是按开发完成时间排列。
2. **破坏性动作层级**：删除、替换导入、重生成和批量覆盖必须与定位、导出等安全动作视觉分离，并显示影响范围。
3. **选中、编辑、预览三种状态**：当前各面板表达方式不完全一致，后续要统一常亮、禁用、退出和跨面板切换规则。
4. **窄视口与缩放**：除单面板不溢出外，还要验证浏览器缩放、系统字体放大、双面板和底部 toast 的安全区。
5. **焦点与键盘可访问性**：浮层打开后的焦点、Esc 关闭、Tab 顺序、图标按钮名称和快捷键冲突应进入统一验收。
6. **加载与挂载成本**：大型面板和低频模块应懒加载；连续打开面板时要观察 mount 长任务和内存，而不只看 WebGL 绘制耗时。
7. **术语与对象边界**：统一“资源点 / 标记”“水体 / 湖泊 / feature”“测量 / 测量对象”等容易误解的名称。
8. **空态与异常态**：无数据、无筛选结果、孤儿对象、待派生和操作失败应使用稳定且可恢复的反馈，不靠临时 toast 说明全部问题。

## 推荐整改顺序

1. 先确定管理分组、首层 / 高级边界和纹章退出主入口的产品决定。
2. 再治理面板共存、持久化恢复、固定浮层和地图安全区。
3. 合并定位、重生成等重复入口，统一图标、关闭和动作层级。
4. 依次拆分生成、高度、军事、导出四个高复杂度界面。
5. 补多面板与可访问性审计后，再恢复权威任务第 45～52、54 项的开发顺序。

以上审计结论已映射到权威任务第 55～60 项；实施时不得从本文件额外扩大范围，统一以 `docs/current-plan.md` 的封闭任务与最小验收为准。
