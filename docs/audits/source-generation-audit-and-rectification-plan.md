# Source 生成算法审查与整改方案

> 历史状态（2026-09-01）：本文保存成文时的生成链审查和整改建议，不是当前任务或候选来源。正文中的“后续”“应逐步恢复”只表示当时判断；若仍有可复核缺口，必须依据当前代码重新登记到根目录 [`../../FOLLOWUPS.md`](../../FOLLOWUPS.md)，不得从本文直接恢复任务。

本文档记录本轮重新审查结论，用于约束后续尚书实现、门下复核和侍中验收。目标不是自创新地形算法，而是把正式应用中已经偏离 `source/Fantasy-Map-Generator` 的关键链路拉回到 source 的生成思想上。

## 太子审查结论

用户指出的路线、河流、地形、45 度织物感、温度度量、国界和专题分界问题不是孤立渲染 bug，而是同一条生成链路的连续放大：

1. 底层图仍保留明显行列结构。当前 `grid.points` 虽有 jitter、行列 drift 和低频 warp，但每个点仍被限制在自己的行列格内，后续很多模块又继续按上下左右或八邻接扩散，导致 45 度、直线边界和群岛织物感。
2. 高度末端加入了非 source 的“按百分位强行匹配高度分布”。这个步骤会把局部连续坡面重排成全局等高带，容易产生平原梯田感、山地和平原边界突然跳变，以及高度专题之外所有专题的同步硬分界。
3. 河流虽然已经改为无环流向图和 flux，但河源上限、阈值和邻接仍偏保守，导致河流稀少；当前还缺少 source 的降水汇流、湖泊出口、河床下切、合流流量和 meander 曲线。
4. 路线当前使用贪心追踪。失败时还会把终点直接塞入路径，造成海中带陆地直线；路线也没有 source 的“先用城镇图决定连接关系，再按水陆分离成本寻路”的约束，所以会过直、过密穿山。
5. 文化、宗教、国家和省份当前主要使用最近中心或简单区域切分，和 source 的成本扩张不同。只要底层高度或点阵偏齐整，这些专题会立即表现为平直分界线。
6. 温度专题当前只提供颜色和 hover 数值，缺少可见度量尺；source 中温度是按纬度、海拔递减计算的明确数值字段，界面需要显示范围和单位。

## Source 算法要点

### 生成顺序

`source/public/main.js` 的核心顺序是：

1. 生成或复用 `grid`。
2. `HeightmapGenerator.generate(grid)` 生成 `grid.cells.h`。
3. `Features.markupGrid()` 标记海陆、湖泊、海岸。
4. 计算地图大小、纬经范围、温度和降水。
5. `reGraph()` 从 grid 抽稀/重建 `pack`，让业务语义不直接等同于基础渲染网格。
6. `Rivers.generate()` 处理汇流、湖泊出口、填洼和河床。
7. 定义生物群系、人口评分、文化扩张、城市、国家、路线、宗教、省份等。

正式应用当前仍是阶段性简化：`pack` 还是一格对应一格，且部分语义层早于河流生成。后续应逐步恢复 source 的“地形/水文先行，语义层基于成本扩张”的顺序。

### 高度图

`source/src/modules/heightmap-generator.ts` 使用模板步骤，而不是连续噪声直接采样，也不做全局高度百分位重排。核心步骤包括：

- `Hill`：从随机起点沿 `grid.cells.c` 邻接传播，传播量按 `blobPower` 递减，并带 0.9 到 1.1 的随机扰动。
- `Range`：先沿邻接图朝终点生成主山脊，再向周围传播高度；`linePower` 随 cells 数增加而提高，100000 cells 时为 0.93。
- `Trough`：用类似 Range 的路径向周围削低高度，形成谷地和海峡前置结构。
- `Strait`：沿邻接路径降低高度，形成纵向或横向海峡。
- `Smooth`、`Mask`、`Add`、`Multiply`、`Invert`：按模板显式执行。

正式应用已经复刻了模板步骤雏形，但偏离点在于：邻接不是来自真实 cell 边，末端额外加了百分位分布匹配，并用额外 ridge 强调/压缩改变了 source 的自然过渡。

### 气候和水文

source 温度模型以地图纬度和海拔递减为基础，降水模型按纬度带和风向把湿度从地图边缘/水域输送到内陆。河流在 `pack` 上按降水 flux 从高到低汇流，包含填洼、湖泊出口、合流和下切；最终绘制时还会通过 meander 和宽度函数生成更自然的河道。

正式应用本轮不一次性完整复刻 pack 河网，但应先做到：河流数量不再被固定小上限压住，邻接走真实 cell 边，源头按汇水和降水选择，路径无环且可合流，显示点列有基础曲折。

### 路线和边界

source 路线不是直接连接城市点。它先用城镇 Delaunay 的 Urquhart 图决定潜在连接，再用带成本的 `findPath` 在 `pack` 上寻路。陆路禁止走水域，海路禁止走陆地，并按高度、生物群系、已有道路连接和城市等因素调整成本。

source 国家、文化、宗教也不是最近中心染色，而是从中心点向邻接 cell 做成本扩张。山地、河流、水域、生物群系、文化差异、人口和类型都会影响扩张成本。因此自然边界会依附河流、山脉、海岸和可居住地，而不是形成纯几何直线。

## 尚书整改顺序

本轮按影响范围从根到枝修复：

1. 让正式应用生成并使用 `grid.cells.c` 真实共享边邻接。高度、feature flood fill、河流、路线和后续扩张都优先使用该邻接，减少行列方向传播。
2. 去掉高度末端的强制百分位匹配，改为只校准海平面比例、保留模板步骤产生的局部坡度；补轻量坡脚平滑，避免山地和平原直接断开。
3. 河流改用真实邻接、动态河源上限和更低 flux 阈值，并为长河段加入确定性 meander 中点，先解决“稀少、过直、缺少支流感”。
4. 路线改为 A* 成本寻路：陆路禁止穿水，山地和大坡度成本显著提高，找不到路径时不画 fallback 直线。
5. 文化、宗教、国家和省份从最近中心改为基于邻接的成本扩张；成本参考 source 思路纳入高度、气候、文化同源和河流阻隔。
6. 温度专题补可见度量尺，至少显示当前温度范围和摄氏单位。

## 验收标准

门下复核：

- `source/` 无源码修改。
- 不再保留路线寻路失败时 `path.push(end)` 的直连逻辑。
- `matchHeightDistribution()` 不再参与正式高度生成。
- feature、河流、路线、文化/宗教/国家/省份扩张不再默认依赖上下左右行列邻接。
- 文档同步记录本轮审查、修改和限制。

侍中验收：

- `node --check` 覆盖改动的正式应用 JS 文件。
- 启动或复用 `http://127.0.0.1:5410`，用浏览器生成 100000 cells 地图。
- 验证 WebGL 非空、无 WebGL error、控制台无 error。
- 抽查路线不存在跨海 fallback 直线，路线统计不为 0。
- 抽查河流数量随 100000 cells 明显高于旧固定上限，且最长河流有 meander 点。
- 输出网页快照供移动端查看。

## 当前仍保留的限制

- 本轮仍不把 `pack` 升级为 source 的抽稀/重建图，仍保持 `one-grid-cell-to-one-pack-cell` 阶段性映射。
- 本轮不引入 Vite 或外部构建器。
- 本轮不修改 `source/`，也不复刻完整 SVG 宽河道、湖泊命名、真实贸易网络、军事和纹章。
- 底层点集仍有行列来源，真实 Delaunay/Voronoi 或蓝噪声采样应作为后续专项；本轮先用共享边邻接和 source 风格传播降低方向偏差。
