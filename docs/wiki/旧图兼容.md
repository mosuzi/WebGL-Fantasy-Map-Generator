# 旧图兼容

旧数据适配覆盖浏览器缓存、未压缩 JSON、gzip / gzip-base64、既有完整地图和旧导出。所有入口最终进入同一解析、版本迁移、typed array 恢复和兼容归一化链。

## 当前可识别的完整地图外壳

- 新建原生压缩存档：`.webfmg`。
- 旧压缩文件：`.webgl-map.json.gz`、`.json.gz` 和 `.gz`。
- 未压缩完整地图：`.json` 或旧 `.webgl-map.json`。
- 浏览器固定存档：gzip-base64 字符串。

扩展名只帮助选择器和文件列表识别；解析仍会检查真实内容、文档类型和版本，不会因为把任意文件改名为 `.webfmg` 就接受。

## 迁移会做什么

- 恢复 typed array 的原构造器。
- 按相邻版本执行 v1 → v2 迁移，不跨版本猜字段。
- 为缺少的可选存储、缓存、视觉字段和兼容镜像补安全默认值。
- 归一旧地区类型、外交、河网、湖泊、标签、视觉、锁和浏览器偏好。
- 旧图没有地图名称时按原 seed 确定性回填。
- 保留能够明确解释的旧对象身份、字段和用户覆盖。

## 迁移不会做什么

- 不静默改变保存的人口、城市人口、地形、海陆、疆域或行政归属。
- 不根据名称猜测歧义对象关系。
- 不自动重新选择省会、重划国家、重建路线或改写旧用户标签样式。
- 不把无头内存迁移写回原文件。
- 不接受高于当前支持版本的未来文档。

需要改变地图事实的兼容修复必须通过显式预览 / 预检和领域事务完成。例如省会重评、旧图规模视觉刷新、路线或河流重生成，都不属于“加载时顺手修好”。

## 安全升级步骤

1. 保留原文件和原浏览器站点数据，不先覆盖。
2. 在新版中导入，阅读结构化诊断和迁移摘要。
3. 检查地图名称、seed、checksum、Grid / Pack 数量、人口、疆域、城市和锁。
4. 切到高度、国家、人口等关键专题，核对旧视觉覆盖与标签。
5. 另存为新的 `.webfmg`，关闭后重新加载。
6. 比较回读后的 checksum、人口数组、对象数量、历史初始状态和 `derivedStale`。

浏览器旧存档恢复失败时，应用应保留原 LocalStorage 字符串并显示诊断，而不是先删除再生成新图。若当前页面已经因为坏文件生成了临时地图，不要把临时地图覆盖到原文件或云端对象。

## 自动化与旧图

无头只读 API 可以加载 JSON、gzip 和迁移后的 v1 文档，分析前后输入哈希不变。无头写会话也使用同一迁移链，但默认输出新文件；覆盖输入需要双重显式确认。

对兼容问题报告至少附：原后缀、文件字节数、文档版本、失败阶段和诊断 code。不要上传完整私人存档、对象名称、坐标、token 或截图；可用最小脱敏样本复现结构问题。

文件类型和导出用途见 [存档与导入导出](存档与导入导出)，遇到具体错误见 [故障排查](故障排查)。
