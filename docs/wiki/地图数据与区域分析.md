# 地图数据与区域分析

地图同时使用基础生成网格和业务网格。大多数“结果不对”的分析错误都来自混用两层 cell、把模型值当现实单位，或把空间共现当成因果。

## Grid 与 Pack

| 空间 | 主要职责 | 常见字段 / 对象 | 典型用途 |
|---|---|---|---|
| Grid | 基础生成与完整世界 Voronoi | 高度、温度、降水、基础几何 | 高度图、气候源数据、全世界连续地形 |
| Pack | 业务对象与可操作区域 | 陆水、政治、人口、城市、路线、河流、地区 | 对象查询、编辑、区域统计、GeoJSON |

`pack.cells.g` 把 Pack cell 映射回 Grid cell。Grid id 与 Pack id 不是同一编号，不可直接互换。调用 `cells.*` 时应显式写空间；当前 `analysis.*` 的区域结果使用 Pack space，并在证据中提供可用的 Grid 映射。

底层基础 mesh 必须使用 Grid 的点、cell 顶点和 Voronoi 几何。Pack 为业务语义裁剪和重组过，不能拿来假装均匀底层网格。

## 主要模型值

| 主题 | 数据含义 | 常见误区 |
|---|---|---|
| 高度 | `0～100` 的模型高度，`20` 为海平面 | 不直接等同米 |
| 温度 | 气候模型值 | 需结合纬度和气候选项解释 |
| 降水 | Grid 原始降水值 | 颜色深浅不是独立现实毫米测站值 |
| 宜居度 | 人口承载输入之一 | 高宜居度不保证已有高人口 |
| 农村人口 | Pack cell population | 不能漏掉城市人口或重复计入 |
| 城市人口 | city / burg population | 与农村人口分开保存和汇总 |
| 坡度 | 当前 cell 与邻接 cell 的最大高度差 | 不是现实角度 |
| 粗糙度 | 邻接高度差均值 | 适合发现局部突变，不代表整条山脉 |
| 政治归属 | Pack `state / province` | `0` 常为中立；数组可含占位或 tombstone |

比例尺和显示单位只改变人类读数，不改变内部世界坐标。对比前记录单位、地图比例和区域 cell 数。

## 对象、镜像与派生

国家、省份、城市、文化、宗教、路线、河流、湖泊、marker、地区、军事、标签、备注和测量对象都有稳定 kind 与 id。对象数组中的索引不总能当作有效 id；应使用 `objects.get / list / query` 或领域面板，不按名称、数组位置和视觉顺序猜引用。

部分事实同时保存在 Grid、Pack、对象和统计镜像中。例如人口修改需要同步农村 cell、城市、国家 / 省份 / 文化 / 宗教聚合和人口点。`metadata.derivedStale.systems` 表示已知过期的派生系统；基于 stale 的经济、军事或水文摘要不能直接当最终结论。

完整存档加载时可以补结构、缓存和兼容镜像，但不能静默重算并覆盖用户保存的人口、地形、疆域或对象身份。

## 定义区域

区域分析支持直接 Pack cells、国家、省份、地区、全部陆地，以及多个区域的并、交、差：

```js
api.analysis.defineRegion({kind: "state", id: 3});
api.analysis.defineRegion({
  operation: "difference",
  regions: [
    {kind: "state", id: 3},
    {cells: [101, 102, 103]}
  ]
});
```

非法、越界和重复 cell 会被验证、去重并排序。结果包含规范化 specification、space、cells、count 和 source checksum；后续比较应复用这份明确定义，而不是重新凭视觉圈选一个近似范围。

## 区域统计与比较

| 方法 | 回答的问题 |
|---|---|
| `analysis.describeRegion` | 一个区域的地形、气候、宜居、人口、城市、路线和归属基线是什么 |
| `analysis.compareRegions` | 两个区域按相同口径差多少 |
| `analysis.explainPrecipitation` | 低降水与地形屏障是否存在证据化共现 |
| `analysis.diagnosePopulation` | 承载、现有人口、城市和通达性的主要限制是什么 |
| `analysis.comparePower` | 人口、城市、路线和宜居度组成的透明代理如何比较 |
| `analysis.diagnoseTerrain` | 哪些 cell 的坡度、粗糙度或局部突变异常 |

单一平均值会隐藏山峰、谷地和少数极端 cell。基线至少保留 count、min、max、mean、P10、P50、P90；人口同时报告 rural、urban、total、城市数和路线覆盖。面积不同的区域既看总量，也看每 cell 指标。

`powerScore` 只是透明代理，不是正式经济、外交或军事规则裁决。需要结论时继续查看市场、交易、军团、外交关系和地区影响。

## 证据化分析流程

1. 用对象查询确认目标身份，不按显示名猜 id。
2. 定义目标区、可比对照区和必须保持的保护区。
3. 用 `describeRegion` 固定 checksum、stale systems、样本量、分位数和对象集合。
4. 调用专门诊断，确认 evidence cells 确实落在目标范围。
5. 把结论分成“直接事实”“空间共现推断”“仍需风向 / 道路 / 规则验证”。
6. 先写可量测目标区间和不变量，再选择 inspector；没有领域事务时只给建议，不裸改字段。
7. 执行后重新计算同一统计，并用真实浏览器检查专题、图层、标签和对象位置。

## 三类常见问题

气候与承载：目标区低降水不自动证明雨影。应比较迎风侧、背风侧、山地屏障、风带、温度、宜居度、城市与交通。

区域发展差距：人口少可能来自承载不足、缺少城市锚点、道路 / 市场不通、政治或地区影响。不要只把总人口机械调平。

地形自然化：先找孤立尖峰、突变边和粗糙度 P90，同时保护海平面、主峰排序、主山脊、分水岭、山口与河流出口；全局均值平滑会破坏这些关系。

相关安全写入顺序见 [编辑器与安全修改](编辑器与安全修改)，气候的具体判断见 [气候、生态与人口](气候生态与人口)。
