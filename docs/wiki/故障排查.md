# 故障排查

先保护当前地图，再判断问题属于启动、文件、界面状态、领域规则还是渲染。不要用重复点击、手改 JSON 或清空浏览器数据掩盖原始证据。

## 启动与加载

| 现象 | 先检查 | 处理 |
|---|---|---|
| `pnpm` 或 Node 版本错误 | `node --version`、`pnpm --version` | 使用项目要求的 Node `^20.19.0` 或 `>=22.12.0` 与 pnpm 10 |
| Vite 地址打不开 | 终端实际输出端口 | Windows 的 `5109～5208` 可能被系统排除，使用 Vite 选择的可用端口 |
| 一直停在加载画卷 | 页面 console、网络资源、生成阶段 | 保留错误页和日志，刷新前先确认不是大地图正常生成 |
| 浏览器提示不支持 | WebGL2 context、显卡驱动、浏览器版本 | 使用现代 Chrome / Edge，确认硬件加速和 WebGL2 可用 |

生产构建问题先运行 `pnpm run build:app`。Vite 的大 chunk 警告不等同于构建失败，应看退出码和实际错误。

## 地图文件拒绝

打开统一导入诊断，记录：

- 来源和文件字节数；
- 检测到的文档 type / version；
- 失败阶段（读取、解压、解析、迁移、schema、业务验证或应用）；
- 稳定 code、中文说明和建议。

未来版本文件不能强行降级。损坏 JSON、错误 gzip 或伪装扩展名也不会被接受。失败时当前地图应保持原样；如果是启动恢复失败，浏览器中的原始存档字符串也不应被自动覆盖。

## 保存或导出不符合预期

- `.webfmg` 是 gzip JSON，不应按纯文本直接打开；先 gunzip 或用应用导入。
- PNG 只保存当前画面和所选 overlay，不包含浮动管理面板，也不能恢复地图。
- 高度灰度图固定输出完整 Grid 高度，不跟随当前专题和相机。
- GeoJSON 是外部空间数据，不包含完整编辑历史、视觉和全部对象语义。
- 云端“覆盖”使用已选远端文件身份与原名；改变本地地图名或模板不会替远端文件重命名。
- 下载没有出现时，检查浏览器下载权限、弹窗 / 多下载拦截和页面状态提示。

## 面板或地图操作看起来无效

1. 查看当前是否仍处于另一个画布工具模式；按 `Esc` 取消，再重新进入。
2. 检查目标图层和专题是否能显示该对象。对象存在不等于当前视图可见。
3. 查看面板提示是“预览完成”“等待确认”“规则拒绝”还是“执行成功”。预览不会写历史。
4. 检查对象是否锁定、范围是否越界、目标 cell 是否满足陆水 / 邻接规则。
5. 查看 history 是否增加，以及 `derivedStale.systems` 是否仍有待更新系统。
6. 用列表“定位”验证对象身份，不按屏幕上的近似位置重复点击。

## 画面与数据不一致

数据查询不能替代浏览器视觉验收。依次检查：

- `layers.get()` 的专题、主题和图层显隐；
- 标签 LOD、城市标签预算和锁定位置；
- 相机是否在预期范围，尝试“适配视图”；
- renderer stats 中动态 route / river / selection cache 是否完成；
- `info.healthEvents()` 的 active error 与 WebGL `getError()`；
- 地图 checksum / revision 是否在预期操作后变化。

`main-thread-long-task` 或 `render-frame-gap` 是性能健康事件，不等同于业务错误；但持续卡顿仍应记录 cells 数、操作序列、浏览器版本和可复现 profile。

## API 与自动化

- 根对象不存在：等待应用 API ready，并检查页面初始化 error；开发模式不是 API 开关。
- `window.api` 不存在：它只是仅在全局名空闲时安装的兼容别名，改用 `window.webglGeneratorApi`。
- 方法不存在或参数错误：调用 `info.capabilities()` 和 `info.describe(method)`，不要抄旧 README。
- 返回空分析：确认对象 id、Grid / Pack space、区域交集和存档是否含相应派生数据。
- 写入被拒绝：读取 error code、revision、inspectionToken、requiresConfirm 和锁冲突，不要绕过 inspector。
- 桥无法连接：确认服务只监听 `127.0.0.1:5412`、令牌来自本次服务、页面已显式开启；刷新后需按新的 pageSession 继续。
- 无头方法不可用：浏览器专属相机、图层、下载和编辑历史会返回运行时不可用，这是设计边界。

## 云端存储

- 未配置：检查站点根目录 `cloud-provider-config.js` 是否包含公开 identifier；不要填 client secret。
- Dropbox 回调失败：页面 origin 与 redirect URI 必须精确匹配，`localhost:5410` 与 `127.0.0.1` 不是同一地址。
- Google 文件看不到：应用只列出自己创建并标记的文件；新文件默认在 `/webFMG`，旧根目录应用文件仍会保留。
- 刷新后断开：令牌可能到期、配置指纹变化、记录损坏或收到 `401`，需要重新连接。
- 覆盖冲突：远端版本已变化，刷新文件列表并重新选择，不要强行覆盖。

## 提交问题时保留什么

可以提供：应用版本、浏览器版本、视口、cells 目标、操作步骤、公开诊断 code、错误阶段、是否可撤销、console / page / health / WebGL 错误摘要，以及不含私人内容的最小样本。

不要提供：access token、OAuth code、AI bridge 配对令牌、完整私人存档、真实对象 / cell id、坐标、私有 checksum、未脱敏截图或浏览器存储原文。

Wiki 内容疑似陈旧时运行：

```powershell
pnpm run audit:wiki
pnpm run audit:ai-docs
```

如果问题涉及旧存档，继续阅读 [旧图兼容](旧图兼容)；涉及安全写入，阅读 [编辑器与安全修改](编辑器与安全修改)。
