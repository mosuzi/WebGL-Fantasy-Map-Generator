# 第 413 项：WebGPU / WebGL2 复合地图场景对照

## 范围与口径

2026-11-15，在独立对照页 `prototype/webgl-cells/webgpu.html` 上，用既有匿名固定快照比较两套图形 API。正式应用、用户地图和存档均未改动。两侧共用 Worker 一次准备的位置、颜色、层序、画布尺寸、相机轨迹及效果参数；保留仅格网场景作为控制组。固定快照有 `99,846` 个 grid cells、`72,343` 个 pack cells 和 `1,795,563` 个地表顶点。

复合场景的非零绘制量如下。线的顶点数包含扩展成三角形的描边，不能直接当作原始地图对象数。

## 性能样本

每个场景先预热 `5` 帧，再采 `60` 帧；两后端每帧轮换先后次序，使用同一组移动和缩放相机值。下表是此次单次本机运行，单位毫秒。`完成等待` 包含浏览器调度和 GPU 队列等待；`绘制流程墙钟` 截止于 GPU 命令完成和标签 DOM 更新，**不包含**浏览器最终的屏幕绘制与合成，也不是纯 GPU 着色器耗时。

两场景在同一个页面中复用一次性 Worker 准备和双后端上传。仅格网控制组关闭其它图层的**逐帧绘制**，不是独立冷启动样本；不能把此页完整初始化成本写成仅格网的成本。准备阶段已单列历史图层构建与复合绘制包增量，上传阶段单列地表与复合图层，便于看清共享成本。

| 指标 p95 | 复合 WebGL2 | 复合 WebGPU | 仅格网 WebGL2 | 仅格网 WebGPU |
|---|---:|---:|---:|---:|
| CPU 提交 | 0.2 | 0.3 | 0.1 | 0.2 |
| 完成等待 | 17.4 | 13.6 | 6.0 | 4.8 |
| 晕染总成本 | 0.4 | 3.1 | 0 | 0 |
| 其中 WebGPU 源图回读 | 0 | 2.8 | 0 | 0 |
| 标签更新 | 0.4 | 0.6 | 0.1 | 0.1 |
| 绘制流程墙钟 | 18.0 | 15.9 | 6.0 | 5.0 |

Worker 准备阶段分别为 JSON 解析 `292.2ms`、历史图层构建 `406.0ms`、国家颜色 `91.9ms`、复合绘制包 `83.2ms`；历史图层构建本身包含多个原型图层，不能归为仅格网准备。两后端地表上传分别为 `34.5 / 15.4ms`，复合图层增量上传为 `6.3 / 7.4ms`；包含着色器等建立工作的上传阶段总量为 `48.6 / 23.2ms`。首次加载及测量窗口记录 `5` 条主线程 LongTask，最大 `79ms`，`>200ms` 为 `0`。已对 `gl.finish()` 的同步等待做一次调查和实质优化，改成异步栅栏轮询；余下短任务精确时间见本地 `work/task413-webgpu/report.json`，未把它们误记为已消除。`requestAnimationFrame` 超时回退为 `0`，浏览器警告和错误为 `0`。

这一次样本中，WebGPU 绘制流程墙钟 p95 比 WebGL2 低约 `2.1ms`，但 WebGPU 的 CPU 提交和晕染回读成本更高。单机、单图、单分辨率结果不足以决定正式应用迁移；应先在正式地图及用户目标编辑入口中测到可复现的瓶颈，再选择需要替换的阶段。

## 与正式地图的差异及复验

固定快照缺少正式 canonical grid 的部分邻接、行政归属和岸线修正关系。此页使用确定性的共享路径平滑及屏幕空间晕染来模拟相同工作类别，不声称与正式 renderer 逐像素相同；也未运行国家画笔事务、存档或正式地图的增量更新链。

```powershell
pnpm run regress:webgpu-complex-scene
pnpm run build:app
pnpm run regress:webgpu-cells-browser
pnpm run regress:deployment
```
