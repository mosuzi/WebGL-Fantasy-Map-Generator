## 权威任务清单

### 第 361 项：首次边界不可逆第三态消除 `执行中`

- **状态**：`执行中；第 359、360 项已分别完成并归档`。
- **唯一正式输入**：沿用上述同一真实存档及文件哈希；必须从文件选择开始录制首次正式可见帧，不得先切换显示开关再冒充首次状态。
- **问题定义**：用户确认首次加载出现的疆界柔化在关闭“平滑边界”后重新开启也无法恢复，因此它不是 `smoothCellBorders` 的正常开启态，也不是“地图边缘渐隐”，而是导入 prepared render 与运行时切换路径之间产生的不可逆第三种画面。第 358 项只证明首帧在 `1,200ms` 内没有变化，并未证明首帧属于可控制、可往返的合法状态。
- **封闭目标**：先冻结首次帧、平滑关闭帧、再次开启帧及其 surface / shore / line 资源指纹，确认第三态来自哪一个 prepared layer、cache owner 或 display fingerprint；随后让首次导入与运行时开关共用同一规范渲染状态机。首个对用户可见的正式帧只能是“平滑开启”或“平滑关闭”之一，禁止显示无法通过 UI 再现的中间画面。
- **阶段顺序**：`361-A 三帧像素与 GPU / cache owner 指纹归因 → 361-B prepared presentation 与运行时 display binding 收敛 → 361-C 开关幂等 / 往返专项 → 361-D 同存档首次导入逐帧终验`。当前“boundary-only cell visual + current-shore-only resident”只作为首要嫌疑，361-A 证明前不得当成既定根因。
- **最终验收**：在平滑开启状态导入时，`首次正式帧 == 关闭后再开启帧 == 再次关闭后开启帧`；在平滑关闭状态导入时，`首次正式帧 == 开启后再关闭帧`。相等必须同时覆盖完整 canvas PNG、疆界 / 海岸裁剪图、surface / shore / line 顶点摘要和 render binding，不得只比较文件大小；首次帧与 `1,200ms` 后也必须一致。全程不存在第三组资源指纹、Loading 后画面替换、WebGL error 或 `>200ms` 新增长任务，并继续满足第 359 项加载绝对时限。
- **非目标**：不把不可逆第三态包装成新的视觉特性，不用延长 Loading 单纯遮住错误画面，不改“地图边缘渐隐”、地图数据、疆界拓扑或视觉主题；是否把平滑偏好写入存档不在本项自动扩展，先消除同一明确状态的渲染不一致。
- **停止条件**：两次精确复现仍无法得到第三态资源指纹，或修复必须改变疆界数据而非显示资源时，冻结三帧和 trace 请用户裁定，不用截图肉眼相似代替归因。
- **详细冻结**：见 [`task-notes/task-361-initial-boundary-third-state.md`](./task-notes/task-361-initial-boundary-third-state.md)。
