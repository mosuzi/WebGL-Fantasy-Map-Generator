## 权威任务清单

- **权威任务第 329 项：收敛已登记 LongTask 性能债与过宽回归额度。** `待执行；来源：用户要求重新审查此前登记放行的 LongTask，判断是否仍需优化并给出方案`
   - **目标**：逐项复核第 322 项 C1、C2、C3c、D2、阶段 E routes，以及第 323、324、328 项现存 LongTask 登记和浏览器门。区分仍可稳定复现的产品性能债、已被后续实现消除的历史信号、浏览器偶发提交成本和仅存于夹具的宽松额度；不得因为旧记录存在就重复改产品，也不得让“任意数量且单条不超过 200ms”继续成为假绿门。
   - **阶段 A——回归额度收敛**：第 323、324、328 项所有登记门必须绑定明确入口、最大数量、最大时长和允许来源；最终已经稳定为 LongTask `0` 的入口恢复严格零门。第 328 项 100k 国家重生成在重新取证前最多只保留 `1` 条且 `≤80ms`，不得继续使用无数量限制的 `≤200ms`。历史归档不篡改，只更新当前机器门。
   - **阶段 B——C3c 路线 / 城市重点治理**：把路线预检、修改、撤销、重做和城市预检、移动、撤销、重做八个正式窗口分别结算 LongTask；只允许一次最窄诊断、一次实质优化和一次目标复验。根据证据选择 overlay DOM 复用、point / route / picking 局部更新、历史快照或同步安装切片，不得先猜热点。目标是八个入口各自 LongTask `0`；若按统一规则优化后仍有 `≤200ms` 信号，只能登记到具体入口、数量和来源。
   - **阶段 C——C1 与其余例外复核**：先用当前实现复跑 10k→100k 网格细分专门门；若 LongTask 为 `0`，删除 `2×160ms` 旧额度，若复现则按地图提交、GPU 分段交换、overlay 与历史快照分窗诊断并只窄修一次。C2 当前严格零门保持；D2 主题 / 最大标签和阶段 E routes 只做目标复验，未复现则删除阶段额度，不再扩产品。第 323 项 100k 新图和第 328 项 100k 国家只在重新稳定复现并锁定阶段后才实施产品优化。
   - **最小验收**：不存在跨多个操作汇总的宽松 LongTask 额度；不存在任意数量 `≤200ms` 即通过的浏览器门。所有保留例外均有入口、数量、上限、来源、一次调查、一次实质优化和一次复验证据。代表性 10k / 100k 正式入口保持数据、历史、回滚、GPU / picking、Loading 和错误面原门；性能探针不得把重指纹、checksum、trace 序列化或夹具 setup 混入产品窗口。
   - **非目标**：不提高 `200ms` 总上限，不以 `clearLongTasks`、扩大等待或重复跑全门隐藏失败；不进行无证据 renderer 大重构，不修改生成结果、地图数据、存档、公开 API、用户地图、Wiki 或 `source/`。详细矩阵见 [`task-notes/task-329-long-task-exception-convergence.md`](./task-notes/task-329-long-task-exception-convergence.md)。

- **权威任务第 330 项：统一优雅 Loading 与编辑面板用户文案。** `待执行；来源：用户发现部分加载文案重新变得生硬，并要求遍历编辑面板文字描述后系统优化`
   - **目标**：系统盘点启动页、地图生成 / 替换、共享 runtime operation、十一类重生成、导入导出与存档、云端操作、面板懒加载和面板内异步状态；同时遍历正式 `28` 个 Vue 面板及对应适配层的普通用户文案。等待反馈要清楚、克制、自然，编辑说明要从用户任务和结果出发，不直接暴露内部实现。
   - **阶段 A——清单与词表**：建立可审计文案矩阵，逐条记录位置、用户情境、当前文字、问题类型、建议文字和普通 / 调试可见性。普通界面禁止无解释地出现 `cell / grid / pack / feature / Worker / buffer / revision / checksum / 镜像 / 补丁 / 派生 / 运行时 / 同事务` 等内部词；开发模式、结构化 API 诊断和内部日志可保留技术原文。沿用既有“资源点 / 通用标记、地貌单元、测量 / 测量对象”等权威业务词表。
   - **阶段 B——Loading 分层治理**：快速操作不得闪烁；共享操作继续由 token 化延迟反馈处理取消、失败、重叠和迟到完成。只有用户能理解且确实不同的阶段才更新文案，生成规模、消息包、Worker、渲染安装和缓存后端不得进入普通提示。面板首次加载也应避免短暂闪字，超过小延迟后才显示“正在打开……，请稍候片刻”一类稳定提示；加载失败仍保留可操作恢复态。
   - **阶段 C——面板文案分批改写**：优先处理普通模式中已经确认的 `目标 cell / pack cells / grid cells / feature # / 中心 pack cell / 同事务联动 / 只读预检 / 重算经济链` 等生硬表达；统一按钮为“动作 + 对象 / 结果”，预览说明明确尚未写入，危险动作说明影响和撤销能力，空态给出下一步。调试专属统计、ID 和底层字段不伪装成普通业务词，也不强行删除。
   - **最小验收**：静态矩阵覆盖全部 Loading 来源、`28 / 28` Vue 面板及对应加载适配层；共享文案专项拒绝普通界面技术词回流。隔离系统 Chrome 验证快速 / 慢速、成功 / 失败、取消、重叠、迟到完成和面板 chunk 故障；普通模式依次打开全部面板，检查文案、空态、预览、危险动作和禁用原因，并在 `1280px` 与窄视口抽检无裁切 / 溢出。真实浏览器中 Loading、普通文案、console、page、非性能 health、WebGL 错误为 `0`，业务行为、历史和数据保持不变。
   - **非目标**：不修改 API / schema / 存档格式、生成算法、地图数据、编辑事务、面板信息架构或视觉主题；不把调试信息全部隐藏，不改 `source/`、Wiki 或用户现有地图。优先复用现有文案模块、懒加载 harness 和 UI 审计工具，不新建超过 `500` 行的浏览器夹具。详细盘点见 [`task-notes/task-330-loading-and-panel-copy-polish.md`](./task-notes/task-330-loading-and-panel-copy-polish.md)。
