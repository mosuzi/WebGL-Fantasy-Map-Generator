- **权威任务第 323 项：地图规模统一限制为 1～100k。** `待执行；来源：用户要求地图规模最大支持 100k，越界数字自动降级且不得小于 1`
   - **统一口径**：建立唯一的地图规模归一化规则，所有用于创建或扩大地图的目标值均为整数 `1～100000`；有限数值大于 `100000` 时自动使用 `100000`，小于 `1` 时自动使用 `1`，两个边界值保持不变。非数值输入继续走明确的默认值或输入错误，不得静默变成意外规模。
   - **覆盖入口**：生成 Tab、整图生成选项、公开 API / schema / 配方、URL 或预设恢复，以及 `grid.refine` 的 `targetCells` 必须复用同一规则；当前 UI 的最小值 `1000` 和网格细分的最大值 `200000` 一并收敛。归一化后的值必须回显到控件、地图 options / metadata、预检结果和操作日志，禁止界面值、API 值与实际计算值分叉。
   - **一格与细分边界**：`cellsTarget=1` 必须能够完成生成并至少绘制一个有限、可见的地图单元；依赖多样本的人文或网络阶段在样本不足时应确定性降级为空结果或最小合法结果，不得崩溃。细分仍只允许增长，但请求超过 `100000` 时先按 `100000` 执行；地图已经达到上限时返回明确 no-op，不再分配超过上限的网格。
   - **存档安全**：不允许通过静默删除 cells 把既有超限存档伪装成 100k；实际网格超过 `100000` 的导入应在替换当前地图前明确拒绝并保留原图，`≤100000` 的旧存档保持兼容。不得修改 `source/`。

- **权威任务第 326 项：地点解析、距离与方位查询 API。** `待执行；来源：用户要求通过地名或 ID 查询两地距离与方位，并为 AI 提供先查 ID、再精确测量的稳定流程`
   - **公开方法与共用实现**：在现有只读 `analysis` 命名空间新增 `resolvePlace(reference, options?)`、`measureDistance(from, to, options?)` 和 `getDirection(from, to, options?)`，浏览器 `window.webglGeneratorApi` 与无头 `createHeadlessMapApi` 复用同一纯数据解析、锚点和测量模块。三者均不得改变地图、selection、相机、图层、历史、checksum 或显示偏好，并须进入 `info.describe`、schema、能力矩阵和 AI 文档。
   - **名称与 ID 解析**：首期地点固定为国家 `state`、省份 `province`、城镇 `city`。名称去除首尾空白后按完整名称匹配，国家同时接受当前 `name / fullName`，不默认做模糊猜测；同名跨类型按“国家 > 省份 > 城镇”选择，同一类型有多个同名对象时按稳定升序 ID 选择第一个。返回值必须同时给出选中对象的 `kind / id / name`、全部同名候选、候选数和实际采用的优先规则，不能因自动首选而隐藏歧义。精确 ID 输入复用项目统一对象引用 `{kind, id}`，以避免三类对象各自编号空间重叠；找不到、已删除、类型非法或锚点无效时返回结构化错误，不回退到相近名称或其它对象。
   - **AI 精确调用流程**：允许距离与方位方法直接接收名称引用或精确 ID 引用；但 AI 需要可复现的精确结果时，必须先用 `resolvePlace` 按名称读取候选并取得选中对象的 `{kind, id}`，再把两端的精确引用传给 `measureDistance` 或 `getDirection`。文档示例需展示同名跨类型、同类型重名和两阶段调用，不得只给依赖数组偶然顺序的裸名称示例。
   - **地点锚点契约**：城镇使用当前正式 `x / y`；国家优先使用有效首都坐标，否则使用国家中心 cell；省份优先使用唯一有效省会坐标，否则使用 `province.pole`，再回退省份中心 cell。结果必须回显每端的世界坐标、`anchorSource` 和地图 revision，使行政区域的“距离”明确是代表点直线距离而非边界最短距离、道路里程或航路长度。
   - **距离口径**：正式距离始终从地图世界坐标以数据计算，并复用当前单位 / 比例尺换算，至少返回有限的 `distanceWorld`、换算值、单位、格式化文本以及 `precision / approximate / reason`；浏览器与无头环境对同一地图、同一精确 ID 和同一单位配置必须在文档化浮点容差内一致。无头结果允许因旧存档坐标精度、行政代表点回退或缺少浏览器会话单位偏好产生已声明误差；缺少单位配置时仍须精确返回世界距离，并对默认换算明确标记近似，不得改用估算 cell 数或名称相似度。浏览器可选返回当前相机下的 `screenDistancePx` 作为界面诊断；该值随缩放、DPR 和视口改变，不能作为正式地理距离或写入存档。
   - **方位口径**：`getDirection` 复用 `measureDistance` 的同一解析、锚点与距离结果，并返回 `dx / dy`、以地图正北为 `0°` 且顺时针递增的 `bearingDegrees`、八方位中文结果（北、东北、东、东南、南、西南、西、西北）和完整距离摘要。地图世界坐标的 Y 轴向下时必须显式换算为“Y 减小即北”；两端重合或低于统一 epsilon 时返回“重合”，不得伪造任一方位。
   - **最小验收**：固定夹具覆盖国家 / 省份 / 城镇三类同名优先、两个省份或城镇同名首选稳定、候选清单、精确 ID 与名称结果一致、非法与删除对象拒绝、国家 / 省份锚点逐级回退、八方位边界和重合。10k / 100k、细分图及保存往返中，浏览器与无头正式距离和方位在容差内一致；浏览器切换至少三档缩放时 `screenDistancePx` 可变化而正式距离不变。API 发现、schema、AI 两阶段示例、单位换算、无副作用、生产构建及 application / page / active health / WebGL error 通过；不得修改 `source/`。

- **权威任务第 328 项：大河参与国家与省份划界。** `待执行；来源：用户要求省份划界或重新生成省份时适度考虑大河走势，并允许大河成为省界乃至国界`
   - **适用入口与非目标**：作用于新图政治生成以及正式 `generate.regenerate` 的国家与省份重生成链，重点覆盖省份自动划界和重生成省份；不得在载入旧图、普通渲染或用户手工编辑边界时擅自重划行政区，也不得修改河道、流域、河流控制点或 `source/`。旧存档保持原边界，只有用户明确执行对应生成操作后才使用新规则。
   - **大河权威判定**：从当前 canonical 河网的流量、河宽、河流等级、连续长度和有效河段建立稳定、可审计的“大河阻隔分数”，不得按河流 ID、显示像素宽度或偶然数组顺序判断。连续主河段的权重高于短支流和季节性小河；小河可以提供轻微地形信息，但不得普遍把行政区域切成碎片。
   - **软边界语义**：大河是政治扩张和行政分配的软阻隔，不是不可跨越的硬墙。跨越成本随河流强度提高，并可由首都 / 省会可达性、既有聚落、港口、道路和合法渡河走廊适度降低；算法仍须综合人口、文化、地形、距离和区域完整性。强河两岸都具备可持续行政中心和连通腹地时，可以形成不同省份，条件充分时也可以形成不同国家；不得为追求沿河边界而制造无中心飞地、单 cell 长条、断裂行政区或不可达领土。
   - **锁、确定性与兼容**：冻结国家 / 省份、锁定中心、受保护对象和用户已确认边界优先于河流偏好；同 seed、salt、地图 revision 与锁状态必须得到同一结果。没有大河、只有弱河或合法行政结构无法沿河形成时，确定性回退到既有综合划界语义，不得拒绝整次生成。Worker 与兼容降级、撤销 / 重做、取消、迟到结果和失败回滚均须保持原子，普通用户不新增必须理解的技术开关。
   - **结构化诊断**：生成结果记录大河候选、阻隔分数、沿河边界长度、跨河行政邻接、因中心 / 道路 / 港口而允许的跨河走廊以及国家 / 省份层级的实际采用原因；诊断只进入开发模式、内部日志或结构化 API 结果，不向普通地图标签泄漏算法术语。河流只作为输入证据，不得因行政结果反写河流属性。
   - **最小验收**：纯数据夹具至少覆盖强连续大河、同几何弱河、短支流、多条汇流、合法渡河走廊、单侧无可用中心、锁定行政区和无河地图。对称且两岸均有合法中心的强河夹具中，至少 `70%` 的合格主河段成为国家或省份边界，并能形成两侧独立行政区；匹配的弱河夹具不得仅因河流而强制分国或产生碎片。固定 10k / 50k / 100k 新图及国家 / 省份重生成锁定边界河段、跨河走廊、行政连通、中心归属、未分配 cell、飞地 / 长条退化和确定性 checksum；锁定对象零改写。真实浏览器覆盖新图、省份重生成、国家重生成、撤销 / 重做、取消、Worker 兼容降级与故障回滚，确认河流 / 道路 / picking / GPU 同源，application / page / active health / WebGL error 为 `0`。

## 执行与归档规则

- 已批准的编号任务视为封闭范围；达到最小验收后立即转向下一项，不扩展完成标准。
- 新功能先登记权威任务，再实施并同步开发日志与接手说明。
- 每个权威编号使用独立任务分支；内部阶段 checkpoint 留在该任务分支。单项完成后必须显式暂存授权范围、中文提交、推送任务分支、合入并推送 `main`，确认远端 `main` 包含完成提交后，才从最新 `main` 新建下一编号分支。不得跨编号共用施工分支，也不得在前项仅“测试通过但未合入 main”时启动后项。
- 任务完成后按完成日期移入 docs/task-archives/ 对应时间卷，当前文件不保留完成正文。
- 归档默认按每月四个时间片切分，跨月必须新建文件；单卷过大时可继续细分。
