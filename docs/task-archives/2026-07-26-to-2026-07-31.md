- **权威任务第 206 项：河流干流关系、湖泊溢流与有界下切。** `第二次纠错完成；来源：用户在“丹水—玉溪”完整水系复核后的直接补充`
  - 根因范围：生成阶段会记录支流 `parent`，但候选河流随后还会按长度与河源合法性过滤；过滤后没有重新验证父河是否仍存在、是否自指、是否在真实陆地汇流点相交。湖泊入流还会被直接挂到湖泊出流，混淆“经湖泊连通”和“汇入同一干流”。
  - 数据契约：`parent` 只表示立即接收本河的真实干流；支流末端必须是陆地汇流 cell，父河必须存在、不能自指，并从该 cell 继续向下游。入湖、入海和出界河流均不以水体另一侧河流充当 `parent`；`basin` 解析到有效根干流。直接父河有效不等于水系有效：父链根河必须拥有合法出口。
  - 生成门禁：河流候选过滤后统一重建父子树；缺失、自指、循环和不相交引用必须修复或拒绝。河道所有相邻 cell 必须拓扑相邻；入海 / 入湖末端的最后陆地 cell 与水体 cell 必须真实相邻，海洋 Feature 必须与地图边界连通；出界河流的末端陆地 cell 必须是边界 cell。根河无合法出口时，整棵上游河树不得作为正常河网进入新生成结果。
  - 展示与 API：河流管理列表、河流详情、通用对象详情和地图悬停均显示主河 / 支流；支流显示直接干流名称与 ID，旧图孤立河段显示明确异常状态。对象查询公开 `parentId / parentName / basinId / basinName / confluence / networkStatus`。
  - 旧图兼容：旧浏览器缓存、JSON 与 gzip 导入时非破坏性归一化；入湖误挂、缺失或自指父河会解除错误关系，无法安全接续的陆地孤立河段保留几何并标记诊断，不在迁移时静默删除。
  - 第二次纠错规则：河流进入湖泊不再天然等于水系终点。湖泊先计算长期净补给 `flux - evaporation`，并沿全图最低溢流鞍点计算有限蓄水容量、预计蓄满时间和出海路径；净补给不为正才可作为稳定闭流终点。净补给为正且最低路径在流量对应的下切预算内时，湖泊必须形成出口河并继续追踪到外海或地图边界。
  - cell 高度语义：`cells.h` 是单元格范围的平均地形高度，不是河床不可穿越的硬高程。河流允许从平均高度较低的 cell 进入略高 cell，但必须使用水文有效高度与流量派生的有界下切预算；禁止把这一修正退化成任意爬坡或穿越高分水岭。河床有效高度只影响排水顺序和河道寻路，不直接篡改单元格平均地形。
  - 湖泊诊断与兼容：新湖泊持久记录版本化 `overflow` 诊断，包括水量状态、净补给、蓄水容量指数、预计蓄满时间、溢流高程、路径长度及下切需求 / 预算；旧浏览器缓存、JSON 与 gzip 缺字段时回填 `unknown-legacy / legacy-outlet`，不伪造旧图水文结论。湖泊对象查询与管理详情公开这些基础字段。
